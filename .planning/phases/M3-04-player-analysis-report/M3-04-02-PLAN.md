<objective>
REP-D03 asks for splits "All Camps / per camp / per competition / per opponent, driven by
`game_id`/competition tier/date from `hc_games.csv` — no hand-maintained lists". Research proved
that assumption does not hold for the one workbook this report is about: his per-camp tabs are not
filtered by any column, they are **hard-coded absolute row windows** into a single `Data` sheet
(`Data!$P$1001:$P$2000` for Mexico, and so on). There is no camp column, no per-camp date, and the
opponent is stamped as the constant `OPP` for every one of these games. The split key exists in
exactly one place: the row order in which he pasted each charting session.

So this plan builds the smallest honest thing that satisfies the spirit of REP-D03: one maintained
reference file with one row per window, every boundary cited to the formula cell it was read from,
and one resolver that turns a declared head-coach game into a split label. No report module ever
sees a row number.

Purpose: plans 03-05 filter by split. Without this they would each invent their own magic numbers.
Output: `data/reference/hc_splits.csv`, `load_hc_splits`, `resolve_hc_game_splits`, config wiring,
tests, and the PII gate extended to the new committed file.
</objective>
