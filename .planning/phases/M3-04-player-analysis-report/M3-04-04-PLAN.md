<objective>
Put our numbers next to his, and cut both the way he cuts them.

The side-by-side is the entire point of REP-D01: his `Explosive %` (yards > 12, pass only) sits in
one column, our Success Rate, our corpus-calibrated Explosiveness and our continuous score sit in
the next ones, on the same players and the same plays, each with n, confidence interval, muting flag
and shrunk rate. None of those is computed here — M3-3 built and froze them, this plan calls them.

The split axis is the second half: `All Camps` plus one section per camp/competition window,
resolved through M3-04-02's maintained reference file. His per-opponent split cannot be honoured
today (the ingest layer stamps a constant `OPP` for every camp game); that is named as a limitation,
not silently approximated by something else.

Purpose: this produces the render-ready data object. Plan 05 only formats it.
Output: `m3_columns_by_qb`, the split assembly, `PlayerAnalysisReportData` and
`build_player_analysis_data`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| maintained split reference → coach-facing section headings | a mis-assigned game shows a coach the wrong camp's numbers |
| model artifacts (calibration, out-of-fold predictions) → published rates | a stale or missing artifact would silently change what "explosive" means |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-M3-04-13 | Spoofing (wrong split shown) | camp sections | mitigate | Section membership comes only from `resolve_hc_game_splits`' `matched` state; every other state lands in `unresolved_games` with its reason, and a test asserts two windows produce different counts |
| T-M3-04-14 | Tampering (definition drift) | M3-3 metric columns | mitigate | Values are read from a live `definition_comparison` call and the test compares against that same call, so a changed definition can never pass as the old number |
| T-M3-04-15 | Repudiation (unstated limitation) | per-opponent split | mitigate | A standing German notice names the constant `OPP` stamp on every run; the conflict label triggers its own notice |
| T-M3-04-16 | Denial of Service (report abort) | missing reference/calibration files | mitigate | Every load is guarded and degrades to a notice; `build_player_analysis_data` never raises, matching `build_own_team_data` |
| T-M3-04-17 | Information Disclosure (PII) | player names in sections | accept | Same disposition as M3-04-03: names live only in the gitignored rendered output; this plan commits no data file and its fixtures are synthetic |
| T-M3-04-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing (M3-04-RESEARCH Package Legitimacy Audit: zero new packages) |
