<objective>
Turn segmented, mapped blocks into canonical plays that belong to named games and named players.

Three things have to be true at the end: a play knows which game it belongs to (HC-D04, via the new
maintained `data/reference/hc_games.csv`), a player label — which in his workbooks is sometimes a
name and sometimes a jersey number in the very same column — goes through the existing
`reference.map_players` without ever breaking the run or leaking a raw name (HC-D02), and the frame
passes `conform_to_canonical` with `source = hc_workbook:<file>:<sheet>` (HC-D01).

The derivation chain itself is deliberately not new code: `parse_result_tokens`,
`derive_outcome_columns`, `derive_identity_columns`, `derive_drive_id`, `add_scoring_play_team`,
`add_score_columns` and `derive_yards_gained_first_down` are imported from `ingest/hudl.py` and used
in the same order, because a second RESULT-parsing implementation would have to be kept in sync
forever (HC-D01, research § "Don't Hand-Roll").

Purpose: after this plan an HC sheet is canonical plays. Plan M3-01-04 only has to decide which of
them are duplicates and wire the source into `ffep ingest`.
Output: `data/reference/hc_games.csv` + its loader, and the second half of
`src/flag_football_ep/ingest/hc_workbook.py` (`segment_games`, `resolve_game_identity`,
`ingest_workbook`), with tests on synthetic workbooks only.
</objective>

  data. Keep it that way; it is a committed file.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workbook rows → canonical plays | untrusted, inconsistently charted rows enter the dataset every model trains on |
| player label → notice / report / commit | PII would cross into git here |
| `hc_games.csv` (hand-edited) → game identity | a wrong row silently re-labels a whole game |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

Plan M3-01-04's PII gate test covers the artefacts that do get committed |
