<objective>
Build the measurement core of METR-01: one label-free continuous number that moves when tracking
gets better inside a play the pass/fail threshold still marks as failed, plus the ready (but not
yet wired) label-based interface for when M2-3 identity labels exist.

Two layers, per the locked CONTEXT decision:

1. **Label-free (implemented now, live):** `fragments_per_expected_player = n_fragments / 10`
   as the ONE officially reported continuous number, and `active_track_count_deviation`
   (mean over frames of `abs(distinct active track_ids - 10)`) as a DIAGNOSTIC guard column that
   partially catches the over-merge failure mode the primary number rewards.
2. **Label-based (interface + synthetic tests only):** `compute_identity_metrics()` producing
   IDF1/MOTA/num_switches through `motmetrics`, with the future CLI keys named now so M2-3's
   wiring is mechanical.

Everything the metric needs already exists in tested form: `cv.continuity._measure_clip` computes
`n_fragments`, `baseline_common` already treats 10 as the 5v5 constant. The new work is
normalisation, aggregation, dialect-tolerant reading of the real vault file, and honest labelling
of what the number cannot see.

The load-bearing honesty constraint: the dominant real failure mode in this dataset is a silent
identity swap during an overlap (39/46 pilot fails, ~85 %) in which no track dies, no track is
born and the active-track count never changes. No label-free number can see it. This plan makes
that a TEST (`test_swap_is_invisible_to_both_metrics`), not a footnote -- if a future change ever
makes the metric look like it detects swaps, the test documents why that claim would be false.

Purpose: METR-01 needs a number that is defined without ground truth, reproducible on a laptop in
seconds, and impossible to mis-sell as an association-quality measure.
Output: two standalone modules under `scripts/hackathon/` and one new test file. No CLI change
(that is plan 02), no docs change (that is plan 03).
</objective>
