<objective>
METR-02: make ONE run of the shared scoring script emit the threshold rate and the continuous
metric for both splits -- dev (Panama Rojo, 61 clips, fully reviewed) and private_test (Puerto
Rico, 61 clips, currently 10/61 reviewed) -- as JSON and as a Markdown table, without ever copying
a private label into a public location and without breaking the single-run form the M2-2 harness
already depends on.

Two properties make or break this plan:

1. **Backward compatibility is load-bearing.** `baseline_common.score_with_shared_harness()`
   subprocess-calls this script with `--tracks/--review/--out` and `baseline_common.summarise()`
   reads `report["per_clip"]`, `report["n_clips"]` and `report["auto"]["n_ok"]`. Those keys and
   their values must stay byte-identical for the same input, or all six committed M2-2 rows silently
   drift. The continuous metric is ADDED to the report, never substituted into it: the legacy
   `per_clip`/`auto` block keeps being computed over ALL tracks, while the new continuous block is
   computed over the player view.
2. **The test split is honest about what it does not have.** The Puerto Rico review is 10/61
   reviewed; `summarise_review` correctly refuses a pass rate for it. The run must print the
   official "nicht auswertbar" line AND the reviewed-only rate with its own denominator and the
   `unvollstaendig (10/61 geprueft)` flag, and still report the continuous metric (which needs no
   verdicts at all).

Purpose: teams and the federation get one command, one report, two splits, and no number that
claims more than it measures.
Output: the extended CLI, its subprocess tests, and one real run over the real dev and vault-test
inputs whose numbers land in the SUMMARY.
</objective>
