**A verified correction to RESEARCH's Standard Stack section, load-bearing for this plan's
dependency footprint:** RESEARCH Q9 stated `boto3` would be needed client-side for any `s3://`
artifact root. `mlflow server --help` (installed 3.15.1, this session) shows `--serve-artifacts`
defaults to **True** and proxies every artifact upload/download/list request through the
tracking server's own HTTP API to whatever `--artifacts-destination` names -- the client only
ever sees `mlflow-artifacts:/...` URIs and talks HTTP, never S3 directly. This means **the
`ffep` client needs no new Python dependency at all**: `boto3` (S3-compatible MinIO/OBS access)
and `psycopg2-binary` (the Postgres `backend-store-uri` driver) are needed only **inside the
MLflow server's own container image** (`docker/mlflow/Dockerfile`), never added to
`pyproject.toml`/`uv.lock`. Both verified live against the real PyPI registry this session
(`slopcheck scan` -> `psycopg2-binary [OK]`, `boto3 [OK]`; current PyPI versions checked live:
`psycopg2-binary==2.9.12`, `boto3==1.43.90`).

**Migration approach, stated and why:** a small script using only the existing `mlflow`
dependency's `MlflowClient` API (`scripts/migrate_mlflow_store.py`) -- not the third-party
`mlflow-export-import` package, which has no RESEARCH package-legitimacy audit and is
unnecessary at this project's run count (a few dozen production runs, not thousands). The
script only ever *reads* from `--source` and only ever *writes* to `--target`; the source
sqlite store is never modified, deleted, or locked, which is itself the rollback path for the
registry side (stop setting `MLFLOW_TRACKING_URI` and the old store is exactly as it was).

**Security boundary, deliberately scoped down:** MLflow ships no default authentication
(RESEARCH Q9, multiple 2026 CVEs against unauthenticated servers). This plan binds every
container port to `127.0.0.1` only and does **not** enable MLflow basic-auth -- that, plus a
reverse proxy and TLS, is explicitly an OTC-VM-migration-time requirement (ADR Anhang A.2's own
operational checklist), not a loopback-only local dev store's. This is stated, not silently
assumed, in `docs/mlflow-container-platform.md`.

**Assumption (stated per the task): Docker is available on this machine.** `docker --version`
(29.5.3) and `docker compose version` (v5.1.4) both succeeded live in this session -- Claude
drives every `docker compose` command directly via Bash, no `checkpoint:human-verify` is needed
for the owner to start Docker Desktop themselves.

From `src/flag_football_ep/model/mlflow_store.py` (the exact function shapes to extend --
every public function in `registry.py` calls `mlflow_store.configure(config)` first, so this
override propagates everywhere with zero other code change):
```python
def tracking_uri(config: Config) -> str:
    return "sqlite:///" + str(config.paths.mlruns / "mlflow.db")

def artifact_location(config: Config) -> str:
    return "file://" + str(config.paths.mlruns / "artifacts")

def configure(config: Config) -> None:
    config.paths.mlruns.mkdir(parents=True, exist_ok=True)
    mlflow.set_tracking_uri(tracking_uri(config))

def ensure_experiment(name: str, config: Config) -> str:
    configure(config)
    client = MlflowClient()
    experiment = client.get_experiment_by_name(name)
    if experiment is None:
        experiment_id = mlflow.create_experiment(name, artifact_location=artifact_location(config))
    else:
        experiment_id = experiment.experiment_id
    mlflow.set_experiment(name)
    return experiment_id
```
Target shape: add `TRACKING_URI_ENV_VAR = "MLFLOW_TRACKING_URI"` at module level; `tracking_uri`
returns `os.environ[TRACKING_URI_ENV_VAR]` unchanged when set, else the existing sqlite string
(unchanged when unset -- every existing caller/test is unaffected); `configure` skips the
`mkdir` when the override is set (a remote store has no local `mlruns` directory to create);
`ensure_experiment` must NOT pass `artifact_location=` to `mlflow.create_experiment` when
`tracking_uri(config)` starts with `http://`/`https://` -- the containerised server resolves its
own artifact root server-side (`--artifacts-destination`, proxied). Add a small
`_is_remote_tracking_uri(uri: str) -> bool` helper for this check, used only here.

`config.load_dotenv()` (`src/flag_football_ep/config.py`, unchanged by this plan) already
populates `os.environ` from the project's own `.env` without overwriting anything already set --
this is why a developer can put `MLFLOW_TRACKING_URI=http://127.0.0.1:5000` in their local,
gitignored `.env` (not `.env.mlflow` -- that file is docker-compose's own, never read by
`load_dotenv()`, see below) as an alternative to exporting it in the shell each session.
Document both options; do not touch `config.py`'s dataclasses (M3-05-03/06 already own that

`mlflow server --help` (installed 3.15.1, verified live this session -- the authoritative
source for the compose command below, not RESEARCH's general claim):
```
--backend-store-uri PATH        ... (required for Postgres: postgresql://user:pass@host:5432/db)
--serve-artifacts / --no-serve-artifacts   Default: True. Proxies artifact upload/download/list
                                            through the server to --artifacts-destination.
--artifacts-destination URI     The base artifact location artifact proxy requests resolve
                                 against (e.g. 's3://my-bucket'). Only applies when
                                 --serve-artifacts is on.
```
So the mlflow service's command is `--backend-store-uri postgresql://... --serve-artifacts
--artifacts-destination s3://<bucket>` -- deliberately NOT `--default-artifact-root s3://...`
(that flag would only matter with `--no-serve-artifacts`, which this plan does not use).

```yaml
      AWS_SECRET_ACCESS_KEY: ${MLFLOW_MINIO_ROOT_PASSWORD}

      mlflow server --host 0.0.0.0 --port 5000
      --backend-store-uri postgresql://${MLFLOW_POSTGRES_USER:-mlflow}:${MLFLOW_POSTGRES_PASSWORD}@postgres:5432/${MLFLOW_POSTGRES_DB:-mlflow}
      --serve-artifacts
      --artifacts-destination s3://${MLFLOW_ARTIFACT_BUCKET:-ffep-mlflow-artifacts}
    ports:
      - "127.0.0.1:5000:5000"
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:5000/health')"]
      interval: 5s
      timeout: 5s
      retries: 20

  minio-mc:
    image: minio/mc:latest
    profiles: ["tools"]
    environment:
      MLFLOW_MINIO_ROOT_USER: ${MLFLOW_MINIO_ROOT_USER}
      MLFLOW_MINIO_ROOT_PASSWORD: ${MLFLOW_MINIO_ROOT_PASSWORD}
      MLFLOW_ARTIFACT_BUCKET: ${MLFLOW_ARTIFACT_BUCKET:-ffep-mlflow-artifacts}
    volumes:
      - ./backups/mlflow:/backups
    entrypoint: ["/bin/sh", "-c"]

volumes:
  mlflow_postgres_data:
  mlflow_minio_data:
```
