<objective>
This phase's CONTEXT assumes "the champion decision is taken" as a precondition. It was not:
`M3-02-RERUN-2026-09-08-SUMMARY.md` confirms the champion alias for both `ep_model` and
`wp_model` still points at the original phase-1.3 version, and M3-02-08's own checkpoint was
never actually run to completion with a decision recorded. Everything downstream in this
phase -- the model card (M3-05-08), the promotion gate's first real exercise, the extra-point
fix's before/after framing (M3-05-07) -- needs to know, unambiguously, which run is "the
champion" and why. That is a decision for the user, not a default this plan picks.

This plan resolves it, using exactly the candidates and commands
`M3-02-RERUN-2026-09-08-SUMMARY.md` already prepared: promote the 2026-09-08 with-HC/IFAF
runs (ep `97259da7acaf43f3b2c65e59f7f11694`, wp `2c8c249d295d4ce9a2845800c459c153`), or the
2026-09-04 with-HC runs (ep `6f3f5bce32564441b83803267f8c716c`, wp `55e64ecfa9804c6cab0624e8ce991485`)
which lack IFAF, or promote nothing yet.

Nothing in this plan implements new capability -- the promotion gate this phase builds
(M3-05-06) does not exist yet, so this decision is made the same way M3-02-08 would have made
it: human judgement over the measured numbers, `ffep promote` pinning an explicit run id. The
gate's job later in this phase is to apply mechanically to the *next* candidate (M3-05-07's
extra-point-fixed re-run), not to this one retroactively.

Purpose: unblock every phase-M3-05 plan that needs a resolved, current champion to describe or
gate against.
Output: an explicit promotion decision executed and recorded in `docs/epa-refinement-2026-10.md`.
</objective>
