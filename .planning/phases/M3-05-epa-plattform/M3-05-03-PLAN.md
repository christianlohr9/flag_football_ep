<objective>
`ffep train` (the only production training entry point) currently logs zero git lineage and
zero corpus fingerprint -- verified live against this project's own MLflow store: the current
champion run's tags have no `mlflow.source.git.commit` key, because MLflow's automatic
git-detection never fires for a venv console-script entry point (`.venv/bin/ffep`). Only
`scripts/hc_corpus_ablation.py`'s ad-hoc runs get this today. Per-tier log-loss and no-play-row
share are in the same position: computed, but only by the ablation script, written to a dated
CSV, never logged as a metric on the production run itself.

CONTEXT requires the promotion gate (M3-05-06) to read metrics MLflow already has, not
re-derive them from CSVs whose naming convention already changed mid-phase (M3-02's
`data/reference/epa_refinement/2026-09-08/` subfolder, sibling to the undated original). This
plan is the prerequisite: generalize what the ablation script already proved out into `_train`'s
shared path, so every `ffep train` run -- champion candidate or not -- carries the numbers a
gate needs, and add the one genuinely missing number (a scalar calibration metric; today only a
reliability-curve PNG exists).

`TIER_FEATURE_COLUMNS` (`tier_womens_international`, `tier_womens_national`, `tier_mixed_other`)
are already one-hot columns in both `EP_FEATURES` and `WP_FEATURES` -- present in `model_data`
by the time `run_logo` runs. Per-tier metrics do not need the ablation script's separate
label-frame reconstruction and CSV re-join; they can be derived directly from these existing
columns, which is simpler than what `hc_corpus_ablation.py::build_tier_metrics` does.

Purpose: make lineage and gate-relevant metrics a property of every production training run.
Output: extended `_train`/`_log_run` and one new `evaluate.calibration_max_deviation` function.
</objective>

`_train`'s existing flow (the exact insertion points for this plan's additions):
```python
def _train(*, plays, config, experiment, exclude_ids, prepare_fn, mutate_fn,
           selected_columns, features, fixed_params, metric_name, weight_column,
           model_prefix, prob_labels, tune, max_evals, export_pkl, build_fn=None) -> str:
    filtered = plays.filter(~pl.col("game_id").is_in(exclude_ids)) if exclude_ids else plays
    if build_fn is not None:
        filtered = build_fn(filtered, config)          # adds tier_* one-hot columns
    prepared = prepare_fn(filtered)
    model_data = mutate_fn(prepared, selected_columns).drop_nulls()
    ...
    training_data_sha256 = _hash_frame(model_data)      # per-arm hash, NOT the corpus fingerprint
    ...
    logo = run_logo(model_data=model_data, features=features, fixed_params=fit_params,
                     weight_column=weight_column)
    ...
    curves = reliability_curves(logo.oof_pred, logo.oof_label, prob_labels)
    source_table = per_source_metrics(logo.oof_pred, logo.oof_label, logo.oof_source, report_num_class)
    ...
    params = {..., "training_data_sha256": training_data_sha256, "excluded_game_ids": ...}
    metrics = {metric_name: metric_value, naive_metric_name: naive, "logloss_improvement": ...}
    for row in source_table.iter_rows(named=True):
        ...
        metrics[f"logo_logloss_by_source_{safe_source}"] = row["logloss"]
    ...
    run_id = _log_run(experiment=experiment, params=params, metrics=metrics, model=model,
                       feature_names=list(features), config=config, trial_losses=trial_losses,
                       figures={f"reliability_{model_prefix}.png": figure},
                       texts={"per_source_metrics.md": _render_markdown_table(source_table)},
                       register_as=registry.registered_model_name(model_prefix))
```
`_log_run` itself just logs whatever `params`/`metrics` dicts it is given plus a `phase` tag --
no signature change needed there, only what `_train` builds and passes in.

`model_data` at the point `logo = run_logo(...)` runs already contains
`tier_womens_international`, `tier_womens_national`, `tier_mixed_other` (one-hot, always exactly
one `1` per row) for BOTH EP and WP -- `hyperparams.TIER_FEATURE_COLUMNS`. Deriving a per-row
tier label from these three columns (e.g. `np.select` over the three boolean arrays, `"unmapped"`
if none are 1) avoids re-doing `hc_corpus_ablation.py::build_tier_metrics`'s join through
`plays`/`competition_tier.csv` -- everything needed is already in `model_data`.

`evaluate.py`'s existing `reliability_curves` returns `list[ReliabilityCurve]`, each with
`.name`, `.prob_true: np.ndarray`, `.prob_pred: np.ndarray`. A max-deviation summary is
`max(abs(prob_true - prob_pred))` per curve.

`evaluate.py`'s existing `per_source_metrics(oof_pred, oof_label, group_array, num_class)` is
generic over any grouping array (already used for `source`) -- reuse it directly for tier by
passing the derived tier array in place of `oof_source`, do not write a second implementation.

No-play share: the three RESULT tokens (`Timeout`, `Offsetting Penalties`, `Penalty`) and their
substring-match convention already exist in `scripts/hc_corpus_ablation.py`
(`_NO_PLAY_TOKENS`, `report_no_play_rows`) -- reuse the token list and matching logic
(`pl.col("result_raw").fill_null("").str.contains(token, literal=True)`), but only the
aggregate share needed for a gate metric (rows matching `__any__` token / total rows in
`model_data`), not the full per-source-per-token CSV breakdown that script already produces.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| training run -> MLflow store | lineage and gate-relevant metrics are only as trustworthy as the code that computes them at fit time |
| metric key sanitization -> MLflow API | tier/class names interpolated into metric keys could collide or contain unsafe characters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-M3-05-06 | Repudiation | `git_commit`/`corpus_fingerprint` params | mitigate | Captured inside `_train` at fit time (never reconstructed later from logs/mtimes, RESEARCH Anti-Pattern), with the proven `"unknown"` fallback so a missing `git` binary never fails a training run |
| T-M3-05-07 | Tampering (metric key collision) | `per_tier_logloss_<tier>`/`calibration_max_deviation_<class>` key sanitization | mitigate | Reuses the existing `_METRIC_KEY_UNSAFE.sub("_", ...)` sanitizer already proven for `logo_logloss_by_source_<source>`, with the same `sanitized_source_metric_keys` param note on any rename |
| T-M3-05-08 | Denial of Service (silent crash on narrow frames) | tier/no-play metrics on frames lacking `tier_*`/`result_raw` columns | mitigate | Both additions are guarded no-ops (log nothing, raise nothing) when the columns are absent, matching the existing `half`-sentinel guard discipline in `mutations.py` -- an `experiments.py` caller passing a narrower frame is unaffected |
| T-M3-05-SC | Tampering | package installs | accept | This plan installs nothing new |
