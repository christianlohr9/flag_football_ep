<objective>
`docs/epa-refinement-2026-10.md`'s 2026-09-08 Nachtrag already reported, but explicitly did not
fix, this finding: `play_type == "extra_point"` rows are not fully excluded from EP/WP
training. Only rows whose extra-point attempt SUCCEEDED get a null label (via `Next_Score_Half`)
and are dropped by `drop_nulls()`. FAILED attempts (`down = 0`, both conversion-success flags
0) instead inherit the label of the half's next real score and stay in the training set -- 537
such rows in the EP frame, 1,103 in the WP frame, spread across `legacy`, both `hc_workbook`
sources and `ifaf`, pre-existing since phase 1.3, verified via `git log` as untouched since
then. CONTEXT scopes this phase to fix it, as a measured methodology change, gated -- not
silently.

The fix belongs in `make_ep_model_mutations`/`make_wp_model_mutations`
(`features/mutations.py`), immediately before their existing final
`.select(list(selected_columns))`, NOT upstream in `_train` before `prepare_fn` runs.
`prepare_ep_data`/`prepare_wp_data` derive `Next_Score_Half` (and WP's `Winner`/clock features)
from the FULL play sequence within a drive/half, including extra-point rows -- a play
immediately before a made extra point needs that row present in the sequence to correctly
resolve its own "next score" label. Filtering extra-point rows out before that derivation would
corrupt OTHER rows' labels; filtering them out of the final selected `model_data`, after label
derivation has already used their presence, removes exactly the rows CONTEXT names and nothing
else.

This plan does NOT touch `model/experiments.py` (the REQ-S1-09 feature-candidate harness) --
CONTEXT scopes this fix to the production EP/WP training path (`_train` via
`make_ep_model_mutations`/`make_wp_model_mutations`), which is what a champion promotion
actually uses; the candidate-experiment harness measuring already-adopted or rejected features
is a separate concern, out of scope here.

Purpose: close a real, measured training-data leak the same way every other locked-methodology
change in this project has been closed -- re-run, report, gate, then decide.
Output: the fix, a fresh four-arm LOGO re-run, a dated report section, and a gated
promotion decision.
</objective>
