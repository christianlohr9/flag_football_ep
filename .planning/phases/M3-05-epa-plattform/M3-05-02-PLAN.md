<objective>
No training run today can say, on its own, which exact corpus it was trained against beyond a
per-model, post-filter hash (`training_data_sha256`). CONTEXT requires a dated corpus freeze
before every retrain, referenced by the run. This plan builds the manifest -- the retraining
pipeline referencing it is M3-05-06's job (it needs this module and the lineage work of
M3-05-03 to exist first); this plan only needs to produce a correct, reproducible artifact and
the command that writes it.

The hashing scheme itself is not new: `scripts/hc_corpus_ablation.py::compute_corpus_fingerprint`
(SHA-256 over the sorted `(game_id, play_id, source)` key set of the full raw corpus) and
`git_commit_sha` (subprocess `git rev-parse HEAD`, `"unknown"` fallback) are already committed
and already logged as MLflow params on every ablation run. This plan moves that exact scheme
into a reusable module (`model/freeze.py`) with a manifest schema around it, rather than
reinventing a second hash.

Per RESEARCH Pitfall 3: no source in this project (`fetch/ifaf.py`, `ingest/hc_workbook.py`)
writes an in-band "fetched at" timestamp today. This plan's per-source snapshot date is a
best-effort file-mtime approximation, explicitly labelled as such in the manifest -- not
treated as ground truth. A `_fetched_at.json` sidecar in the fetch layer is a real, separate
follow-up, out of this plan's scope.

Purpose: give every future retrain a citable, reproducible statement of which corpus it saw.
Output: `model/freeze.py`, `ffep freeze-corpus`, one committed real manifest for the current
corpus.
</objective>

From `scripts/hc_corpus_ablation.py` (already committed, the hashing scheme to reuse verbatim):
```python
def compute_corpus_fingerprint(plays: pl.DataFrame) -> str:
    keys = plays.select("game_id", "play_id", "source").sort(["game_id", "play_id", "source"])
    return hashlib.sha256(keys.write_csv().encode("utf-8")).hexdigest()

def git_commit_sha() -> str:
    try:
        result = subprocess.run(
            ["git", "rev-parse", "HEAD"], cwd=REPO_ROOT,
            capture_output=True, text=True, check=True,
        )
        return result.stdout.strip()
    except (OSError, subprocess.CalledProcessError):
        return "unknown"
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| corpus state -> committed manifest | the manifest is a claim about what `plays.parquet` contained on a given date; a wrong claim misleads every run that cites it |
| filesystem mtime -> "snapshot date" | mtime can be touched by `git checkout`/backup/`rsync` without content changing (RESEARCH Pitfall 3) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-M3-05-03 | Tampering | `data/reference/corpus_freeze/*.json` | mitigate | Manifests are committed to git like every other reference dataset -- git history is this project's existing tamper-evidence mechanism (RESEARCH, Security Domain) |
| T-M3-05-04 | Information Disclosure (misleading provenance) | best-effort mtime snapshot date | accept | Explicitly labelled `"approximate": true` in the manifest schema rather than presented as exact; a real fetch-layer sidecar is a documented follow-up, not silently promised here |

| T-M3-05-SC | Tampering | package installs | accept | This plan installs nothing (RESEARCH Package Legitimacy Audit: `boto3` is gated behind the ADR, not this plan) |
