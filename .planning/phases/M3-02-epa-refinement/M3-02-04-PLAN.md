<objective>
Turn the two wave-1 code fixes into actual rows in `data/processed/plays.parquet`. Today the number
is zero (M3-01-04 real run); after this plan it must be a reported, non-zero number per source.

The mechanism is the maintenance loop `docs/hc-workbook-ingest.md` already documents: an ingest run
emits one "Unbekanntes Spiel ..." notice per undeclared `(workbook, sheet, block_key)`, a maintainer
adds the matching `hc_games.csv` row, and the next run resolves it. What this plan adds is that the
maintainer step is a deterministic, committed script rather than 180 hand-typed lines, and that the
scope of what gets declared is a deliberate decision rather than "everything the segmenter found".

**What gets declared, and what deliberately does not:**

| Workbook / sheet | Block kind | Declare? | Why |
|---|---|---|---|
| `Offense Analytics 2026 Camps and Competitions` / `Data` | numeric | YES | Clean PLAY#-reset segmentation, 35 games, real `ODK` so `posteam`/`defteam` resolve |
| `Scoring Probability 2023-2026` / `Data` blocks 1 and 3 | numeric | YES | Real PLAY#-charted games, 151 total, 9 of them the already-declared `legacy-39..47` duplicates |
| `Scoring Probability 2023-2026` / `Data` block 0 | pair | NO | `_stamp_posteam_defteam` sets `posteam`/`defteam` to null for every pair-block row by design (Frage 2 unanswered), so these rows cannot produce an EP or WP label even with a half sentinel. Declaring them would put unusable rows into `plays.parquet` and burn reference rows that Frage 2's answer will invalidate |
| `Scoring Probability 2023-2026` / `Data` blocks 2 and 4 | pair, 1 row each | NO | Single-row noise, not games (RESEARCH section 1.1) |
| `Scoring Probability 2023-2026` / `Copy of Data` | mixed | NO | Different, undocumented column layout; Frage 2 (RESEARCH section 1.3) |
| `Germany Analytics Stats EC 2025 vs WC Nations` / `Data` | numeric | NO | Frage 1 unanswered; the 269 rows look like a pasted analysis fragment, not play-by-play |

Each NO leaves those games provisional, which — via M3-02-01's sentinel scoping — leaves their
`half` null and keeps them quarantining on `half_assigned`, visibly, in the validation report.

Purpose: M3-02-05 has nothing to train on until this runs, and the deliverable's corpus counts come
from here.
Output: `scripts/hc_games_refill.py`, `tests/test_m3_hc_games_refill.py`, a refilled
`data/reference/hc_games.csv`, an updated `docs/hc-workbook-ingest.md`.
</objective>
