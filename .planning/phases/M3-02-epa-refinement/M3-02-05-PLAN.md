<objective>
Retrain EP and WP on the enlarged corpus and measure what the head coach's data actually adds.

The methodology is locked from phase 1.3 (EPA-D02) and this plan changes none of it. One correction
to CONTEXT's wording, from M3-02-RESEARCH section 5.1: every reported EP/WP metric in this project
comes from **leave-one-game-out** over `game_id` (`model/evaluate.py::run_logo`,
`sklearn.model_selection.LeaveOneGroupOut`), not from a small fixed `GroupKFold` — that variant is
used only inside `_tune`'s inner hyperparameter search and is never the reported number. EPA-D04's
"frozen GroupKFold folds" therefore means: **the set of `game_id`s in each arm is pinned and written
down**. LOGO is exhaustive over whatever games are in the input frame, so a shared split object
would be meaningless; `corpus_arms.csv` plus the already-logged `training_data_sha256` is what makes
each arm reproducible.

The ablation needs no new training-harness code (RESEARCH section 5.2): `train_ep`/`train_wp` take a
`plays: pl.DataFrame` directly, so the two arms are two calls with different input frames. Likewise
per-source calibration reporting already exists — `model/evaluate.py::per_source_metrics` computes
per-source log-loss against each source's OWN naive class-frequency baseline plus a pooled row, and
`_train` already logs it as a Markdown artifact per run. This plan calls what exists and writes the
results down; it does not build a second measurement path.

Two honest framings to carry into the deliverable, both from the 1.3 training report: WP beat its
naive baseline by a wide margin (0.367 vs 0.691) while **EP did not** (1.028 vs 1.007). Whether the
enlarged corpus changes that is one of the questions this run answers, and the answer goes into
`docs/epa-refinement-2026-10.md` either way.

Purpose: HC-03's first half — the retrained, calibrated, versioned models and the measured value of
the head coach's rows.
Output: `scripts/hc_corpus_ablation.py`, `tests/test_hc_corpus_ablation.py` and seven CSVs under
`data/reference/epa_refinement/`.
</objective>

<runtime_expectations>
Training runs on this machine (CPU/MPS), autonomously, but not within a default command timeout.
Measured in 1.3 (`01.3-TRAINING-REPORT.md` section 2, run `5b17f0be...` / `c86922a0...`):
214 LOGO folds took **162.8 s for EP** and **29.7 s for WP** on 16,444 / 16,646 plays.

Leave-one-game-out cost grows roughly with folds x rows. With the head-coach games added, expect
several hundred folds and materially more rows per fold, so budget on the order of ten to twenty
minutes for an EP arm and a few minutes for a WP arm — four arms in total. Run each arm as a
**single foreground command with an extended timeout** (up to the 600 000 ms maximum), or as one
background command, and never with `--tune` (hyperopt would multiply this by `max_evals`). If an arm
exceeds the budget, report the measured `logo_wall_seconds` rather than reducing the fold count or
sub-sampling the corpus — the fold scheme is locked by D-07.
</runtime_expectations>
