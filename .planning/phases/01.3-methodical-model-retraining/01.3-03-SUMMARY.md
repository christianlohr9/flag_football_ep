## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Extended the T-1.2-32 stateful-CLI-subcommand hygiene guard to `ffep promote`**
- **Found during:** Task 2 (writing `ffep promote` CLI tests)
- **Issue:** `tests/test_cli_run.py::test_no_test_invokes_a_stateful_cli_command_without_a_config_override` statically scans every test module for `.invoke(app, [...])` calls naming a "stateful" subcommand without `--config`/`--help`, to prevent a forgotten `--config` from silently reading/writing the operator's real `mlruns`/`models`. The new `promote` command is exactly this kind of stateful subcommand (it reads and writes the real MLflow store when `--config` defaults to the checked-in `ffep.toml`), but `_STATEFUL_SUBCOMMANDS` did not list it, so a future test author invoking `promote` without `--config` would go undetected.
- **Fix:** Added `"promote"` to `_STATEFUL_SUBCOMMANDS` in `tests/test_cli_run.py`.
- **Files modified:** `tests/test_cli_run.py`
- **Verification:** `.venv/bin/pytest tests/test_cli_run.py -q` passes; every new `promote` invocation in `tests/test_cli_smoke.py` already passes `--config` explicitly, so this change is purely a stricter future-regression guard, not a fix to an existing violation.
- **Committed in:** `cb2baa5` (Task 2 test commit)

**2. [Rule 1 - Bug] CLI `--help` content assertions must strip ANSI escape codes before substring matching**
- **Found during:** Task 2 (`test_promote_help`, and transitively the plan's own `<acceptance_criteria>` command `.venv/bin/ffep promote --help exits 0 and its output contains --model and --run`)
- **Issue:** Typer's rich-based `--help` renderer highlights an option's leading `--` separately from the rest of the option name, inserting an ANSI color-reset escape sequence between the two literal `-` characters (e.g. `--model` becomes the byte sequence for `-` + reset-escape + `-model`). This happens even when stdout is piped to a file (verified: `ffep promote --help > file; grep -c -- "--model" file` returns 0). A naive `"--model" in result.output` (or a literal `grep`) therefore always fails, independent of anything this plan changed -- it is pre-existing CLI-wide rendering behavior, first exposed here because this is the first test in the suite asserting on specific option-flag text in `--help` output.
- **Fix:** Added a `_plain()` helper in `tests/test_cli_smoke.py` that strips `\x1b\[[0-9;]*m` sequences before asserting; `test_promote_help` now asserts against the stripped text. Verified the equivalent Python-side check for the plan's literal acceptance-criterion command (`.venv/bin/ffep promote --help`) also confirms `--model`/`--run` present after stripping.
- **Files modified:** `tests/test_cli_smoke.py`
- **Verification:** `.venv/bin/pytest tests/test_cli_smoke.py::test_promote_help -q` passes.
- **Committed in:** `cb2baa5` (Task 2 test commit)
