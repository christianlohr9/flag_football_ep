### `src/flag_football_ep/model/evaluate.py` (NEW service, batch) — NEW FILE

**Analog:** `model/train.py`'s `_tune` function (lines 266-346) — same "loop over splits, fit, collect losses" shape, adapted from hyperopt trials to LOGO folds.

**Core LOGO loop pattern** (verified against installed scikit-learn 1.5.1, per RESEARCH.md Pattern 1):
```python
from sklearn.model_selection import LeaveOneGroupOut
import numpy as np

logo = LeaveOneGroupOut()
groups = model_data["game_id"].to_numpy()
X = model_data.select(features).to_numpy()
y = model_data.select("label").to_numpy().ravel()

oof_pred = np.full((len(y), num_class), np.nan)
for train_idx, test_idx in logo.split(X, y, groups=groups):
    model = xgb.XGBRegressor(**fit_params)
    model.fit(X[train_idx], y[train_idx], sample_weight=weight[train_idx] if weight is not None else None)
    oof_pred[test_idx] = model.predict(X[test_idx])
```
`logo.get_n_splits(groups=groups)` gives the exact fit count up front (RESEARCH.md Pattern 1 note) — mirror `train.py`'s existing pre-flight validation style (`missing = [...]; if missing: raise ...`, lines 184-188) to surface this count/estimate before the loop starts.

**Reliability curve pattern (per-class, one-vs-rest)** — same "loop and accumulate" shape as the LOGO loop above:
```python
from sklearn.calibration import calibration_curve

for class_idx, class_name in enumerate(EP_PROB_LABELS):
    y_true_binary = (oof_labels == class_idx).astype(int)
    y_prob_class = oof_pred[:, class_idx]
    frac_pos, mean_pred = calibration_curve(y_true_binary, y_prob_class, n_bins=10)
```

**Naive baseline log-loss pattern** — reuses `sklearn.metrics.log_loss`, already imported in `train.py` (line 56):
```python
class_freqs = np.bincount(train_y, minlength=num_class) / len(train_y)
naive_pred = np.tile(class_freqs, (len(test_y), 1))
naive_log_loss = log_loss(test_y, naive_pred, labels=list(range(num_class)))
```

**Error handling:** follow `train.py`'s named-exception convention (`MissingTrainingColumns` at line 84-85) — add a module-level exception class here if evaluate.py needs its own (e.g. for a `game_id` group with degenerate single-row folds), rather than letting a raw `sklearn` exception surface.

**Inner-CV tuning note:** `GroupKFold(n_splits=5)` for the hyperopt inner loop lives inside `_tune`'s `_objective` in `train.py` (or is called from there) — do not run LOGO inside hyperopt trials (RESEARCH.md Anti-Pattern, explicit CONTEXT lock).

```python
_COMPETITION_TIER_SCHEMA: dict[str, pl.DataType] = {
    "source": pl.Utf8,
    "competition": pl.Utf8,
    "tier": pl.Utf8,
}

def load_competition_tier(path: Path) -> pl.DataFrame:
    """Load `source,competition,tier`. Rejects duplicate (source, competition)."""
    df = _read_reference_csv(path, _COMPETITION_TIER_SCHEMA)
    if df.height:
        dupes = (
            df.group_by(["source", "competition"])
            .agg(pl.len().alias("n"))
            .filter(pl.col("n") > 1)
            .select(["source", "competition"])
            .rows()
        )
        if dupes:
            raise ValueError(f"duplicate (source, competition) pair(s) in {path}: {dupes}")
    return df
```

### Named-exception, no-silent-failure error handling
**Source:** `src/flag_football_ep/model/train.py` (`MissingTrainingColumns`, line 84-85), `src/flag_football_ep/model/score.py` (`RunNotFound`, `MissingScoreColumns`, lines 55-60), `src/flag_football_ep/features/mutations.py` (`MissingFeatureColumns`, `DegenerateWeightRange`, lines 41-55), `src/flag_football_ep/reference.py` (`MissingReferenceFile`, `UnmappedTeamError`, lines 20-25)
**Apply to:** every new module in this phase (`evaluate.py`, `registry.py`, `charts/pat_breakeven.py`) — define a narrow `ValueError` subclass per failure mode, and raise it with a message naming the specific offending value/column/path, never let a library exception (polars `ColumnNotFoundError`, `MlflowException`, raw `KeyError`) surface unnamed. Every existing module in this codebase does this consistently; it is the strongest convention to preserve.

### Config-scoped, path-validated resolution (T-1.2-08 lineage)
**Source:** `src/flag_football_ep/model/score.py` lines 48-50, 63-118 (`_RUN_ID_PATTERN`, `_validate_run_id`, `resolve_run`, `load_model`)
**Apply to:** `registry.py`'s alias/model-name validation, and any CLI flag (`--ep-run`, future `--alias`) that reaches an MLflow URI string. Every function that builds a `runs:/` or `models:/` URI must (1) set the tracking URI from `config.paths.mlruns`/`config.paths.mlruns / "mlflow.db"` first, never trust an ambient URI, and (2) validate any caller-supplied identifier against a plain-identifier regex before interpolating it into the URI string.
