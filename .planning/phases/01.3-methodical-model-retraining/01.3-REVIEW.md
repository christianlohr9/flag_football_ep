# Phase 01.3: Code Review Report

**Reviewed:** 2026-08-19
**Depth:** standard
**Files Reviewed:** 31
**Status:** issues_found

## Summary

Reviewed the phase 01.3 training/experiment/promotion/scoring stack (LOGO evaluation, PAT
baselines, feature-candidate harness, MLflow registry, break-even chart, CLI wiring) plus its
test suite and operator docs. The security posture is solid: run ids, model names and aliases
are pattern-validated before URI interpolation (T-1.2-08 / T-1.3-07), secrets never touch
committed config, MLflow metric keys are sanitised, and no `eval`/`pickle.load`/injection
paths exist. The LOGO protocol, cross-game leakage scoping, and atomicity of the OOF writes
were traced and hold. Documentation cross-checks pass (the quoted `resolve_champion` error
message, OOF column contract, CANDIDATES list and adoption criterion all match the code).

No Critical findings. Ten Warnings, concentrated in three areas: the opt-in `--tune` path
(an unevaluated `reg_lambda` shipped into the refit, misleading logged params, and a
crash-prone inner CV on class-sparse folds), train/score encoding asymmetry for null-`down`
rows on the warn-only legacy source, and several places where the codebase's own
"no silent failure / fail loudly with names" convention has gaps (`Total_W_Scaled` range,
`map_competition_tier`'s error path, `.env` resolution, non-atomic `ffep score` output).

## Warnings

### WR-01: Hyperopt objective never applies `reg_lambda`, but the tuned refit does

**File:** `src/flag_football_ep/model/train.py:411-421, 451-463`
**Issue:** `HYPEROPT_SPACE` samples `reg_lambda`, and `_tune`'s returned `fit_params` applies
`best["reg_lambda"]` to the production refit (line 461), but the trial `_objective`'s
`XGBClassifier(...)` constructor (lines 412-421) never passes `reg_lambda`. Every trial is
therefore scored with XGBoost's default `reg_lambda=1`, while the shipped refit gets whatever
value the winning trial happened to sample — an unmeasured hyperparameter applied to the
production model. Unlike the documented `colsample_bytree` int-cast bug (hyperparams.py
lines 128-135, deliberately not ported), this omission is not called out anywhere; if it is a
notebook-fidelity decision it must be documented, otherwise it is a tuning bug.
**Fix:**
```python
clf = xgb.XGBClassifier(
    ...,
    reg_alpha=space["reg_alpha"],
    reg_lambda=space["reg_lambda"],
    ...
)
```
Or, if preserving notebook behaviour: drop `reg_lambda` from `fit_params` and document the
decision next to the `HYPEROPT_QUNIFORM_KEYS` comment.

### WR-02: Tuned runs log the fixed hyperparameters as run params, not the params actually fit

**File:** `src/flag_football_ep/model/train.py:292-307`
**Issue:** `params = {**fixed_params, ...}` logs `eta=0.025`, `max_depth=5`, `subsample=0.8`
etc. for every run — including tuned runs, where the model was actually fit with
`fit_params` (best-trial values, and `subsample` deliberately dropped). An operator reading
the MLflow UI to review a run before `ffep promote` (the exact workflow docs/model-training.md
§2-3 prescribes) sees hyperparameter values the shipped model was not fit with; the `best_*`
params exist but nothing marks the unprefixed ones as stale in the tuned case.
**Fix:** Log the actual fit params: `params = {**{str(k): v for k, v in fit_params.items()}, ...}`
(keeping `best_*` for the raw search output), or log fixed params under a `fixed_` prefix when
`tune=True`.

### WR-03: `--tune` inner CV crashes opaquely when a fold's training partition misses a class

**File:** `src/flag_football_ep/model/train.py:398-431`
**Issue:** The comment at line 397-398 claims `class_labels` (computed on the full frame)
prevents log_loss from raising when "an inner fold [is] missing a rare class" — but that
guard only covers the *eval* side. If a GroupKFold *training* partition lacks a class (very
plausible for EP's rare Safety/Opp_Safety classes, which appear in few games), `XGBClassifier.fit`
raises an opaque "Invalid classes inferred from unique values of y" error, or `predict_proba`
returns fewer columns than `class_labels` and `log_loss` raises a shape mismatch. This
violates the codebase's named-exception convention (`EvaluationError`/`ExperimentError`
elsewhere) exactly where a small or skewed corpus makes it likely.
**Fix:** Pre-flight the split before the hyperopt loop:
```python
for train_idx, _ in group_kfold.split(X_np, y_np, groups=groups_np):
    missing = set(class_labels) - set(np.unique(y_np[train_idx]))
    if missing:
        raise MissingTrainingColumns(  # or a dedicated TuningError
            f"_tune: inner CV fold's training partition is missing class(es) {sorted(missing)} "
            "-- too few games carry these labels for a grouped inner CV; reduce INNER_CV_FOLDS "
            "or grow the corpus"
        )
```

### WR-04: Null-`down` rows are trained with all-zero one-hots but scored as null

**File:** `src/flag_football_ep/features/mutations.py:792-797` and `src/flag_football_ep/model/score.py:127-133`
**Issue:** `make_ep_model_mutations` encodes down dummies via `pl.when(down == k).then(1).otherwise(0)`,
so a null `down` yields all five dummies = 0 and the row *survives* training (`down` itself is
not in `EP_SELECTED_COLUMNS`, and `drop_nulls` only sees the dummies). `_prepare_ep_features`
in score.py encodes the same dummies via `(down == k).cast(Int32)`, so a null `down` yields
null dummies and `_score_probabilities` gives the row null probabilities. Null-`down` rows are
real: `downs_range` failures are downgraded to WARN on the legacy source (docs/pipeline.md §4),
so such rows live in `plays.parquet`. The same physical row is a valid training example but an
unscoreable row at inference — a silent train/serve encoding divergence.
**Fix:** Make the encodings identical. Either match training in scoring:
```python
down0=pl.when(pl.col("down") == 0).then(1).otherwise(0).cast(pl.Int32), ...
```
or (better, avoids training on all-zero phantom encodings) add `"down"` to the null-drop in
`make_ep_model_mutations`'s `.filter(...)` so null-`down` rows are excluded from training too,
and document which was chosen.

### WR-05: `Total_W_Scaled` min-max rescale has no degenerate-range guard on `Total_W` itself

**File:** `src/flag_football_ep/features/mutations.py:843-845`
**Issue:** `DegenerateWeightRange` is raised for zero-range `Drive_Score_Dist` and
`score_differential`, but the final rescale `(Total_W - min) / (max - min)` is unguarded. A
`Total_W` with zero range (component weights that offset, or a `recency_weight_column`
containing zeros driving `Total_W` toward a constant) silently produces NaN sample weights —
precisely the RESEARCH Pitfall 4 failure mode this module's docstring claims cannot occur.
**Fix:** After computing `Total_W`, mirror the existing guards:
```python
total_w_max, total_w_min = df2["Total_W"].max(), df2["Total_W"].min()
if total_w_max == total_w_min:
    raise DegenerateWeightRange("Total_W has zero range across the input frame ...")
```

### WR-06: `map_competition_tier` error path raises TypeError instead of `UnmappedCompetitionError` on null keys

**File:** `src/flag_football_ep/reference.py:226-237`
**Issue:** When any row's `source` or `competition` is null (the pre-01.3 IFAF default when no
`tournament_*.json` is present — see test_pipeline_ingest.py:223-228, which had to add that
file precisely because null `competition` occurs), the left join yields a null `tier`, the
row lands in `unmapped`, and `sorted(unmapped)` then compares `None` against `str` —
`TypeError: '<' not supported between instances of 'NoneType' and 'str'`. The diagnostic that
exists to name the offending pair crashes before naming it.
**Fix:**
```python
details = ", ".join(
    f"(source={source!r}, competition={competition!r})"
    for source, competition in sorted(unmapped, key=lambda p: (str(p[0]), str(p[1])))
)
```

### WR-07: `.env` is resolved from the process CWD, breaking the "same behaviour from any directory" invariant

**File:** `src/flag_football_ep/config.py:145, 188-199`
**Issue:** `load_config` resolves every path relative to the config file's directory and
docs/pipeline.md §6 states "ffep behaves the same regardless of where it is invoked from" —
but `load_dotenv()` is called with its default `Path(".env")`, which is CWD-relative. Running
`ffep --config /path/to/ffep.toml fetch-sportapp` from any other directory silently skips the
repo's `.env` and fails with "environment variable not set", a confusing failure whose cause
(wrong CWD) is never named.
**Fix:** Resolve `.env` next to the config file: `load_dotenv(path.resolve().parent / ".env")`
(keeping the never-overwrite semantics), or document loudly that `.env` is CWD-only.

### WR-08: `score_plays` estimates PAT baselines from whatever frame it is given

**File:** `src/flag_football_ep/model/score.py:234`
**Issue:** `estimate_pat_baselines(plays)` runs on the input frame. In the default `ffep score`
flow (full canonical corpus) this matches REQ-S1-10's pooled-full-corpus contract, but
docs/model-training.md §5 explicitly directs new/unseen games to champion-model scoring via
`ffep score` — and scoring a subset (a new game's frame, or `plays.parquet` filtered upstream)
silently computes PAT rates from that subset's handful of attempts (different `epa` semantics
than every reported number), or hard-fails with `InsufficientPatAttempts` when the subset has
no PAT-shaped rows at all. Either outcome contradicts "pooled full-corpus baseline" without
telling the operator.
**Fix:** At minimum, document in `score_plays`'s docstring and docs/model-training.md §5 that
`ffep score` must be fed the full canonical frame. Better: log the attempt counts used
(`n=`) into the run/console output so a subset-derived baseline is visible, or persist the
training-time baselines as run params and warn when the scoring-time estimate diverges.

### WR-09: `ffep score` writes its Parquet non-atomically and does not create `--out` parents

**File:** `src/flag_football_ep/cli.py:194-195`
**Issue:** `scored.write_parquet(out_path)` writes directly onto the live path. Every other
processed-dir artifact in this codebase (ingest Parquet, OOF predictions) uses the
write-to-`.tmp`-then-`Path.replace` discipline specifically so "an interrupted write cannot
destroy a previously good file" (evaluate.py:334-357) — a crash mid-write here corrupts
`plays_scored.parquet`, the one downstream-facing scored artifact. Additionally, an `--out`
path in a non-existent directory raises a raw OS error instead of creating parents (both
`write_pat_breakeven` and `write_oof_predictions` do `mkdir(parents=True)`).
**Fix:**
```python
out_path.parent.mkdir(parents=True, exist_ok=True)
tmp_path = out_path.with_suffix(out_path.suffix + ".tmp")
try:
    scored.write_parquet(tmp_path)
    tmp_path.replace(out_path)
finally:
    if tmp_path.exists():
        tmp_path.unlink()
```

### WR-10: Suite-hygiene guard omits the two new stateful subcommands

**File:** `tests/test_cli_run.py:368-376`
**Issue:** `_STATEFUL_SUBCOMMANDS` (the T-1.2-32 guard that fails any test invoking a stateful
CLI command without `--config`) lists the seven pre-01.3 commands but not `experiment` (reads
`plays.parquet`, writes MLflow runs into the configured store) or `pat-breakeven` (reads
`plays.parquet`, writes a PNG) — both added this phase, both stateful. A future test invoking
either without `--config` would silently fall back to the checked-in `ffep.toml` and write
into the operator's real `data/processed`/`mlruns`, exactly what this guard exists to prevent.
Current tests happen to pass `--config`, but the gate no longer covers the full surface.
**Fix:**
```python
_STATEFUL_SUBCOMMANDS = (
    "ingest", "run", "train", "score", "promote",
    "fetch-sportapp", "fetch-ifaf", "experiment", "pat-breakeven",
)
```

## Info

### IN-01: `resolve_run`'s `experiment` parameter is dead, and explicit run ids are not scoped to the model

**File:** `src/flag_football_ep/model/score.py:77-102`
**Issue:** The `experiment` argument is never read in the function body — resolution goes
through the run-id/registry paths only. Consequently an explicit `--ep-run` is validated as
hex and existing, but never checked to belong to the EP experiment (or even to be a training
run at all); a wrong-model run id fails later inside `_score_probabilities` with an opaque
shape error instead of a named one.
**Fix:** Drop the parameter or use it: after `mlflow.get_run(run_id)`, assert the run's
experiment name equals `experiment` and raise `RunNotFound` naming both otherwise.

### IN-02: Stale `_register_run` helpers register duplicate model versions per run

**File:** `tests/test_model_score.py:152-164`, `tests/test_cli_smoke.py:54-64`
**Issue:** Both docstrings claim "train_ep/train_wp do not call registered_model_name=
themselves (that wiring lands in plan 01.3-05)" — plan 01.3-05 landed; `_train` now registers
via `register_as` unconditionally. The helpers therefore register a *second* version for the
same run, so `registry.promote`'s `matches[0]` picks among two versions per run and the tests
exercise a doubled-registration state no production flow produces.
**Fix:** Delete `_register_run` and its call sites (the trained run is already registered), and
update the docstrings.

### IN-03: `run_logo`'s NaN check conflates coverage gaps with model-produced NaN

**File:** `src/flag_football_ep/model/evaluate.py:127-131`
**Issue:** The sentinel matrix is initialised with NaN and the post-loop check reports "at
least one row was never predicted" — but a fold model emitting NaN predictions (degenerate
fit, inf features) triggers the same message, sending the operator down the wrong path.
**Fix:** Track coverage with a boolean mask (`covered[test_idx] = True`) and report the two
conditions separately.

### IN-04: `artifact_location` builds a `file://` URI by string concatenation

**File:** `src/flag_football_ep/model/mlflow_store.py:42`
**Issue:** `"file://" + str(path)` produces an invalid URI for paths containing spaces or
non-ASCII characters (plausible on macOS user directories).
**Fix:** `return (config.paths.mlruns / "artifacts").as_uri()`.

### IN-05: Sanitised per-source metric keys can collide silently

**File:** `src/flag_football_ep/model/train.py:315-324`
**Issue:** Two distinct sources that sanitise to the same key (e.g. `legacy-sportapp` and a
hypothetical `legacy_sportapp`) overwrite one another in the `metrics` dict; only the
`sanitized_source_metric_keys` param would hint at it, and only for the renamed one.
**Fix:** Detect collisions after sanitisation and suffix (`_2`) or raise.

### IN-06: Dead defensive `getattr` on a required config key

**File:** `src/flag_football_ep/cli.py:126, 405`
**Issue:** `getattr(cfg.sources.ifaf, "api_key_env", None)` — `api_key_env` is in `_IFAF_KEYS`,
so `load_config` guarantees the attribute exists; the fallback branch is unreachable and
suggests the key is optional when it is not.
**Fix:** Use `cfg.sources.ifaf.api_key_env` directly (its value may still be an unset env
name, which `secret(..., required=False)` already handles).

### IN-07: Config values are not type-validated

**File:** `src/flag_football_ep/config.py:175-178`
**Issue:** `_key` returns raw TOML values. `exclude_games_ep = "legacy-37"` (a string instead
of a list) passes loading, and `list("legacy-37")` downstream silently becomes single
characters — excluding nothing, with no error. Same for every str-typed field receiving a
non-string.
**Fix:** Assert `isinstance(value, list)` (and element `str`) for `exclude_games_*` in
`load_config`, raising `ConfigError` naming the key.

### IN-08: OOF predictions are overwritten before the MLflow run exists

**File:** `src/flag_football_ep/model/train.py:277`
**Issue:** `write_oof_predictions` replaces `oof_predictions_{ep,wp}.parquet` before
`_log_run` starts the run. If MLflow logging fails, the on-disk OOF files reflect a training
attempt no recorded run describes, and the previous (recorded) run's `oof_predictions_path`
param now points at data from a different fit.
**Fix:** Write the OOF file after the run is created (inside `_log_run`'s run context, or
return the frame and write post-`_log_run`), so disk state and tracked runs cannot diverge.

### IN-09: CLI smoke test's subcommand list omits `experiment` and `pat-breakeven`

**File:** `tests/test_cli_smoke.py:31`
**Issue:** `SUBCOMMANDS` covers the seven pre-01.3 commands, so
`test_top_level_help_lists_all_subcommands` never asserts the two new commands appear in
`ffep --help` (their own `--help` tests live in other modules, but the top-level listing is
unguarded).
**Fix:** Add `"experiment"` and `"pat-breakeven"` to `SUBCOMMANDS`.

### IN-10: A failed `savefig` leaves a corrupt PNG that the write-once guard then protects

**File:** `src/flag_football_ep/charts/pat_breakeven.py:102-116`
**Issue:** `fig.savefig(out_path)` writes directly to the live path; if it fails partway, a
truncated PNG remains, and the next run without `--overwrite` refuses to replace it — the
guard designed to protect a good chart now protects a corrupt one.
**Fix:** Save to a `.tmp` sibling and `Path.replace` onto `out_path` (the same discipline as
`write_oof_predictions`), keeping the pre-existence check on the final path.
