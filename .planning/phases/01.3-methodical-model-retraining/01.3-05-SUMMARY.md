## Decisions Made

- Replicated `pipeline._atomic_write_parquet`'s write-to-temp-then-`Path.replace` shape directly in `write_oof_predictions` rather than importing the helper. Importing `pipeline.py` does not create a circular import (verified: nothing under `ingest/`, `validation/`, or `reference.py` imports `model.evaluate`), but the plan's own acceptance criterion (`grep -n "replace(" ... returns a match inside write_oof_predictions`) requires the atomic-rename call to be textually present in `evaluate.py`, which a delegated call to the imported function would not satisfy. Replicating also keeps `evaluate.py` free of `pipeline.py`'s heavier `ingest`/`typer` import chain.
- `naive_baseline_logloss`/`reliability_curves`/`per_source_metrics` all use `num_class == 1` as the binary-WP convention (marginal positive rate, no one-vs-rest binarisation), matching `fixed_params.get("num_class")` being absent (`None`) for WP's fixed params. `_train` computes `report_num_class = num_class or 1` once from the pre-tune `fixed_params` and threads it through all three calls, so EP (`num_class=5`) and WP (`num_class=1`) share one code path.
- Per-source MLflow metric keys (`logo_logloss_by_source_<source>`) are built only from the non-`__pooled__` rows of `per_source_metrics`'s output -- the pooled numbers are already covered by the existing `metric_name`/`naive_*`/`logloss_improvement` trio, so logging a fourth pooled-duplicate metric would be redundant.
- `render_reliability_figure`'s returned `Figure` is closed via `matplotlib.pyplot.close(fig)` inside a `try/finally` wrapped around the `_log_run` call, so a training run's figure is never leaked even if `_log_run` raises after `mlflow.log_figure` has already read it.
