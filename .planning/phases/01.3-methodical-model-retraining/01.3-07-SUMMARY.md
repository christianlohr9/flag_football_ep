## Accomplishments

- `src/flag_football_ep/model/experiments.py`: `run_candidate` mirrors `train._train`'s pipeline (filter excluded games -> `spec.build` -> `prepare_fn` -> `mutate_fn` -> `drop_nulls()`) and measures a control arm (current `EP_FEATURES`/`WP_FEATURES`) and a candidate arm (control plus the candidate's extra columns) with `model.evaluate.run_logo`, on the identical frame and folds. `delta = control_logloss - candidate_logloss`; `adopted = delta > CANDIDATE_ADOPTION_MIN_DELTA` (0.0). Raises `ExperimentError` naming the offending column when a candidate feature already exists in the control list or is missing after `spec.build`, and naming the row counts when the two arms' row sets diverge.
- Every candidate run logs to a dedicated `{experiment}_candidates` MLflow experiment (`candidate_experiment_name`) with a `candidate` tag, `verdict` param (`adopted`/`rejected`), both feature lists, `n_folds`/`n_plays`/`model_prefix` params and `control_logloss`/`candidate_logloss`/`delta` metrics -- never a model artifact, registration or alias call.
- `CANDIDATES` registers `half` (a passthrough -- already a `CORE_COLUMNS` Int32 column) and `competition_tier` (built via the new `add_competition_tier_features`).
- `src/flag_football_ep/features/mutations.py`: `add_competition_tier_features(df, mapping)` joins the maintained tier vocabulary via `reference.map_competition_tier` (raising `UnmappedCompetitionError` on any unmapped `(source, competition)` pair, never silently zeroing a row's tier) and derives one Int32 indicator column per `COMPETITION_TIERS` entry, built from the vocabulary itself so the feature list is stable across corpora even when a tier is unobserved.
- `src/flag_football_ep/cli.py`: `ffep experiment --candidate {name|all} --model {ep|wp|both}` validates both flags against closed sets with `typer.BadParameter`, then runs `run_candidate` for every applicable (model, candidate) pair and echoes control/candidate log-loss, delta and verdict.
- Ran the real experiments against the ingested corpus (`.venv/bin/ffep ingest` against the raw Hudl/legacy/IFAF data present in this worktree -- 21,437 plays, 247 games) via both the CLI and a direct `run_candidate` call for precise wall-clock timing. Results below.
- `tests/test_model_experiments.py` (30 tests): every `<behavior>` bullet for Tasks 1-3 -- `CandidateResult` field coverage, verdict/delta arithmetic, equal-row-set and offending-column error paths, MLflow logging (dedicated experiment, no production-experiment pollution, no model artifact), the `competition_tier` candidate's registration and row-count parity, and CLI help/bad-parameter behavior.
- `tests/test_features_mutations.py` gains a `TestAddCompetitionTierFeatures` class (9 tests): one-Int32-column-per-tier, naming rule, exactly-one-hot-per-row, row count/order preservation, returned column names, unmapped-pair error, all-zero column for an unobserved tier, intermediate-column removal, and a real-corpus smoke test (skipped if the corpus is absent).

## Decisions Made

- `run_candidate` always measures against the fixed `EP_PARAMS`/`WP_PARAMS`; `tune`/`max_evals` are accepted for interface symmetry with `train.train_ep`/`train_wp` but unused, so a candidate's outcome is never conflated with a differently-tuned hyperopt run.
- The competition-tier candidate's `build` runs before `prepare_fn`/`mutate_fn` (documented in both the module docstring and the spec's own docstring) because the `(source, competition)` join needs the raw canonical `competition` column, which is not in `GROUP_COLUMNS` and is dropped by `mutate_fn`'s final `.select(...)`.
- The equal-row-set guard builds and `drop_nulls()`s the control and candidate frames separately (both from the same `prepared` frame) and compares heights explicitly, rather than trusting that adding columns to a `.select(...)` call cannot change row count -- this is what makes the "candidate that changes the row set is not comparable" CONTEXT constraint enforceable rather than aspirational.
