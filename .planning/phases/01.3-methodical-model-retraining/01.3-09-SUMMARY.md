# Phase 1.3 Plan 09: Combined Adoption, Full Retrain, Promotion and Docs Summary

**Adopted `half`+`competition_tier` into `EP_FEATURES` and `competition_tier` into `WP_FEATURES` after a combined-confirmation measurement, retrained both models on the full 21,437-play/247-game real corpus under leave-one-game-out (WP beats its naive baseline by a wide margin and calibrates well; EP does not beat naive and shows real miscalibration -- reported honestly), promoted both to `champion` after human review of the training report and MLflow UI, and shipped `docs/model-training.md` as the operator guide.**

## Performance

- **Duration:** ~4h wall-clock across two sessions, split by the plan's mandatory Task 3
  human-review checkpoint. Excluding the review pause itself, active execution (adoption
  decision + retraining + report writing, then promotion + docs after approval) was roughly
  2h30m, most of it real leave-one-game-out fitting wall time (162.8s + 29.7s per full LOGO
  pass, run twice across the full test suite reruns needed to catch and fix fallout from the
  feature-list change).
- **Started:** 2026-08-19 (Task 1)
- **Completed:** 2026-08-19 (Task 4, post-checkpoint-approval)
- **Tasks:** 4 (3 `auto` + 1 `checkpoint:human-verify`, `gate="blocking"`)
- **Files modified:** 15 (2 created, 13 modified)

## Accomplishments

- **Task 1 (adoption decision):** Read all four REQ-S1-09 verdicts (`01.3-07-SUMMARY.md`:
  `half` adopted EP / rejected WP, `competition_tier` adopted both; `01.3-08-SUMMARY.md`:
  `recency` rejected (no-op), `real_clock` not viable) and applied CONTEXT's criterion.
  Measured a **combined confirmation arm** for EP (`half`+`competition_tier` together, since
  both were independently adopted) via a one-off script against the harness before committing:
  control 1.029113, combined 1.027657, delta **+0.001457** — beats control, so the union is
  adopted. `EP_FEATURES` gained `half` and the three `tier_*` columns; `WP_FEATURES` gained
  `tier_*` only. `hyperparams.py` documents every adopted column's justifying delta inline.
  `train.py::_build_competition_tier` (a new `_train` `build_fn` hook, mirroring
  `experiments.py`'s ordering) builds the tier one-hot columns before `prepare_fn`/`mutate_fn`
  for both `train_ep`/`train_wp`. `tests/test_migration_equivalence.py`'s "Known, expected
  deltas" gained a numbered REQ-S1-09 entry naming every adopted column with its delta.
- **Fallout fix (same task, separate commit):** because `competition_tier` is now part of the
  *production base feature set*, every caller that measures or scores against
  `EP_FEATURES`/`WP_FEATURES` needed the same build step: `model/score.py::score_plays` gained
  it (previously only `train.py` did), and `model/experiments.py` gained
  `_build_current_production_base_features`, called unconditionally in `run_candidate`/
  `run_recency_candidate`/`run_real_clock_experiment` so the harness's control arm matches
  production. `half`/`competition_tier` were removed from `CANDIDATES` (already adopted,
  nothing left to test — re-running either now correctly raises the existing
  already-in-control-list `ExperimentError`). Six more test files needed a matching
  `competition_tier.csv` fixture or inline mapping frame (`test_model_evaluate.py`,
  `test_model_registry.py`, `test_model_score.py`, `test_pipeline_ingest.py`,
  `test_cli_smoke.py`) — `test_pipeline_ingest.py`'s shared IFAF fixture also gained a
  `tournament_test.json` so its `competition` value stops being null (a null value can never
  match a mapping row).
- **Task 2 (retrain + report):** `.venv/bin/ffep ingest` reproduced the real corpus (21,437
  plays / 247 games, matching `01.3-DATA-PROFILE.md`). `.venv/bin/ffep train --model both

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `competition_tier` adoption broke `score_plays` and the candidate
harness's control arm**
- **Found during:** Task 1's own acceptance-criteria pytest run (`tests/test_model_experiments.py`
  and later the full suite)
- **Issue:** `EP_FEATURES`/`WP_FEATURES` gaining the `tier_*` columns meant every caller that
  selects those constants directly against a frame — not just `train.py`, which the plan's
  `<files>` list named — now needs the tier columns built first. `model/score.py::score_plays`
  raised `MissingScoreColumns` naming the tier columns; `model/experiments.py`'s `run_candidate`
  et al. raised `ColumnNotFoundError` for every candidate, including ones unrelated to
  `competition_tier`, because the *control* arm now also needs the columns.
- **Fix:** Added the same build step to `score_plays` (before either `prepare_fn` runs) and a
  new `_build_current_production_base_features` helper in `experiments.py`, called
  unconditionally at the top of all three harness entry points. Removed `half`/`competition_tier`
  from `CANDIDATES` (a candidate already in the base feature set has nothing left to test — the
  overlap guard would always reject it) and updated the tests that exercised them as generic
  "any candidate" examples to use a `season`-column passthrough spec instead.
- **Files modified:** `src/flag_football_ep/model/score.py`, `src/flag_football_ep/model/experiments.py`, `tests/test_model_experiments.py`
- **Verification:** `tests/test_model_experiments.py`, `tests/test_model_score.py` both green; full suite green.
- **Committed in:** `c15f52c`

**2. [Rule 3 - Blocking] Six more test files' synthetic corpora had no competition-tier mapping**
- **Found during:** a full-suite pytest run after Task 1's first commit (the plan's own
  acceptance criteria require the full suite to pass, and it did not on the first attempt)
- **Issue:** `test_model_evaluate.py`'s hand-built `model_data` helpers, and every
  `_make_config`-style fixture in `test_model_registry.py`/`test_model_score.py`/
  `test_pipeline_ingest.py`/`test_cli_smoke.py` that calls `train_ep`/`train_wp` against a
  synthetic corpus, had no `competition_tier.csv` (or, for `test_model_evaluate.py`, no inline
  mapping frame) for `_build_competition_tier`/`add_competition_tier_features` to read. IFAF's
  shared fixture (`test_pipeline_ingest.py::_write_ifaf_fixture`) had a null `competition` value
  (no `tournament_*.json` had ever been written for it) — a null value can never match a mapping
  row, so it needed a real value, not just a mapping entry.
- **Fix:** Added a default `competition_tier.csv` write (or, for the pure-`run_logo` test module,
  an inline `pl.DataFrame` mapping passed directly to `add_competition_tier_features`) to each
  affected fixture, covering the actual `(source, competition)` pairs each corpus produces.
  Added `tournament_test.json` to the shared IFAF fixture so its `competition` resolves to a
  real, mappable string ("IFAF Test Cup").
- **Files modified:** `tests/test_model_evaluate.py`, `tests/test_model_registry.py`, `tests/test_model_score.py`, `tests/test_pipeline_ingest.py`, `tests/test_cli_smoke.py`
- **Verification:** Full `pytest -q` green (re-run three times across this plan: after Task 1's
  fallout fix, after Task 2's retraining, after Task 4's docs — 0 failures each time).
- **Committed in:** `c15f52c`
