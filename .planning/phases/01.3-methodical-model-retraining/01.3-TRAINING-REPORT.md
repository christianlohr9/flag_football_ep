## 2. Evaluation protocol

Leave-one-game-out (LOGO) over `game_id` (REQ-S1-07, D-07): every game is held out exactly
once, fit on every other game's rows, and the held-out game's predictions accumulate into an
out-of-fold prediction matrix (`model/evaluate.py::run_logo`, `sklearn.model_selection.
LeaveOneGroupOut`). No game's plays ever appear in both a fold's train and test partition. This
replaces the notebooks' play-level 80/20 `train_test_split`, which let same-game plays leak
into both sides.

**Fold count: 214** for both models — not 246 (247 − 1 excluded game). `make_ep_model_mutations`
/`make_wp_model_mutations`'s `drop_nulls()` removes every row of a game whose `yards_to_go` is
null; per `01.3-DATA-PROFILE.md` §5 and the 01.3-08 finding, `yards_to_go` is null for **100%**
of `ifaf` rows in this corpus, and `WP_TRAINING_COLUMNS`/`EP_TRAINING_COLUMNS` both require it
— so all 32 `ifaf` games drop out entirely, plus the 1 excluded `legacy` game: 247 − 32 − 1 =
214. This is a pre-existing IFAF ingest data-coverage gap (01.3-08-SUMMARY.md), not something
this plan's code introduced; see §9.

## 4. Calibration

Reliability-curve PNGs (`reliability_ep.png` / `reliability_wp.png`) and the underlying
per-class `sklearn.calibration.calibration_curve` (one-vs-rest for EP's 5 classes, direct for
WP's binary case), 10 bins, logged as MLflow run artifacts on the runs cited in §3.

**WP (`reliability_wp.png`) looks well calibrated.** The single curve tracks the perfect-
calibration diagonal closely across the full [0, 1] range of predicted probabilities, consistent
with the large naive-baseline improvement in §3.

**EP (`reliability_ep.png`) does not look well calibrated**, and the picture explains §3's
result:
- `Touchdown_Prob` tracks reasonably at low-to-mid probabilities but crosses the diagonal and
  flattens near the top bins (the model's most confident touchdown predictions are
  *overconfident*).
- `Opp_Touchdown_Prob` is worse: the curve rises with the diagonal through mid-range bins, then
  reverses sharply at the highest-probability bin (observed frequency drops instead of rising)
  — a clear miscalibration in the model's most-confident opponent-touchdown predictions.
- `Safety_Prob`/`Opp_Safety_Prob` barely move off zero — both are rare-event classes with too
  few positive out-of-fold examples for the reliability curve to be informative; the model's
  predicted probabilities for these classes stay compressed near zero regardless of the true
  outcome.
- `No_Score_Prob` (the majority class) sits visibly below the diagonal across most bins — the
  model systematically underestimates how often "no score" actually follows, which is exactly
  the failure mode a strong class-frequency baseline exploits.

**This is report-only, per CONTEXT's explicit scope.** No isotonic/Platt calibration correction
is implemented in this plan; that is an explicit follow-up decision (§9) if the curves above are
judged bad enough to warrant it — which, per this reading, EP's curves are.

**`recency`**: rejected. `game_date` is null for 100% of rows in every source in this corpus
(`01.3-DATA-PROFILE.md` §2), so every half-life arm (60/180/365/730 days) is numerically
identical to the unweighted control — a documented no-op, not a genuine recency measurement.

**`real_clock`**: measurement is not viable on the real corpus. `run_real_clock_experiment`
raised a named `ExperimentError`: the IFAF-only subset (3,191 rows / 32 games) has 0% coverage
of `yards_to_go` (the same gap noted in §2/§5), so both arms reduce to 0 rows before `run_logo`
can measure anything. This is unrelated to `game_clock_ms` itself — `game_clock_ms` is 100%
populated for `ifaf` and the real-clock derivation is fully exercised in unit tests against a
synthetic corpus. **`real_clock` is never adopted into production regardless of its measured
delta** — CONTEXT is explicit that the production feature set stays synthetic until REQ-S1-02
delivers real Hudl time; this experiment's job was only to quantify the cost, which the current
corpus cannot yet do.

**Combined confirmation (plan 01.3-09 Task 1).** `half` and `competition_tier` were both
independently adopted for EP, so a combined arm was measured before committing to the union
(candidates were measured independently; their gains are not guaranteed to add):

| Arm | Model | Control log-loss | Combined log-loss | Delta | Verdict |
|---|---|---|---|---|---|
| `half` + `competition_tier` | EP | 1.029113 | 1.027657 | **+0.001457** | **adopted (union)** |
| `competition_tier` (sole adopted candidate) | WP | 0.367286 | 0.367263 | +0.000023 | adopted |

The EP combined arm beats the control (+0.001457 > 0), confirming the union rather than falling
back to the single best-performing subset. This combined number (1.027657) is exactly what the
real production run in §3 measures (`logo_mlogloss` 1.027657), confirming the harness and the
production pipeline agree.

**Final adoption decision:** `EP_FEATURES` gained `half` and the three `tier_*` one-hot columns;
`WP_FEATURES` gained the three `tier_*` columns only. `recency` and `real_clock` are not in
production. See `src/flag_football_ep/model/hyperparams.py` (provenance comments citing this
plan and the delta values above) and `tests/test_migration_equivalence.py`'s "Known, expected

`WP_PARAMS`, ported from the notebooks' previously-tuned cell-7/cell-6 values). **Reason:**
01.3-04's synthetic-proxy wall-time estimate (12.9s for a 47-game corpus) did not anticipate the
real corpus's 214-fold LOGO cost measured in this phase (162.8s EP / 29.7s WP for a single
fixed-params LOGO pass, §2) — `--tune`'s hyperopt search (`max_evals=100` by default) scores
each trial against a 5-fold grouped inner CV, not a full 214-fold LOGO pass, but 100 trials × 5
inner folds is still a materially larger fit count than one LOGO pass, and RESEARCH's
"Open Question 1" already records that the notebook's originally-tuned hyperparameters were
never persisted — so `EP_PARAMS`/`WP_PARAMS` are the only recoverable, previously-validated
defaults, and running without `--tune` keeps this phase's headline numbers reproducible against
a known, fixed hyperparameter set rather than a fresh, unbudgeted search. `--tune` remains
available (`ffep train --tune`) for a future retraining pass once its wall-clock cost is
separately budgeted.

## 9. Open items

- **`sportapp` (live sportapp.fi) is absent from this corpus.** STATE.md's blocker: the
  sportapp.fi API key rotation is deferred by the user; `ffep fetch-sportapp` has not been run.
  The corpus trains on `legacy`/`legacy-sportapp`/`ifaf` only (and `ifaf` contributes zero rows
  to training, see next item) — Hudl is also absent by worktree design (no files under
  `data/raw/hudl` at ingest time).
- **`ifaf` (IFAF WM-2026) contributes zero rows to production training**, not because it is
  excluded by policy but because `yards_to_go` is null for 100% of its 3,191 rows in this
  corpus (§2/§5/§6's `real_clock` finding) — a pre-existing IFAF ingest data-coverage gap
  (01.3-08-SUMMARY.md), out of this plan's scope to fix, but material to CONTEXT's "pool
  everything" strategy and the folded IFAF-benchmarking todo: until `ingest/ifaf.py`'s
  `yards_to_go` derivation is fixed, IFAF WM-2026 cannot be benchmarked through the training
  pipeline the way the folded todo intended.
- **REQ-S1-02 (real time data) is still pending.** `half_seconds_remaining`/
  `game_seconds_remaining` stay synthetic in production (`prepare_wp_data`'s default); the
  `real_clock` sub-experiment (§6) was meant to quantify the cost of that but could not run to
  completion on the real corpus for the reason above. The measured cost of synthetic time
  remains unknown pending both REQ-S1-02 (real Hudl time) and the `yards_to_go` ingest fix.
- **Calibration correction is deferred**, per CONTEXT's explicit scope boundary — §4's finding
  that EP's reliability curves are genuinely poor (crossing the diagonal on the touchdown
  classes, degenerate on the safety classes) is now on record as the evidence a future decision
  to add an isotonic/Platt correction layer would act on.
- **`recency`'s no-signal verdict (§6) is a data-contract gap, not a code gap** — `game_date` is
  100% null across every source; the mechanism is implemented and tested against synthetic
  dates and will activate automatically once any source's export carries real game dates.
- **`real_clock`'s not-viable verdict (§6) exposed a second, independent IFAF coverage gap**
  (`yards_to_go`) beyond the already-known `game_clock_ms`/`half_seconds_remaining` situation —
  worth flagging to whoever next touches `ingest/ifaf.py` or plans Phase 1.4's WP charts.
- **PAT rates (§7) are pooled across all sources but only `legacy` actually contributes PAT-
  shaped rows** — not a bug, but a limitation worth remembering before treating the CI as
  representative of, say, `ifaf`'s PAT behavior specifically.
- **EP does not beat its naive baseline (§3/§4)** — carried forward as the single most important
  open item for whoever reviews this report at the Task 3 checkpoint: promotion decisions should
  weigh this explicitly, not just check that a champion alias can technically be set.

## Success criteria

Mapping to `.planning/ROADMAP.md`'s Phase 1.3 "Success Criteria" (5 statements):

   train and test."** — **Met.** §2: every metric in this report comes from
   `sklearn.model_selection.LeaveOneGroupOut` over `game_id` (`cv_scheme=leave-one-game-out`
