# Phase 1.3 Plan 08: Recency Weighting and Real-Clock WP Sub-Experiment Summary

**Implemented exponential recency weighting (`add_recency_weight`, half-life grid `run_recency_candidate`) and an IFAF-only real-clock WP experiment (`prepare_wp_data(real_clock=True)`, `run_real_clock_experiment`); both measured against the real corpus with real, closing verdicts -- recency is a documented no-op given 100%-null `game_date`, and the real-clock comparison is not viable given 100%-null `yards_to_go` on the same IFAF rows.**

## Accomplishments

- `src/flag_football_ep/model/hyperparams.py`: `RECENCY_HALF_LIFE_DAYS_GRID = (60.0, 180.0, 365.0, 730.0)` and `RECENCY_NULL_DATE_WEIGHT = 1.0`, both with provenance comments citing REQ-S1-09, CONTEXT, and the exact `01.3-DATA-PROFILE.md` null-rate finding that shapes the null-date policy.
- `src/flag_football_ep/features/mutations.py`: `add_recency_weight(df, half_life_days)` parses `game_date` (`str.to_date(strict=False)`), computes `Recency_W = 0.5 ** (age_days / half_life_days)` against the frame's most recent date, fills null-date rows with `RECENCY_NULL_DATE_WEIGHT`, and returns `(frame, null_date_row_count)`. Raises `MissingFeatureColumns` (column absent), `InvalidGameDateValues` (unparseable non-null values, new exception), and `DegenerateWeightRange` (single distinct non-null date) -- never a silent NaN or zero weight.
- `make_ep_model_mutations` gained an optional keyword-only `recency_weight_column` that multiplies into `Total_W` before the existing min-max rescale; `None` (default) is byte-for-byte the prior behavior. `Drive_Score_Dist_W`/`ScoreDiff_W` and the `DegenerateWeightRange` guards are untouched.
- `src/flag_football_ep/model/experiments.py`: `CandidateSpec` gained an optional `weight_build` field. `run_recency_candidate(plays, config, model_prefix="ep")` builds one EP frame per `RECENCY_HALF_LIFE_DAYS_GRID` entry plus an unweighted control (identical `EP_FEATURES` across every arm), measures each with `run_logo`, logs every arm as its own MLflow run (`candidate=recency`, `half_life_days` param) in the EP candidate experiment, and returns `(best_half_life_result, half_life_results)`. Raises `ExperimentError` for any `model_prefix` other than `"ep"` (`train_wp` fits without sample weights) and for a half-life arm whose row count diverges from the control's.
- `prepare_wp_data` gained a keyword-only `real_clock: bool = False` parameter. `False` (default) is the exact pre-existing synthetic derivation, untouched. `True` sources `half_seconds_remaining` from `game_clock_ms / 1000.0` and derives `game_seconds_remaining`/`elapsed_share`/`Diff_Time_Ratio` with the same formulas the synthetic path uses. Raises `MissingFeatureColumns` (column absent) and the new `InvalidGameClockValues` (any null `game_clock_ms` in the frame). Module docstring updated to document the opt-in exception without weakening the "production stays synthetic until REQ-S1-02" statement.
- `run_real_clock_experiment(plays, config)` filters to `source == "ifaf"` before either arm, raises `ExperimentError` naming the source/row/game counts when the subset can't support LOGO, measures synthetic vs. real-clock arms on identical `WP_FEATURES` and folds, and logs both to the WP candidate experiment (`candidate=real_clock`, `arm` param). `WP_FEATURES` and `train_wp` are never touched.
- `src/flag_football_ep/cli.py`: `ffep experiment` dispatches `recency` and `real_clock` to their dedicated runner functions (the generic per-candidate loop can't express either), printing one line per half-life plus a winning verdict for recency, and a single synthetic/real_clock/delta/verdict line for real_clock. Also added a `skipped` echo line for candidate/model combinations `applies_to` excludes (previously silent).
- Ran both experiments against the real ingested corpus (`data/processed/plays.parquet`, regenerated in this worktree via `.venv/bin/ffep ingest` against the raw Hudl-absent/legacy/IFAF sources present here -- 21,437 plays, 247 games, matching `01.3-DATA-PROFILE.md` exactly). Results below.
- 41 new tests: `TestAddRecencyWeight` (14) + `make_ep_model_mutations` recency-column coverage (4) in `tests/test_features_mutations.py`; `TestPrepareWpDataRealClock` (10) in the same file; recency-candidate coverage (12) + real-clock-candidate coverage (11) in `tests/test_model_experiments.py`.

## Recency Candidate Verdict (Task 2)

Measured with `run_recency_candidate` against the real corpus, `model_prefix="ep"`, 246 LOGO folds (247 games minus `exclude_games_ep`).

| Arm | Pooled log-loss | Delta vs. control | Verdict |
|---|---|---|---|
| control (unweighted) | 1.029113 | -- | -- |
| half-life 60.0 days | 1.029113 | 0.000000 | rejected |
| half-life 180.0 days | 1.029113 | 0.000000 | rejected |
| half-life 365.0 days | 1.029113 | 0.000000 | rejected |
| half-life 730.0 days | 1.029113 | 0.000000 | rejected |

**Winner:** `recency_half_life_60.0` (`min()` over a full tie picks the first grid entry; all four arms are numerically identical). **Reading:** `game_date` is null for all 21,437 rows across every source in the real corpus (`01.3-DATA-PROFILE.md` section 2), so `add_recency_weight` assigns `RECENCY_NULL_DATE_WEIGHT = 1.0` to every row regardless of half-life -- `Total_W` is multiplied by a constant 1.0, so `Total_W_Scaled` and every downstream model fit are byte-for-byte identical to the control across all five arms. This is not a broken experiment; it is the correct, honest measurement of "recency weighting has no signal to work with in the current corpus," logged as five separate MLflow runs (`candidate=recency`, one per half-life plus control) in `ep_model_candidates`. All 246-fold LOGO fits ran for real; nothing was skipped or faked.

## Real-Clock Candidate Verdict (Task 3)

`.venv/bin/ffep experiment --candidate real_clock --model wp` against the real corpus raised a named `ExperimentError` rather than completing:

```
run_real_clock_experiment: not viable on this corpus -- the IFAF subset has 3191 row(s)
across 32 game(s), but drop_nulls() removes every row because the following
WP_TRAINING_COLUMNS entry/entries are null for every row in this subset: yards_to_go.
This is not a game_clock_ms/time-feature problem -- it is a pre-existing IFAF ingest
data-coverage gap unrelated to this candidate.
```

**Reading:** `01.3-DATA-PROFILE.md` section 5 confirms `game_clock_ms` is 100% populated for `ifaf` (3,191/3,191) -- the real-clock derivation itself is fully viable and is exercised end-to-end by `tests/test_features_mutations.py::TestPrepareWpDataRealClock` and `tests/test_model_experiments.py`'s real-clock candidate tests against a synthetic IFAF corpus (11 tests, including a live 2-arm MLflow-logging assertion). But on the *real* corpus, `yards_to_go` -- a plain `WP_FEATURES` column, unrelated to time -- is null for all 3,191 `ifaf` rows (confirmed directly: `plays.filter(pl.col("source")=="ifaf")["yards_to_go"].null_count()` = 3191/3191, i.e. 0% coverage; this number is not in `01.3-DATA-PROFILE.md`, which only profiled `game_clock_ms`/`half_seconds_remaining` coverage, not `yards_to_go`). `make_wp_model_mutations`'s `drop_nulls()` therefore reduces both arms to 0 rows before either can reach `run_logo`. Per the plan's own escape hatch ("do not fabricate a result... record that the experiment is not viable on the current corpus, say exactly which coverage number made it so"), this is recorded as an explicit, code-enforced not-viable finding rather than a fabricated log-loss comparison. The code path, tests, and MLflow logging are all in place and will produce a real comparison the moment `yards_to_go` is populated for IFAF rows (a separate, pre-existing `ingest/ifaf.py` data-coverage gap, out of this plan's scope to fix).

This finding is evidence for the REQ-S1-02/analyst-conversation blocker STATE.md tracks (real time data), but also surfaces a second, independent IFAF ingest gap (`yards_to_go`) worth flagging to whoever next touches `ingest/ifaf.py` or plans Phase 1.4's WP charts.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `run_real_clock_experiment` crashed with an unnamed sklearn error on a 0-row frame**
- **Found during:** Task 3, running `.venv/bin/ffep experiment --candidate real_clock --model wp` against the real corpus
- **Issue:** `yards_to_go` is null for 100% of the real corpus's `ifaf` rows (3,191/3,191). `make_wp_model_mutations(...).drop_nulls()` therefore silently produced a 0-row frame for both arms, which was then handed to `run_logo`; `sklearn.model_selection.LeaveOneGroupOut.get_n_splits` raised a raw `ValueError: Found array with 0 sample(s)... while a minimum of 1 is required` deep inside `check_array`, with no indication of which column or which corpus characteristic caused it.
- **Fix:** Added an explicit guard in `run_real_clock_experiment` between frame-building and `run_logo`: when either arm's post-`drop_nulls()` frame is empty, compute which `WP_TRAINING_COLUMNS` entries were 100% null in the pre-`drop_nulls()` frame and raise a named `ExperimentError` citing them, explicitly distinguishing "not a game_clock_ms/time-feature problem" from the actual cause.
- **Files modified:** `src/flag_football_ep/model/experiments.py`
- **Verification:** `.venv/bin/ffep experiment --candidate real_clock --model wp` now exits with the named, diagnosable error shown above instead of an sklearn traceback; `tests/test_model_experiments.py::test_run_real_clock_experiment_raises_named_when_a_wp_column_is_entirely_null` reproduces this on a synthetic corpus with `yards_to_go` forced null.
- **Committed in:** `413a899` (Task 3)

**2. [Rule 2 - Missing critical] CLI silently skipped candidates that don't apply to the requested model**
- **Found during:** Task 2, wiring the `recency` dispatch branch into `ffep experiment`'s existing per-(model, candidate) loop
- **Issue:** The pre-existing loop's `if prefix not in spec.applies_to: continue` silently skipped a candidate/model combination with no output -- for `recency` (EP-only) and `real_clock` (WP-only), running `--model both --candidate all` would silently produce no line at all for the non-applicable side, which is indistinguishable from a bug that ran nothing.
- **Fix:** Added `typer.echo(f"{name} ({prefix}): skipped -- does not apply to {prefix!r}")` before the `continue`.
- **Files modified:** `src/flag_football_ep/cli.py`
- **Verification:** Manual CLI run; existing CLI tests (`test_experiment_cli_*`) still pass unmodified since none assert on stdout absence for skipped combinations.
- **Committed in:** `f791e3c` (Task 2)
