# Phase 1.3 Plan 04: Leave-One-Game-Out Evaluation Summary

**Replaced the play-level 80/20 `train_test_split` in EP/WP training with a leave-one-game-out (LOGO) measurement loop over `game_id`, a grouped inner CV for hyperopt tuning, and a single refit-on-all-games production model.**

**LOGO wall-clock measurement (RESEARCH Open Question 2):** `data/processed/plays.parquet` is not present in this worktree (only `.gitkeep`, same situation 01.3-01 documented), so the real corpus could not be measured directly. Instead, `run_logo` was timed against a synthetic corpus sized to match the real Hudl corpus's documented dimensions (PROJECT.md: "47 games / ~3,700 plays") -- 47 games, 3,713 rows, EP features/params, `Total_W_Scaled` weighting. Result: **47 sequential `xgb.XGBRegressor` fits complete in 12.91 seconds** (`logo_wall_seconds` as `run_logo` itself reports it). This is well within an acceptable range for a single `ffep train` invocation and does not, on this evidence, justify parallelization at the current corpus size -- confirming CONTEXT's "knowing the ~50+ fits cost" was an acceptable tradeoff. WP training (fewer features, no sample weights, `binary:logistic`) is expected to be faster per fit; not separately measured. A real-data re-measurement remains open for whenever `ffep ingest` has run in a worktree with real exports.

## Accomplishments

- `src/flag_football_ep/model/evaluate.py`: `run_logo` fits one `xgb.XGBRegressor` per held-out `game_id`, accumulates a complete, NaN-free out-of-fold prediction matrix, and raises `EvaluationError` naming missing columns or an undersized group count. Never recomputes `make_*_model_mutations` inside the fold loop.
- `src/flag_football_ep/model/hyperparams.py`: `LOGO_GROUP_COLUMN`, `GROUP_COLUMNS`, `EP_TRAINING_COLUMNS`/`WP_TRAINING_COLUMNS` (supersets of the frozen `*_SELECTED_COLUMNS`), `INNER_CV_FOLDS`.
- `src/flag_football_ep/model/train.py`: `_train` measures with `run_logo` (pooled out-of-fold log-loss is the reported `logo_mlogloss`/`logo_logloss` metric) and then fits one fresh production model on the whole frame -- the LOGO fold models are measurement-only and never logged. `_tune`'s inner CV scores every hyperopt trial against `GroupKFold(game_id)`, never a fixed play-level split, and never nests a full LOGO pass inside a trial.
- `params` logged to MLflow gain `cv_scheme="leave-one-game-out"`, `group_column`, `n_folds`, `logo_wall_seconds`; `test_size`/`random_state` are gone.
- `tests/test_model_evaluate.py` (12 tests): fold disjointness (via `LeaveOneGroupOut` directly, not trusting `run_logo`'s internals), out-of-fold coverage/shape/alignment, error naming, and the no-mutation-inside-a-fold guarantee.
- `tests/test_model_train.py`: provenance-param assertions retarget to `cv_scheme`/`n_folds`; metric-name tests retarget to `logo_mlogloss`/`logo_logloss` and assert the old names are gone; new tests assert `cv_scheme == "leave-one-game-out"`, the production refit sees every row (not an 80% split), and no hyperopt trial's `GroupKFold` train/eval partition shares a `game_id`.

## Decisions Made

- `run_logo` fits `xgb.XGBRegressor` (not `XGBClassifier`) per fold, matching the estimator class `_train`'s production refit already uses, so the LOGO-measured model family is exactly the model family that ships.
- The LOGO loop consumes the already-mutated frame's pre-computed weight column and never re-invokes the mutation stage per fold -- avoids `DegenerateWeightRange` false negatives/positives on small per-fold subsets, per RESEARCH's explicit anti-pattern warning.
- `_tune`'s inner CV fold count is `min(INNER_CV_FOLDS, n_distinct_games)` so small corpora (including the test suite's synthetic ones) never request more `GroupKFold` splits than there are groups.
- Real-corpus LOGO wall-clock measurement was not possible in this worktree (no ingested `plays.parquet`); substituted a size-matched synthetic proxy (47 games / 3,713 rows) and documented the result and its limitation explicitly, rather than skipping the measurement requirement silently.
