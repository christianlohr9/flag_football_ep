<objective>
Build the feature-candidate experiment harness and run the first two REQ-S1-09 candidates —
`half` and the competition-level/gender covariate — each as a control-versus-candidate
leave-one-game-out comparison whose verdict is recorded in MLflow.

Purpose: REQ-S1-09 requires each feature candidate to be re-tested on grouped CV with a
documented outcome. CONTEXT §"Feature re-tests & training-data mix" locks the adoption
criterion (mean pooled LOGO log-loss improves over the current feature set), requires every
candidate experiment to be logged in MLflow with its verdict, and specifies the competition
covariate as a categorical tier from maintained reference data, one-hot encoded — explicitly
"not source-as-proxy".

Output: `model/experiments.py`, `add_competition_tier_features` in `mutations.py`,
`ffep experiment`, and the two candidates' logged verdicts.
</objective>

**The control arm must be the real current feature set.** CONTEXT's adoption criterion is
"mean pooled LOGO log-loss improves over the current feature set" — so every candidate run
measures two arms on the *same* frame, same folds, same hyperparameters: control =
`EP_FEATURES`/`WP_FEATURES` as they stand, candidate = control plus the candidate columns. A
candidate that changes the row set (by introducing nulls) is not comparable; see Task 2's
handling.

**Do not re-test `Total_W_Scaled`.** CONTEXT §"Existing EP weighting": the drive-score-distance
x score-differential weighting stays "an untouched given — not re-tested".

**`competition` is not in `GROUP_COLUMNS`.** The tier join needs `(source, competition)`, so the
one-hot columns must be built before `make_*_model_mutations`'s `.select(...)` drops
non-selected columns — see Task 2.
