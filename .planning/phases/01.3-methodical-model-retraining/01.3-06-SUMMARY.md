# Phase 1.3 Plan 06: Empirical PAT Baselines and Break-Even Chart Summary

**Replaced the notebook's hard-coded 50%/92% PAT success rates with corpus-estimated rates (measured 49.0%/41.2% on the current dataset) carrying attempt counts and Clopper-Pearson confidence intervals, plus a reusable `ffep pat-breakeven` decision chart.**

## Performance

- **Duration:** ~50 min
- **Completed:** 2026-08-19
- **Tasks:** 3
- **Files modified/created:** 12

## Accomplishments

- `estimate_pat_baselines`/`PatBaselines` in `features/mutations.py` compute the pooled 1-pt
  and 2-pt PAT success rates from the full canonical corpus, each with its attempt count and
  a `scipy.stats.binomtest(...).proportion_ci()` confidence interval.
- `add_ep_variables` now requires `pat_baselines` as an explicit keyword argument (no
  default, no production fallback); `score_plays` estimates it once from the full input frame
  before scoring, and a corpus with zero PAT attempts of either type fails loudly with
  `InsufficientPatAttempts` naming the type and count.
- A reusable `charts/pat_breakeven.py` module renders the 1-pt-vs-2-pt expected-points chart
  (headless, `Agg` backend) and writes it to PNG with a write-once overwrite guard; `ffep
  pat-breakeven` wires it to the CLI, echoing both rates with their attempt counts and CIs.
- `docs/pipeline.md`'s "PAT baselines are hard-coded" limitation bullet is rewritten to
  describe the current empirical behaviour, citing the measured pooled rates as
  corpus-dependent.
- Verified against the real canonical dataset: 1-pt 49.0% (n=251), 2-pt 41.2% (n=102),
  matching `01.3-DATA-PROFILE.md`'s §"PAT attempt counts" table exactly.

## Decisions Made

- Used the exact same `down == 0` / `yards_to_go <= 5` (1-pt) vs `> 5` (2-pt) predicates the
  existing failed-PAT `epa` branches already used, so the estimator and the arithmetic that
  consumes it never disagree about what counts as a "1-pt attempt".
- Kept `PatBaselines.legacy_notebook()` for regression-test use only, enforced by a hygiene
  test scanning `src/flag_football_ep/` for any reference outside `features/mutations.py`.
- Chose Clopper-Pearson (`scipy.stats.binomtest(...).proportion_ci()`) over a normal
  approximation per RESEARCH's explicit warning about small counts and extreme rates in this
  corpus.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `test_model_score.py`'s `_training_corpus` fixture had zero PAT attempts**
- **Found during:** Task 1 verification (`pytest tests/test_model_score.py`)
- **Issue:** `canonical_plays_with_scores`'s synthetic corpus cycles `down` 1..4 and never
  produces a `down == 0` row, so every `score_plays` test in `test_model_score.py` hit
  `InsufficientPatAttempts` once `score_plays` started estimating baselines from the full
  input frame (new behaviour this plan adds, per its own `<behavior>` spec).
- **Fix:** Overrode `down`/`yards_to_go`/`one_point_conv_success`/`two_point_conv_success`
  for two plays per game (a 1-pt and a 2-pt PAT try, alternating success/failure by game
  index) in `_training_corpus`, without touching the shared `testing.py` factory used by
  other test modules.
- **Files modified:** tests/test_model_score.py
- **Verification:** `pytest tests/test_model_score.py -q` passes (all 33 tests)
- **Committed in:** 388a781 (Task 1 commit)

**2. [Rule 3 - Blocking] `test_cli_run.py`'s Hudl PAT fixture had zero 2-pt attempts**
- **Found during:** Task 1 verification (`pytest tests/test_cli_run.py`)
- **Issue:** `_write_drive_game`'s single PAT-play template (`DIST=0`, `YARD LN=5`) always
  produces a 1-pt attempt (`yardline_50 == 45` -> `one_point_conv_success`); no game in the
  fixture ever produced a `two_point_conv_success` row, so `estimate_pat_baselines` always
  raised `InsufficientPatAttempts` for the 2-pt type once wired into `score_plays`.
- **Fix:** `_write_drive_game` now alternates PAT type per "score" drive (1-pt: `DIST=3`,
  `YARD LN=5`; 2-pt: `DIST=8`, `YARD LN=10`, both still `RESULT=Good`). This changed the
  offense's point total per game (some scores are now 8 points instead of a fixed 7), so
  `_write_training_tree`'s `final_scores.csv` generation was updated (new
  `_expected_offense_points` helper mirroring the same alternation) to keep
  `score_reconstruction` validation passing — the games were quarantining on a score mismatch
  before this fix.
- **Files modified:** tests/test_cli_run.py
- **Verification:** `pytest tests/test_cli_run.py -q` passes (all 20 tests); full suite passes
- **Committed in:** 388a781 (Task 1 commit)
