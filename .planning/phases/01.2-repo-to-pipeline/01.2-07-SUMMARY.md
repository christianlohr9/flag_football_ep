### Auto-fixed Issues

**1. [Rule 3 - Blocking] Fixed `cfg.paths.raw` AttributeError blocking the live verification run**
- **Found during:** Task 3 (attempting `uv run ffep fetch-ifaf --tournament ffwc26-women`)
- **Issue:** `cli.py`'s `fetch_sportapp`/`fetch_ifaf` commands referenced `cfg.paths.raw / "sportapp"` and `cfg.paths.raw / "ifaf"`; the `Paths` dataclass (from plan 03) has no `raw` attribute, only `raw_sportapp`/`raw_ifaf`/etc. Both CLI commands crashed with `AttributeError` before issuing a single request — this is not in this plan's `files_modified` list, but it directly blocked the task's mandated action.
- **Fix:** Changed both lines to `cfg.paths.raw_sportapp` and `cfg.paths.raw_ifaf`.
- **Files modified:** `src/flag_football_ep/cli.py`
- **Verification:** `uv run ffep fetch-ifaf --tournament ffwc26-women` ran to completion after the fix; full test suite (`uv run pytest tests/ -q`) still green.
- **Committed in:** `c80ad8e`

**2. [Rule 1 - Bug] Fixed `/events` pagination silently reading every page as empty**
- **Found during:** Task 3, live run (the fetched `events_*.json` files were all `[]` — 2 bytes — instead of real content)
- **Issue:** `_fetch_events` in `fetch/ifaf.py` only checked `page.get("items", [])` as a non-list fallback. Manual verification against the live endpoint (`GET /games/{id}/events?includeReverted=false&limit=500&offset=0`) showed the real shape is `{"events": [...], "total": N, "hasMore": bool}` — no `items` key at all. Every page was read as an empty list, so pagination stopped after one call and every game's events file was written as `[]`.
- **Fix:** Added `_extract_events_page`, checking `events`/`items`/`data` in priority order for a list-valued key.
- **Files modified:** `src/flag_football_ep/fetch/ifaf.py`, `tests/test_fetch_ifaf.py` (added `test_events_pagination_handles_real_events_wrapper_shape` regression test)
- **Verification:** Re-ran the live discovery after the fix; `events_*.json` files for the 42 games with recorded events now contain real event arrays (e.g. `POSSESSION_CHANGE`, `DOWN_UPDATE` records with `sequenceNumber`/timestamps). Full test suite green.
- **Committed in:** `c80ad8e`

## Live cpx.studio Discovery Run (Task 3 findings)

**Command:** `uv run ffep fetch-ifaf --tournament ffwc26-women` (against `https://us.cpx.studio/v1`, no `.env`/`CPX_API_KEY` set)

**Outcome: success.** No 401/403, no 429, no unreachable host.

- **Auth:** every request (tournament metadata, teams, games list, unified-plays, events — 3 discovery + 96 per-game requests) succeeded with `api_key=None` and no `Authorization` header. `CPX_API_KEY` was not needed for any endpoint exercised. Recommend keeping it optional per the existing `.env.example` note; if the API later requires auth for other tournaments this fetch code already supports it (`Authorization: Bearer` header, redacted from all output).
- **Rate limits:** no `429` or throttling observed across ~99 sequential requests (3 discovery + 48 unified-plays + 48 events, each already paginated once since every game's event count came back under the default `limit=500` in a single page).
- **Games:** `/games` returned **96 games total**; **48 matched** `tournamentId == "ffwc26-women"` (the `/games` payload is a flat top-level list of game objects, each carrying a `tournamentId` field — the `tournament`/`tournamentSlug` fallback keys in `_TOURNAMENT_MATCH_KEYS` were not needed for this tournament but are kept for robustness against other tournaments' payload shapes).
- **Empty games:** 6 of the 48 matched games (all involving "Nigeria" — vs. Spain, USA, Australia, Italy, France, Brazil) have `status: "FINAL"` but return a genuinely empty `unified-plays` array and `events: []` (verified directly with a manual `requests.get`, not a fetch bug — real 200-with-empty-body responses). Likely forfeits/no-shows; plan 12's ingest should treat these as valid FINAL games with zero recorded plays, not as fetch failures.
- **`unified-plays` structure** (confirmed against CONTEXT.md's prediction, with the exact keys observed):
  - `context`: `gameClockMs` (int, ms — e.g. `1200000` for a fresh 20-min half; this is **real elapsed-clock data**, not synthetic), `half`, `down`, `ballOn`, `possessionTeamId`, `score: {home, away}`
  - **No `distance`/`yardsToGo` field inside `context`** — down/distance-to-go is not directly present in `unified-plays`; only `down` and `ballOn` (field position). This is a gap CONTEXT.md's field list did not flag and plan 12 needs to account for when mapping to the canonical `yards_to_go` column (it may need to be inferred, taken from the parallel `games.json`'s `currentContext.yardsToGo` per-game live-state field instead, or left null for this source).
  - `sequence`: list of action steps (`PASS`, `COMPLETE`, `TOUCHDOWN`, `FLAG_PULL`, etc.) each with `player`/`playerId`/`intendedReceiverId`
  - `outcome`: `type`, `scoringPlay` (bool), `turnover` (bool), `pointsScored` (present on scoring plays)
  - `description`: human-readable `kind`/`label`/`detail`/`text` plus `from`/`to` player objects (`name`, `number`, `teamId`, `photoUrl`) — real player names, same PII class as Hudl's charted names
  - Additional top-level fields beyond CONTEXT.md's list: `penalty` (bool), `penaltyCount` (int), `players` (role-keyed jersey numbers, e.g. `receiver.number`), `sources.capturedPlayId`, `corrected`, `createdAt`/`updatedAt`, `id`
- **`events` structure** (the bug fix's discovery): `{"events": [...], "total": N, "hasMore": bool}` — each event has `gameId`, `eventType` (e.g. `POSSESSION_CHANGE`, `DOWN_UPDATE`), `sequenceNumber`, `recordedByUserId`/`recordedByRole`, `clientTimestamp`/`serverTimestamp`, `payload` (event-type-specific), `reverted` (bool), `id`. This is a lower-level raw event log distinct from `unified-plays`'s already-summarized per-play view — plan 12 should decide whether `events` is needed at all for EP/WP purposes, since `unified-plays` already carries down/distance/score/clock context per play.
- **`games.json` shape:** flat top-level list (not `{data: [...]}`  or similar); each game object carries `homeTeam`/`awayTeam` (`id`, `name`, `color`), `currentScore`, `currentContext` (live-state snapshot including `yardsToGo` — the field missing from `unified-plays`), `status`, `date`, `location`.
