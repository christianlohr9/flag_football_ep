## Accomplishments
- `ifaf._play_sort_key` no longer raises `TypeError` on a null, absent, or non-int `playNumber`, or a non-dict play entry -- it now returns a uniform `tuple[int, int, int]` with usable int values ranked ahead of everything else
- `ifaf.ingest_snapshots` wraps the entire flatten-through-conform per-game chain in a `try/except (TypeError, AttributeError, ValueError, KeyError, pl.exceptions.PolarsError)`, mirroring `sportapp.ingest_snapshots`'s existing containment pattern exactly, including a new `_empty_canonical_frame()` helper
- `UnmappedTeamError` still propagates uncaught (T-1.2-15) -- confirmed by a new regression test
- `pipeline._ingest_ifaf`'s last-resort `except Exception` notice now says explicitly "source-level failure, all ifaf games dropped from this run" instead of reading like an ordinary per-game notice
- New integration test proves a real `run_ingest(["ifaf"])` over a directory containing one malformed-playNumber game still ingests the healthy game
- `docs/pipeline.md`'s "Per-file containment" paragraph now covers sportapp.fi and IFAF, not just Hudl

## Decisions Made
- `_play_sort_key` uses a group-ranked 3-tuple instead of trying to make `None`/`int` comparable directly -- eliminates the type-mismatch root cause rather than patching around it with a try/except at the sort call site.
- Kept `pipeline._ingest_ifaf`'s `except Exception` net rather than narrowing or removing it, since directory-level/meta-loading failures are still a real (if rare) whole-source failure mode distinct from the now-contained per-game failures.
