## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| canonical Parquet → model fit | validated local data; the trust question is provenance, not injection |
| training run → mlruns/ and models/ | artifacts written to the local filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.2-07 | Repudiation | silent `ep_model.pkl` overwrite destroying the provenance of a deployed model | mitigate | every run gets its own MLflow run directory with params, metrics and artifact; the optional pkl export is date-and-hash suffixed and raises rather than overwriting; a grep gate asserts no `pickle.dump` to a fixed name in `train.py` |
| T-1.2-11 | Repudiation | inability to tell which data produced which model | mitigate | `training_data_sha256`, `n_plays` and the excluded game ids are logged as run params |
| T-1.2-29 | Denial of Service | a 100-trial hyperopt search running on every train, breaking the phase-1.4 ten-minute chain | mitigate | tuning is opt-in via `--tune` with `--max-evals`, default off, and the reason is recorded in code |
| T-1.2-08 | Elevation of Privilege | pickle artifacts being loaded from arbitrary paths later | transfer | mitigated in plan 15, which resolves models from the configured MLflow store rather than from a caller-supplied pickle path |
</threat_model>
