<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `docs/data-contract.schema.json` → validator | contract data drives validation logic; a malformed or version-bumped contract must not crash the pipeline silently |
| hand-edited reference CSVs → pipeline | operator-typed scores and team mappings become the ground truth for quarantine decisions |
| Hudl export headers → ingest | untrusted, varying-shape CSV headers cross into typed processing here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.2-03 | Tampering | export header shape (12 to 45 columns observed) | mitigate | `validate_header` fails hard on missing core columns, materializes absent optional columns as typed nulls, and drops unknown columns with a recorded notice — mutation code never has to defend against a missing core column |
| T-1.2-14 | Tampering | hand-edited reference CSVs (typo in a score, duplicate game_id) | mitigate | loaders declare explicit dtypes and raise `ValueError` on duplicate keys and on `half2_first_play < 2`; nothing is coerced silently |
| T-1.2-15 | Spoofing | unmapped or ambiguous team labels merging two teams into one canonical code | mitigate | `map_teams` raises `UnmappedTeamError` listing every unmapped label; an empty mapping never falls through to pass-through behaviour |
| T-1.2-16 | Repudiation | post-ratification contract bump silently changing validation semantics | mitigate | major-version mismatch raises `ContractVersionError`; a minor bump warns with both versions so the run log records which contract validated the data |
</threat_model>
