# Phase 01.2 Plan 19: Scope EP/WP fills and shifts to game_id Summary

**Closed WR-04 by scoping the last four unscoped `backward_fill()`/`shift(-1)` calls in `add_ep_variables`/`add_wp_variables` to `.over("game_id")`, backed by four new cross-game-leakage regression tests.**

## Accomplishments
- `add_ep_variables`'s `ep`/`tmp_posteam` backward-fills and `home_ep_after` shift are now `.over("game_id")`-scoped, matching the module's documented no-cross-game-leakage invariant
- `add_wp_variables`'s `wp`/`tmp_posteam` backward-fills and `home_wp_after` shift are now `.over("game_id")`-scoped
- Every `backward_fill()` and `shift(-1)` call in `features/mutations.py` is now `.over("game_id")`-scoped (verified by grep: 8 scoped `backward_fill().over("game_id")` occurrences, zero unscoped `backward_fill()` or `shift(-1)`)
- Four new tests in `tests/test_features_mutations.py` prove the scoping is load-bearing: each fails when the `.over("game_id")` is removed (verified locally by reverting, running, and restoring — not committed)

## Decisions Made
- Left `half_end`/`game_end` at their default `0` on every row in the new two-game leakage fixtures (including game A's "last" row), instead of making that row a genuine `_mark_half_end`-derived game-end row. The module nulls `ep`/`epa` at `half_end==1 & half==1` and at `game_end==1`, and nulls `wpa`/overrides `home_wp` at `game_end==1` — if game A's boundary row carried a real `game_end=1` flag, those branches would force the assertion columns to null regardless of whether the backward_fill/shift(-1) scoping fix is present, making the test pass even against unscoped code (a false negative). This is exactly the masking case flagged in the plan's task 2 action text. Verified: with `game_end=0` throughout, all four new tests fail cleanly against the unscoped implementation and pass against the scoped one.
- Reused `_minimal_ep_frame` (adding a `play_id` default) rather than building leakage tests on `canonical_plays_with_scores` + `prepare_ep_data`, because the canonical builder's `_mark_half_end` unconditionally derives `game_end=1` on every game's true last row — the same masking problem above, but without hand-frame control to avoid it. Added a parallel `_minimal_wp_frame`/`_MINIMAL_WP_ROW_DEFAULTS` helper for the WP-side tests since `_minimal_ep_frame` doesn't carry the WP-specific columns (`wp`, `home_team_score`, `away_team_score`).
