# Phase 01.2 Plan 15: Model Scoring Summary

**`ffep score` resolves EP/WP models from the MLflow tracking store (never an arbitrary pickle path) and produces EPA/WPA via the ported `add_ep_variables`/`add_wp_variables` functions, preserving row count on plays with missing features.**

## Accomplishments

- `resolve_run`/`load_model` resolve and load XGBoost models exclusively from `config.paths.mlruns`, with caller-supplied run ids validated against a plain-hex pattern before ever reaching a `runs:/` uri -- no `pickle.load` of a caller path exists anywhere in the module.
- `score_plays` reuses `prepare_ep_data`/`prepare_wp_data` and `add_ep_variables`/`add_wp_variables` from `features/mutations.py` end to end -- no EPA/WPA formula is reimplemented in `score.py`.
- Rows with a null EP or WP feature are scored with null probabilities instead of being dropped: output row count always equals input row count, in the input's original order.
- Fixed a standalone-import gap: `model.score` now sets `MLFLOW_ALLOW_FILE_STORE=true` at its own import time, so `ffep score` (which never imports `model.train`) doesn't crash against mlflow>=3.15's local file-store deprecation guard.

## Decisions Made

- Used `mlflow.search_runs(..., output_format="list")` rather than the pandas-backed default output, keeping `score.py` free of any pandas dependency even though `mlflow.search_runs`'s default return type is a pandas DataFrame.
- Computed the EP down one-hot features (`down0`..`down4`) directly in `score.py` instead of calling `make_ep_model_mutations` (task 1's read_first analog), because that function also computes `Total_W_Scaled` sample weights (raising `DegenerateWeightRange` on low-variation input) and drops null rows -- both are training-only concerns that would violate scoring's row-count-preservation requirement.
- Row identity across the EP and WP scoring passes is tracked via an internal `_score_row_id` column (added once at the top of `score_plays`, dropped before return) rather than relying on join order, guaranteeing deterministic output order matching the input.

### Auto-fixed Issues

**1. [Rule 1 - Bug] `score.py` crashed when imported without `model.train` (missing `MLFLOW_ALLOW_FILE_STORE` guard)**
- **Found during:** manual verification after Task 2 GREEN, before final commit
- **Issue:** `train.py` (plan 01.2-13) sets `os.environ.setdefault("MLFLOW_ALLOW_FILE_STORE", "true")` at its own import time. `cli.py`'s `score` command only imports `flag_football_ep.model.score`, never `model.train` -- so when `ffep score` runs standalone (the normal path), the guard never executed and mlflow>=3.15 raised `MlflowException: The filesystem tracking backend ... is in maintenance mode ...` on the very first tracking call. Reproduced with a subprocess that imports only `model.score` with the env var unset -- confirmed the crash, then confirmed the fix resolves it.
- **Fix:** Added the same `os.environ.setdefault("MLFLOW_ALLOW_FILE_STORE", "true")` at the top of `score.py`, before any `mlflow` import, mirroring `train.py`'s pattern exactly.
- **Files modified:** `src/flag_football_ep/model/score.py`
- **Verification:** Subprocess test with `MLFLOW_ALLOW_FILE_STORE` unset, importing only `flag_football_ep.model.score`, followed by a real `mlflow.start_run()` against a temp file store -- succeeds after the fix (failed before).
- **Committed in:** `d41ec26`

**2. [Rule 3 - Blocking] Unused `numpy` import in the test file (ruff F401)**
- **Found during:** post-implementation `ruff check` sweep
- **Issue:** `tests/test_model_score.py` imported `numpy as np` but never used it directly (numpy access happens only through `.to_numpy()` on polars series).
- **Fix:** Removed the unused import.
- **Files modified:** `tests/test_model_score.py`
- **Verification:** `ruff check` clean on both changed files; full test suite still green.
- **Committed in:** `0b9901d`
