### Gaps Summary

Two Critical, independently-reproduced defects block full achievement of the phase goal:

1. **Scoring silently corrupts EPA/WPA/ep on mixed null-feature frames** (`model/score.py`). `_score_probabilities`'s complete/incomplete split-and-concat destroys chronological row order before the order-dependent `add_ep_variables`/`add_wp_variables` functions run; the final join restores *output* row order but not the already-corrupted derived values. Since IFAF rows always carry a null `yards_to_go` by design, any run that merges IFAF data (which REQ-S1-06 explicitly requires) will produce silently wrong EPA/WPA for games adjacent to those null rows. Neither `test_score_plays_preserves_row_count_with_null_feature_rows` nor `test_migration_equivalence.py` catches this — both were independently confirmed not to exercise the failure path.

2. **An entire ingest source can silently vanish from the canonical Parquet.** `hudl.ingest_dir` and `sportapp.ingest_snapshots` let realistic per-file/per-game data-quality exceptions (a non-numeric charted cell, a wrong delimiter) escape their intended per-file notice-collection design and propagate to `pipeline.py`'s blanket `except Exception`, which drops every game from that source for the run. The resulting `source_notices` are collected into `IngestResult.notices` but that list is never passed to `render_report` and never echoed by `cli.py`'s `ingest` command — so the operator gets zero signal (no report entry, no console line, no CLI output) that an entire source was dropped. This directly undermines "the ingest CLI ... emits a per-game validation report" (REQ-S1-05) as a completeness guarantee, and weakens the "merged into one canonical schema" claim (REQ-S1-06) for any run where this path triggers.

Both defects were found by `01.2-REVIEW.md` (Critical findings CR-01, CR-02, plus Warning WR-01) and were independently re-derived from the source code in this verification session (not merely trusted from the review narrative) — see the Evidence columns above for the exact lines and mechanisms confirmed.

Several additional Warning-level findings from the review (score zeroed on a game's first play, IFAF defensive 2-pt conversions mis-credited, cross-game leakage in EP/WP backward-fills, `play_type` vocabulary drift across sources) are real but lower-severity data-correctness issues; they are listed under Anti-Patterns for visibility but were not elevated to blocking gaps because they either affect a narrower slice of games (WR-02, WR-03) or a single non-critical column (WR-11), whereas CR-01/CR-02 threaten the pipeline's primary analytic output and validation-report completeness respectively — the two properties the phase goal names directly ("validated Parquet").

**Not treated as phase gaps (per task framing):** the unrotated sportapp.fi API key is a documented, user-deferred operator action recorded in STATE.md, not a code defect of this phase. Reference-data partial seeding (2 of 7 Hudl games) and legacy placeholder team codes (OPP/TM1/TM2) are documented user decisions, not gaps.
