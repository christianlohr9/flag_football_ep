## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `.venv` rebuilt on Python 3.12 to unblock `uv run`**
- **Found during:** Environment setup, before Task 1
- **Issue:** `uv run python -c "import polars"` failed — `pyarrow==17.0.0` has no prebuilt wheel for the auto-resolved Python 3.13.3 interpreter and its source build failed with `ModuleNotFoundError: No module named 'pkg_resources'` in the isolated build environment. This blocked every subsequent `uv run` command needed to write or verify the capture script.
- **Fix:** `rm -rf .venv && uv venv --python 3.12 && uv sync` — Python 3.12.12 was already available locally (via Homebrew) and every dependency, including `pyarrow`, resolved a prebuilt wheel.
- **Files modified:** none (`.venv/` is gitignored; no `pyproject.toml`/`uv.lock` changes)
- **Verification:** `uv run python -c "import polars as pl; print(pl.__version__)"` → `1.5.0`; full capture script then ran successfully
- **Committed in:** n/a (environment-only, no file changes to commit)

**2. [Rule 1 - Bug] Deterministic `label_distribution` key order in the manifest**
- **Found during:** Task 2 post-verification re-run (checking the "re-running yields an identical manifest apart from captured_at" acceptance criterion)
- **Issue:** `pl.Series.value_counts()` row order is not guaranteed stable across runs; a second script invocation produced a manifest with the same dict content but different JSON key order for `label_distribution`, which would look like unexplained drift to a naive text diff even though the acceptance criterion (parsed-value equality) still held.
- **Fix:** Sort `label_distribution` by key (numeric labels ascending, `"null"` bucket last) before returning the dict, so `json.dumps` always emits the same key order.
- **Files modified:** `scripts/capture_notebook_baseline.py`, `tests/fixtures/baseline_manifest.json` (regenerated)
- **Verification:** Ran the script twice in a row; the two manifests are byte-identical apart from the `captured_at` line (confirmed via `diff`)
- **Committed in:** `95cac34`
