## Decisions Made

- **WC24 disposition:** `re-derive-with-fallback`, user decision at the task 1 checkpoint (see "WC24 disposition" section above for the full rationale and numbers).
- **`source="legacy-sportapp"`, not `"sportapp"`, for the grandfathered rows** — keeps them distinguishable from freshly re-derived sportapp rows once the key is rotated and the re-derive path actually runs, and lets the pipeline apply warn-only validation specifically to this provenance-opaque batch.
- **Team-identity columns forced to `Utf8` via `schema_overrides`** when reading the legacy CSV — sportapp.fi team ids are numeric-looking strings ("11", "13"), and polars would otherwise infer them as integers, breaking the canonical `Utf8` contract and any string-equality comparison downstream.
- **`clean_sort` not ported** — the original's descending multi-game sort only made sense for a concatenated multi-game frame before per-game mutation; the new snapshot-first design processes one game at a time, already in the JSON's own chronological nesting order, so re-sorting was both unnecessary and (on inspection) backwards for a single game.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Added `sack` boolean and `yardline_50_simple` bin derivations**
- **Found during:** Task 2 and Task 3
- **Issue:** `canonical.CORE_COLUMNS` requires both `sack` and `yardline_50_simple` as non-nullable core columns, but neither the original `Python/fetch_sportappfi_api.py` pipeline nor the already-mutated WC24 CSV ever computed them. Without these, `conform_to_canonical` raises `MissingCanonicalColumns` for every sportapp-sourced row.
- **Fix:** Added `sack = (play_result == "sack")` (mirrors the existing `interception`/`complete_pass` derivation pattern already in `add_event_columns`) and `yardline_50_simple = (yardline_50 < 25 ? 0 : 1)` (the exact binning formula already used by Hudl's `helper_add_hudl_mutations.py`, so the feature means the same thing across sources) to both `add_event_columns`/`clean_yardage` (fresh path) and `read_mutated_sportapp_snapshot` (legacy path).
- **Files modified:** `src/flag_football_ep/ingest/sportapp.py`
- **Verification:** `test_ingest_snapshots_yardline_50_within_range`, `test_read_mutated_sportapp_snapshot_derives_sack_and_yardline_50_simple`
- **Committed in:** `751d31c`, `7789cf5`

**2. [Rule 1 - Bug] Fixed a mutation-order bug that would have broken `clean_yardage` if `map_teams` ran first**
- **Found during:** Task 2, while tracing the pipeline order
- **Issue:** `clean_yardage` compares raw `start_yard_line_team_half_id`/`end_yard_line_team_half_id` against `home_team`/`away_team`. If `map_teams` (which remaps `home_team`/`away_team`/`posteam`/`defteam` to canonical team codes) ran before `clean_yardage`, that comparison would silently never match once `home_team`/`away_team` were no longer raw sportapp ids, corrupting every `yardline_50` value.
- **Fix:** Ordered `clean_yardage` before `map_teams` in `ingest_snapshots`, with a comment explaining why the order is load-bearing.
- **Files modified:** `src/flag_football_ep/ingest/sportapp.py`
- **Verification:** `test_ingest_snapshots_yardline_50_within_range`, `test_ingest_snapshots_maps_team_labels_via_map_teams` (both pass; caught the bug locally before committing by tracing the pipeline manually against the fixture)
- **Committed in:** `751d31c`

**3. [Rule 1 - Bug] Preserved real nulls instead of porting a lossy `str(None)` cast**
- **Found during:** Task 2
- **Issue:** The original `convert_to_polars`'s `df['yards_to_go'].astype(str)` (pandas) turns every `None`/`NaN` into the literal string `"None"`/`"nan"`, which would make `clean_yardage`'s `.is_null()` branch on `yards_to_go` dead code.
- **Fix:** `flatten_plays` stringifies `yards_to_go`/`yards_to_go_after` per-value, keeping `None` as a real null (needed anyway since polars cannot infer a schema across an int/`"G"`-string mixed column without a consistent type).
- **Files modified:** `src/flag_football_ep/ingest/sportapp.py`
- **Verification:** covered indirectly by `test_flatten_plays_returns_one_row_per_play` and the full ingest chain tests passing without schema errors.
- **Committed in:** `751d31c`

**4. [Rule 3 - Blocking] Fixed `cli.py`'s `fetch-sportapp` default game-id resolution**
- **Found during:** Task 3, while executing the plan-mandated "attempt `ffep fetch-sportapp`" step
- **Issue:** `ids = list(cfg.reference.sportapp_games)` iterated `cfg.reference.sportapp_games`, which is a `Path` to the reference CSV, not a list of ids — `list(a_path_object)` raises `TypeError: 'PosixPath' object is not iterable`, so the command crashed before it could even reach the missing-API-key check that this task's re-derive-with-fallback logic depends on.
- **Fix:** Changed to `load_sportapp_games(cfg.reference.sportapp_games)["source_game_id"].to_list()`.
- **Files modified:** `src/flag_football_ep/cli.py`
- **Verification:** `uv run ffep fetch-sportapp` now fails at the intended point (`environment variable SPORTAPP_API_KEY is not set`); `tests/test_cli_smoke.py` and `tests/test_config.py` still pass (no regression).
- **Committed in:** `7789cf5`
