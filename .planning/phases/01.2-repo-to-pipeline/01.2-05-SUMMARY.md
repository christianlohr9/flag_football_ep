## Decisions Made

- Contract tolerance is major-version-only, per `.planning/phases/01.2-repo-to-pipeline/01.2-CONTEXT.md`'s decision that the validator must survive the pending analyst ratification bump.
- `core_columns`/`optional_columns` are built from each column's `presence` field rather than the `contract_model` shortcut list, cross-checked with a warning on disagreement, so a ratified contract that promotes an optional column to core changes validator behaviour automatically.
- Team-identity resolution never passes an unmapped label through: `map_teams` raises `UnmappedTeamError` even against an empty mapping frame, matching the T-1.2-15 threat mitigation.
- Partial seeding accepted per the plan's explicit "partial is fine" path: only AUT-vs-UKR and SLO-vs-ITA (both EC25, 2025-09-27) were placed and seeded, using the user-supplied `half2_first_play` values and final scores. Home team = charting-perspective team (TEAM1 in the filename), matching the contract's `filename_semantics`.
- Legacy `team_mapping` rows were added only for `posteam` labels that are unambiguous, well-known 3-letter country/federation codes already used elsewhere (AUT, CZE, ESP, FIN, FRA, GER, SUI) plus the two-letter `GB` expanded to the standard `GBR` federation code. The legacy dataset also contains `IRE`, `OPP`, `TM1` and `TM2` as distinct `posteam` values; these were deliberately left unmapped rather than guessed (`IRE` could be `IRE` or `IRL`; `OPP`/`TM1`/`TM2` are generic charting placeholders whose real team identity varies by game and cannot be resolved from the data alone). Any legacy row using one of these four labels will raise `UnmappedTeamError` when `map_teams` runs against it, which is the intended loud-failure behaviour until an operator supplies the correct mapping.
- Investigated the raw Hudl export's own `TEAM`/`OPP TEAM` columns during seeding and found they hold the charting account name (`AFVD`, the German federation's account) and a free-text competition label, not the actual competing teams — confirming the contract's design choice that team identity for ingest comes from the filename tokens (`TEAM1`/`TEAM2`), not from these raw columns. No mapping rows were added for `AFVD` since it plays no role in team-identity resolution for the two seeded games.
