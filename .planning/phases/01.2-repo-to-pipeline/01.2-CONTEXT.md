<domain>
## Phase Boundary

The analysis becomes a reproducible package-based pipeline: notebook and `Python/` helper logic moves into `src/flag_football_ep`, an ingest CLI turns raw exports into canonical, validated Parquet with a per-game validation report, and all sources share one canonical schema with raw files consolidated under `data/` (REQ-S1-04, REQ-S1-05, REQ-S1-06).

**Scope extension (folded todo):** The IFAF/cpx.studio WM-2026 API joins Hudl and sportapp.fi as a **third ingest source** in this phase. The canonical schema is designed against all three sources at once.

Methodology changes to the model (GroupKFold, calibration, feature re-tests, empirical PAT baselines) are **not** this phase — that is Phase 1.3. 1.2 ports training/scoring behavior with obvious fixes only, plus an MLflow tracking foundation.

<decisions>
## Implementation Decisions

### CLI shape & entry points
- **Command surface:** One installed CLI with subcommands — `ffep ingest`, `ffep fetch-sportapp`, `ffep fetch-ifaf`, `ffep train`, `ffep score`. Everything discoverable from one entry point.
- **Library:** Typer (new dependency, pulls in Click).
- **Chaining:** `ffep run` chains ingest → features → train → score with sensible defaults — rehearsal for the <10-minute goal in Phase 1.4 (report generation joins the chain there).
- **Configuration:** A checked-in config file (TOML/YAML — format is Claude's discretion) holds paths and settings (data/, models/, schema file location); secrets (sportapp.fi apikey, cpx.studio if needed) come only from environment / .env, never committed.

### Validation report & failure policy
- **Failure mode:** Quarantine — games failing validation are excluded from the canonical Parquet and listed prominently in the report; the run continues with valid games. Fix the export, re-run.
- **Final-score reference:** A small maintained CSV under `data/reference/` (same workflow as `data/half_boundaries.csv`) maps each game to its true final score; the score-reconstruction check validates against it.
- **Report form:** Console summary during the run + a per-run Markdown report written next to the Parquet — one section per game, pass/fail per check (downs 0–4, `yardline_50` in [0, 50], monotonic drive IDs, gapless play sequences, score reconstruction).
- **Legacy path:** The grandfathered `data_raw.csv` games (47) run through the same checks but **warn-only** — never quarantined, since they cannot be re-exported and are the bulk of training data.
- **Contract tolerance:** The validator consumes `docs/data-contract.schema.json` and must tolerate a contract version bump (ratification with the analyst is pending, tracked as a todo).

### data/ layout & source merge
- **Layout:** `data/raw/hudl/`, `data/raw/sportapp/`, `data/raw/ifaf/`, `data/raw/legacy/` for inputs; `data/processed/` for canonical Parquet; `data/reference/` for maintained files (half boundaries, final scores, roster, team mapping).
- **API strategy:** Snapshot first — `ffep fetch-*` downloads raw JSON into `data/raw/<source>/` once; ingest always reads from disk. Reproducible, offline, no silent upstream changes.
- **Merge model:** One canonical plays table with nullable extras — core columns (down, distance, yardline, result, score, teams, half) required for every source; rich Hudl charting fields and IFAF real game-clock nullable. Mirrors the contract's core-plus-optional model.
- **Team identity:** A maintained reference CSV maps each source-specific team label/ID (Hudl filename codes, sportapp names, cpx team UUIDs) to one canonical team code. Ingest fails loudly on unmapped teams.
- **IFAF/cpx.studio discovery (user-supplied endpoints):** `https://us.cpx.studio/v1/games` lists all games; `https://us.cpx.studio/v1/tournaments/ffwc26-women` (+ `/teams`) provides tournament metadata, teams, fields; per game: `/v1/games/{id}/unified-plays` (verified structure: context with gameClockMs/half/down/ballOn/possession/score, sequence, outcome, description) and `/v1/games/{id}/events?includeReverted=false&limit=500&offset=0`. `ffep fetch-ifaf` uses real discovery — no manual game list.
- **Player fields:** Stay free text as source-provided (plus cpx jersey number/playerId columns where present). Cross-source player mapping is deferred to Phase 1.4, decided on real report need.
- **Parquet shape:** Single `plays.parquet`, rebuilt atomically per ingest, with source/competition/season as ordinary filter columns; games metadata as a second small Parquet.
- **Cleanup:** Stray root files are sorted or deleted — live inputs move to their `data/raw|reference` home; derivable intermediates (e.g. `games_plays.csv`) are regenerated by the pipeline and deleted; `*_OLD` files and stray artifacts (`h`) deleted (git history preserves them).

### Notebook migration & model logic
- **Cut-line:** Port training/scoring with obvious fixes (e.g. no more silent `ep_model.pkl` overwrites) — NOT a methodological redo. `ffep train`/`ffep score` reproduce today's behavior modulo those fixes; all evaluation methodology lands in 1.3.
- **MLflow:** Foundation in 1.2, full use in 1.3. 1.2 wires MLflow as the training entry point's logging backend — local `mlruns/`, params + metrics + model artifact logged on every `ffep train`. 1.3 builds GroupKFold/calibration experiments on that foundation and satisfies REQ-S1-11 via the registry.
- **Package structure:** Pipeline-stage modules — `ingest/` (hudl, sportapp, ifaf, legacy), `validation`, `features`, `model` (train/score + MLflow), `cli`. `Python/` helpers are absorbed into their stage; the `Python/` directory is deleted afterward.
- **Notebooks:** Rewritten as thin demos that only import the package and visualize; the heavy logic-bearing notebooks are replaced, not archived.
- **Tests:** pytest for critical logic — unit tests for derivation rules (`drive_id` from ODK flips, `half` from boundary file, `posteam`/TEAM1 rule) and each validation check, plus a migration-equivalence test (package output == notebook output on `data_raw.csv`). No coverage targets.

### Claude's Discretion
- Config file format (TOML vs YAML) and exact structure.
- Exact file formats/naming of the reference CSVs (final scores, team mapping) — consistent with `data/half_boundaries.csv` style.
- Module-level API design, Typer command signatures, Markdown report layout.
- MLflow local setup details (experiment naming, artifact layout) as long as every `ffep train` run is logged.

Discovery endpoints resolved during discussion (see merge decisions). Open items that remain for research/planning: usage terms/rate limits, coverage of other tournaments.
