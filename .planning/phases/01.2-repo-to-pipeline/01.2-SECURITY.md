# Phase 01.2 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|----------------|
| PyPI → project environment | third-party packages enter the runtime via `uv add` | package code |
| shell → CLI | operator-supplied paths/options enter the process | CLI args |
| environment/.env → process | secrets enter the runtime here, and only here | API keys |
| filesystem `data/` → pipeline | operator-supplied raw exports, some containing player PII | raw exports |
| git repository → public/backup surfaces | anything committed leaves the operator's control permanently | committed files |
| external APIs (sportapp.fi, cpx.studio) → local filesystem | untrusted remote payloads written to disk | JSON snapshots |
| environment secrets → HTTP requests | API keys cross into network traffic/log output | API keys |
| source frames → canonical table | source-specific column values cross into shared schema | play data |
| MLflow artifact store → process | model artifacts deserialized into running process | pickled model |
| caller-supplied run ids → artifact uri | operator input interpolated into `runs:/` uri | run id string |
| test suite → operator's real data directories | tests must not clobber canonical dataset | test writes |
| per-play scoring flags → cumulative score chain | mis-credit propagates through whole game | score data |
| pipeline internals → operator | report/stdout are the only channels the operator learns what landed in `plays.parquet` | report text |
