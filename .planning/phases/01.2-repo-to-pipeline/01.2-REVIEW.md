# Phase 01.2: Code Review Report

**Reviewed:** 2026-08-17T15:47:55Z
**Depth:** standard
**Files Reviewed:** 48

## Summary

Reviewed the full notebook-to-package port: canonical schema, four ingest paths (hudl, legacy, sportapp, ifaf), fetch stage, feature mutations, EP/WP training/scoring, pipeline orchestration, validation, and the test suite. Claims verified against the installed polars 1.5.0 in the project venv (two suspected polars-semantics bugs were tested empirically before classification).

The port is largely careful and well-tested, but two Critical defects stand out: `score_plays` computes EPA/WPA on a frame whose chronological row order has been destroyed by the null-feature partitioning step (silent corruption of the pipeline's primary analytic output), and the hudl/sportapp ingest loops let per-file data-quality exceptions (strict casts, wrong delimiter) escape their per-file error handling and abort an entire source — whose loss is then effectively invisible because source-level notices are never rendered anywhere (WR-01). Several Warnings concern score-chain correctness (first-play scores zeroed, defensive 2-pt conversions credited to the offense) and cross-game leakage in the EP/WP variable derivations.

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: `score_plays` computes EPA/WPA on a chronologically scrambled frame

**File:** `src/flag_football_ep/model/score.py:175` (root cause), consumed at `score.py:211-217`
**Issue:** `_score_probabilities` splits the input into `complete` (no null features) and `incomplete` rows, then returns `pl.concat([complete, incomplete])` — every row with any null feature is moved to the tail of the frame. `add_ep_variables` / `add_wp_variables` are then called on this reordered frame, and both are order-dependent: they derive `home_ep_after`/`home_wp_after` via `shift(-1)` and fill `ep`/`wp`/`tmp_posteam` via `backward_fill()`. Whenever any row has a null feature, the "next play" used for EPA/WPA is the wrong row, and backward-fills pull values from unrelated plays. This is not an edge case: every ifaf row has null `yards_to_go` by design (module docstring of `ingest/ifaf.py`), so in a mixed corpus entire games are relocated to the tail and every game adjacent to a null-feature row gets corrupted `epa`/`wpa`/`ep` values. The final `join` on `_score_row_id` (score.py:226-231) restores *output row order* but not the already-corrupted derived values, so the corruption is silent. `test_score_plays_preserves_row_count_with_null_feature_rows` only asserts row count and null probabilities, so the suite does not catch this.
**Fix:**
```python
# in score_plays, after each _score_probabilities call, restore play order
ep_scored = _score_probabilities(ep_prepared, ep_model, EP_FEATURES, EP_PROB_LABELS)
ep_scored = ep_scored.sort(_ROW_ID_COLUMN)   # restore chronological order
ep_result = add_ep_variables(ep_scored)

wp_scored = _score_probabilities(wp_prepared, wp_model, WP_FEATURES, [WP_PROBABILITY_COLUMN])
wp_scored = wp_scored.sort(_ROW_ID_COLUMN)
wp_result = add_wp_variables(wp_scored)
```
(Alternatively, have `_score_probabilities` preserve order internally, e.g. compute predictions into a null-initialized column via the row id instead of filter/concat.) Add a regression test asserting `epa` for a row adjacent to a null-feature row equals the value computed on a fully-complete frame.

### CR-02: Per-file data-quality exceptions abort an entire ingest source

**File:** `src/flag_football_ep/ingest/hudl.py:407-411` (strict casts), `hudl.py:615-649` (`ingest_dir` catches only `FilenameError`/`MissingCoreColumnsError`), `hudl.py:201-207` (`WrongDelimiterError` uncaught by `ingest_dir`), `src/flag_football_ep/ingest/sportapp.py:504-506` (strict `yards_to_go` cast inside the per-game loop, uncaught by `ingest_snapshots`)
**Issue:** The hudl module's stated design is "everything data-quality related is collected into `IngestNotices`, never raised," and `check_column_domains` explicitly records a non-numeric `DN`/`DIST`/`YARD LN`/`PLAY #` cell as a notice. But two lines later, `derive_identity_columns` casts those same Utf8 columns with `cast(pl.Int32)` — strict by default — so the very value just recorded as a notice raises `InvalidOperationError`. `ingest_dir` does not catch it (nor `WrongDelimiterError` from `read_export`, nor `MissingCanonicalColumns` from `conform_to_canonical` — note this is a *different* class than the caught `MissingCoreColumnsError`), so the exception propagates to `pipeline._ingest_hudl`'s blanket `except Exception`, which drops **every** hudl game for the run with a single notice string. One malformed cell in one export therefore silently removes the whole hudl source from `plays.parquet` (and the notice is never surfaced — see WR-01), which corrupts any model trained from that run. The sportapp fresh-snapshot path has the same shape: a strict cast failure in `clean_yardage` escapes the per-game loop in `ingest_snapshots` and kills all fresh sportapp games.
**Fix:**
```python
# hudl.derive_identity_columns — non-strict casts, matching conform_to_canonical:
pl.col("DN").cast(pl.Int32, strict=False).alias("down"),
pl.col("DIST").cast(pl.Int32, strict=False).alias("yards_to_go"),
pl.col("YARD LN").cast(pl.Int32, strict=False).alias("yardline"),
pl.col("PLAY #").cast(pl.Int32, strict=False).alias("play_id"),

# hudl.ingest_dir — catch the per-file structural errors it documents:
except (MissingCoreColumnsError, WrongDelimiterError, MissingCanonicalColumns) as exc:
    ...

# sportapp.ingest_snapshots — wrap the per-game mutation chain in the same
# try/except pattern already used for load_snapshot/flatten_plays.
```

## Warnings

### WR-01: Source-level notices and skipped-file messages are never surfaced

**File:** `src/flag_football_ep/pipeline.py:413` (report gets `game_notices` only), `src/flag_football_ep/cli.py:47-49` (`ingest` never echoes `result.notices`), `src/flag_football_ep/validation/report.py:100-111` (per-game sections iterate `game_results` only)
**Issue:** `run_ingest` collects `notices` (source aborted, directory missing, legacy-sportapp loaded, hudl file skipped) but neither `cli.ingest` nor `render_report` ever displays them. Worse, `game_notices` entries for hudl files skipped with `df=None` (bad filename, missing core columns) key games that have no rows, so they never appear in `game_results` and are silently dropped from the report. Combined with CR-02, an entire source can vanish from a run with zero operator-visible signal.
**Fix:** Pass `notices` into `render_report` and add a "## Source notices" section; echo `result.notices` in `cli.ingest`; render `game_notices` keys that have no matching `game_results` entry under a "Skipped files" section.

### WR-02: A score on a game's first play is silently zeroed

**File:** `src/flag_football_ep/canonical.py:285-301`
**Issue:** In `add_score_columns`, the `pl.when(pl.col("play_id") == 1).then(pl.lit(0))` branch takes precedence over the scoring branch, so a touchdown (e.g. a kickoff-return TD — hudl charts `ODK == "K"` rows) or safety on play 1 contributes 0 points. The game's entire cumulative score, `score_differential`, and WP `Winner` label are then wrong, and `score_reconstruction` will FAIL against the reference score — quarantining a perfectly valid game for new-format sources. This is a ported notebook quirk of exactly the "silent logic bug" class the port's policy elsewhere fixed (cf. the `scoring_play` precedence fix documented in `add_scoring_play_team`).
**Fix:**
```python
pl.when((pl.col("play_id") == 1) & (pl.col("home_team") != pl.col("scoring_play_team")))
.then(pl.lit(0))
.when(pl.col("home_team") == pl.col("scoring_play_team"))
.then(points_value)
.when(pl.col("play_id") == 1)
.then(pl.lit(0))
.otherwise(pl.lit(None))
```
(i.e., check the scoring branch before, or in combination with, the play-1 zero seed; mirror for away.)

### WR-03: IFAF defensive 2-point conversions credited to the offense

**File:** `src/flag_football_ep/ingest/ifaf.py:68-72`, `ifaf.py:330-343`, `ifaf.py:355`
**Issue:** `_POINTS_TO_FLAG` only consults `outcome.turnover` for `pointsScored == 6`. A conversion attempt returned by the defense (`pointsScored == 2`, `turnover == True` — a real flag-football scoring event) sets `two_point_conv_success`, an *offensive* flag, while `defensive_two_point_conv` is hard-coded to 0 (line 355). `add_scoring_play_team(credit_defense=True)` then credits `posteam` with 2 points that belong to `defteam`, corrupting the score chain and tripping `score_reconstruction` for the whole game.
**Fix:** For `pointsScored == 2`, route on `turnover` the same way 6 points does:
```python
if pts_value == 2:
    flag_exprs["two_point_conv_success"] |= pts_matches & (~turnover)
    flag_exprs["defensive_two_point_conv"] |= pts_matches & turnover
```
and derive `defensive_two_point_conv` from the same expression map instead of `pl.lit(0)`.

### WR-04: `add_ep_variables`/`add_wp_variables` shift and backward_fill without `.over("game_id")`

**File:** `src/flag_football_ep/features/mutations.py:262-265` (`ep`/`tmp_posteam` backward_fill), `mutations.py:272` (`home_ep_after` shift(-1)), `mutations.py:419-421` (`wp` backward_fill), `mutations.py:442` (`home_wp_after` shift(-1))
**Issue:** On a multi-game frame (exactly what `score_plays` passes), the unscoped `backward_fill()` pulls `ep`/`wp`/`tmp_posteam` values across game boundaries into a game's trailing null rows, and `shift(-1)` reads the next game's first play. The `game_end`/`half_end` null-out steps mitigate the shift for exactly the boundary row, but the backward fills are not mitigated at all (a game with trailing null probabilities inherits the next game's values). This directly contradicts the module's own "no cross-game leakage / `.over('game_id')` invariant" docstring, which is enforced everywhere else in the file.
**Fix:** Scope all four operations: `.backward_fill().over("game_id")` and `.shift(-1).over("game_id")`.

### WR-05: `fetch_tournament` overwrites cached discovery snapshots with `null` on request failure

**File:** `src/flag_football_ep/fetch/ifaf.py:188-206`
**Issue:** `tournament_payload`/`teams_payload`/`games_payload` are written to disk unconditionally, even when `http_get_json` returned `None` (non-2xx, timeout, non-JSON). A transient network failure therefore clobbers a previously good `games.json`/`tournament_*.json` with the literal JSON `null`, and subsequent `ingest_snapshots` runs silently degrade to null home/away/competition metadata for every game. This is a data-loss regression path the per-game fetch explicitly avoids ("no partial file is left behind").
**Fix:** Skip the write when the payload is `None`:
```python
if tournament_payload is not None:
    _write_json(tournament_path, tournament_payload)
```
(likewise for teams and games; only append actually-written paths to `discovery_paths`).

### WR-06: IFAF events pagination terminates on `len(page) < limit`, ignoring `hasMore`

**File:** `src/flag_football_ep/fetch/ifaf.py:104-121`
**Issue:** The loop stops as soon as a page returns fewer than `limit` items. If the server caps page size below the requested `limit` (CLI default 500 — common API behavior, and the live-verified response shape includes an explicit `hasMore` flag the code ignores), the very first page satisfies `len(page_items) < limit` and the events snapshot is silently truncated to one page.
**Fix:** When the page is a dict carrying `hasMore`, use it as the primary termination signal; only fall back to the `len < limit` heuristic for bare-list responses. Also advance `offset` by `len(page_items)` rather than `limit` so a capped page size cannot skip records.

### WR-07: Tuned runs log a leaked "test" metric

**File:** `src/flag_football_ep/model/train.py:207-234`
**Issue:** With `tune=True`, the final model is refit on the *full* frame (`fit_X = model_data...`), and `metric_value` is then computed on `test_X` — a subset of the data the model was just fit on — but logged under the same `test_mlogloss`/`test_logloss` name as the genuinely held-out metric from untuned runs. Anyone comparing runs in MLflow will see systematically optimistic numbers for tuned runs without any marker that the evaluation set was inside the training data.
**Fix:** For tuned runs, either log the metric under a distinct name (e.g. `train_refit_logloss`) or log the best trial's held-out loss (`min(trial_losses)`) as the comparable test metric, and document the difference in `_log_run`.

### WR-08: WP `log_loss` call unguarded against a single-class test split

**File:** `src/flag_football_ep/model/train.py:232-234`
**Issue:** `labels = list(range(num_class)) if num_class else None` — the EP path is guarded against a rare class missing from the 20% split (the inline comment explains exactly this hazard), but WP (`num_class` absent) passes `labels=None`. If the random 80/20 split leaves only one class in `test_y` (plausible on the current small corpus), `log_loss` raises `ValueError` and the whole training run dies after the fit succeeded.
**Fix:** `labels = list(range(num_class)) if num_class else [0, 1]` (WP labels are defined as 0/1 by `make_wp_model_mutations`).

### WR-09: `.env` resolved from CWD while everything else is config-relative

**File:** `src/flag_football_ep/config.py:138`, `config.py:181`
**Issue:** `load_config`'s docstring promises "behavior is the same regardless of where `ffep` is invoked from," and all paths are resolved relative to the config file. But `load_dotenv()` is called with its default `Path(".env")` — CWD-relative — so `ffep --config /repo/ffep.toml` run from any other directory silently fails to load the project's secrets (or loads a *different* project's `.env`).
**Fix:** `load_dotenv(path.parent / ".env")` inside `load_config`.

### WR-10: IFAF `drive_id` starts at 0 when the first play lacks `possessionTeamId`

**File:** `src/flag_football_ep/ingest/ifaf.py:238-249`
**Issue:** `drive_id` starts at 0 and increments when `posteam_raw != prev_posteam_raw`. If the game's first play is missing `possessionTeamId` (a case the module explicitly tolerates via `_missing_possession`), `None != None` is False and the leading plays get `drive_id == 0`, which `monotonic_drive_ids` ("first drive_id … expected 1") then FAILs — quarantining the game for a parser artifact rather than a data problem. Consecutive missing-possession plays also never open a new drive even across a real possession change.
**Fix:** Seed the first play explicitly: `if play_id == 1 or posteam_raw != prev_posteam_raw: drive_id += 1` (using the play counter, not the possession comparison, for the first row).

### WR-11: `play_type` vocabulary diverges across sources in a canonical column

**File:** `src/flag_football_ep/ingest/sportapp.py:340-348` (emits `"rush"`), `src/flag_football_ep/ingest/hudl.py:308` and `ingest/legacy.py:199-201` (emit `"run"`)
**Issue:** The whole point of the canonical schema is that a column means the same thing across sources, yet `play_type` holds `"run"` for hudl/legacy rows and `"rush"` for sportapp rows (both fresh and grandfathered WC24). Any downstream filter (`play_type == "run"`) silently drops all sportapp run plays. This is a cross-source contract violation, not a per-source vocabulary choice — the raw vocabulary already lives in `result_raw`.
**Fix:** Normalize sportapp's `play_type` mapping to `"run"` (one literal change in `add_event_columns`), and add a domain check or test asserting the canonical `play_type` value set is identical across sources.

## Info

### IN-01: Operator-precedence hazard in `correct_posteam`

**File:** `src/flag_football_ep/ingest/sportapp.py:419-422`
**Issue:** `((pl.col("play_id")) == (pl.col("posteam_helper_2"))) & pl.col("def_touchdown") == 1` parses as `(bool_expr & def_touchdown) == 1`. Verified against polars 1.5.0: it happens to produce identical results for 0/1/null values — but this is the exact precedence-bug class `canonical.add_scoring_play_team`'s docstring documents as a fixed notebook bug.
**Fix:** Parenthesize: `... & (pl.col("def_touchdown") == 1)`.

### IN-02: `pl.when(down=0)` keyword style reintroduced in hudl after being deliberately removed in legacy

**File:** `src/flag_football_ep/ingest/hudl.py:511-517`
**Issue:** `ingest/legacy.py`'s docstring records replacing `pl.when(down=0)` with explicit predicates as "avoids a deprecated call style" — yet `derive_yards_gained_first_down` uses `pl.when(down=0)`, `pl.when(down=4, complete_pass=0)`.
**Fix:** Use explicit `pl.col(...) == ...` predicates for consistency and future-proofing.

### IN-03: Hyperopt search is unseeded; `"seed"` key in the space is dead

**File:** `src/flag_football_ep/model/hyperparams.py:91`, `src/flag_football_ep/model/train.py:290-323`
**Issue:** `HYPEROPT_SPACE` carries `"seed": 0` but `_objective` never reads it and `fmin` is called without `rstate`, so tuning results are irreproducible run-to-run despite the module's reproducibility posture (`random_state=42` everywhere else).
**Fix:** Pass `rstate=np.random.default_rng(0)` to `fmin` and drop the dead `"seed"` key (or feed it to `XGBClassifier`).

### IN-04: CWD-dependent `Path("src/...")` reads in tests

**File:** `tests/test_model_score.py:191`, `tests/test_model_score.py:290`, `tests/test_ingest_ifaf.py:463`
**Issue:** Three source-shape gate tests read `Path("src/flag_football_ep/...")` relative to the process CWD; running pytest from any directory other than the repo root makes them fail with `FileNotFoundError` (a false failure). Other tests use the `repo_root` fixture correctly.
**Fix:** Use the `repo_root` fixture (or `Path(__file__).parent.parent`) in all three.

### IN-05: Four different `IngestNotices` types share one name

**File:** `src/flag_football_ep/ingest/hudl.py:126`, `ingest/legacy.py:59`, `ingest/sportapp.py:68`, `ingest/ifaf.py:136`
**Issue:** `IngestNotices` is a dataclass with different fields in hudl/legacy/ifaf and a bare `list[str]` alias in sportapp. Cross-module imports of the wrong one type-check silently (it's just a name), and `pipeline.py` must remember which shape each source returns.
**Fix:** Either rename per-source (`HudlIngestNotices`, ...) or converge on a single shared notices type.

### IN-06: `ffep score --out` fails when the output directory does not exist

**File:** `src/flag_football_ep/cli.py:191-192`
**Issue:** `scored.write_parquet(out_path)` does not create `out_path.parent`; `run_ingest` creates its output directories, `score` does not — `--out new-dir/x.parquet` dies with `FileNotFoundError`.
**Fix:** `out_path.parent.mkdir(parents=True, exist_ok=True)` before the write.

### IN-07: Tournament metadata lookup not string-normalized

**File:** `src/flag_football_ep/ingest/ifaf.py:466` vs `ifaf.py:398`
**Issue:** `_load_tournaments_meta` keys the dict by `str(payload["id"])`, but the lookup uses the raw `game_entry.get("tournamentId")`. A numeric tournament id in the payload silently misses, degrading competition/season/gender to null with no notice.
**Fix:** `tournaments_meta.get(str(game_entry.get("tournamentId")), {})` (guarding `None`).

### IN-08: `Total_W_Scaled` zero-range is unguarded

**File:** `src/flag_football_ep/features/mutations.py:558-562`
**Issue:** `DegenerateWeightRange` guards `Drive_Score_Dist` and `score_differential` ranges, but the composite `Total_W` min-max scaling divides by `Total_W.max() - Total_W.min()` with no guard — a constant `Total_W` (possible when the two component weights are anti-correlated) silently produces the very NaN/inf weights the exception class exists to prevent.
**Fix:** Apply the same range check to `Total_W` before scaling.

### IN-09: `gapless_play_ids` can raise on null play_ids

**File:** `src/flag_football_ep/validation/checks.py:210-211`
**Issue:** `sorted(pid for pid, c in counts.items() if c > 1)` mixes `None` with ints if a game has duplicated null `play_id`s alongside duplicated integers — `sorted` raises `TypeError` and the whole validation gate dies instead of reporting the game. Similarly `set(ids)` with `None` never matches `expected`, silently counting nulls as "missing" of nothing.
**Fix:** Filter nulls first and report a null count explicitly (as `downs_range` does), e.g. `ids = [i for i in row["all_ids"] if i is not None]`.
