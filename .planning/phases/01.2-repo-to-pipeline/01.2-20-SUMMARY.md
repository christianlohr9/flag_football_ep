# Phase 01.2 Plan 20: Ingest containment (CR-02 containment half) Summary

**Non-strict pl.Int32 casts plus complete per-file/per-game exception containment in hudl.py and sportapp.py, and a null-safe gapless_play_ids, so no single malformed cell or structural error can vanish an entire ingest source.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3 completed
- **Files modified:** 6

## Accomplishments
- `hudl.derive_identity_columns`'s four `DN`/`DIST`/`YARD LN`/`PLAY #` casts are now `strict=False`; a non-numeric cell becomes a null reported by `check_column_domains`, not a crash.
- `hudl.ingest_dir`'s per-file except clause now covers `MissingCoreColumnsError`, `WrongDelimiterError`, `MissingCanonicalColumns`, and `pl.exceptions.PolarsError` (previously only the first), each recording the exception class name in the notice.
- `sportapp.clean_yardage`'s `yards_to_go`/`yards_to_go_after` casts are non-strict, and `ingest_snapshots`' whole per-game mutation chain (`_extract_players_from_summary` through `conform_to_canonical`) is now wrapped in a `try/except pl.exceptions.PolarsError` that skips only the failing game.
- `UnmappedTeamError` is deliberately excluded from every new catch (it is a plain `Exception`, not a `PolarsError`) in both ingest modules — verified by dedicated regression tests in both files.
- `validation.checks.gapless_play_ids` filters nulls before `sorted()`/`Counter()` run (previously `TypeError` on mixed `None`/`int` duplicates) and reports the null count as its own FAIL detail part.

## Decisions Made
- Kept the `PolarsError` catches as defense-in-depth per the plan's explicit interface notes — the non-strict casts already eliminate the specific failures documented in the plan's `<interfaces>` section, so the except clauses mainly guard against any remaining strict cast or schema error deeper in the derivation chain.
- `gapless_play_ids`'s null handling reports "null play_id (N row(s))" as a separate detail segment (matching `downs_range`'s existing null-reporting style) rather than trying to fold nulls into the missing-id or duplicate-id vocabulary, since a null is conceptually neither.
