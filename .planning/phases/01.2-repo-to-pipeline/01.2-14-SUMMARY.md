## Accomplishments

- `run_ingest` dispatches hudl/legacy/sportapp/ifaf through their own ingest entry points, loading the contract and all reference data exactly once per run, converging everything with a strict vertical-only concat, then running the shared validation gate (`run_checks` + `partition_games`).
- `plays.parquet` and `games.parquet` are written atomically (`.tmp` sibling + `os.replace`), so an interrupted or failing run never leaves the canonical dataset half-written; games.parquet is written before plays.parquet so a games-write failure can never touch a prior plays.parquet.
- `ffep ingest --source hudl` / `--strict` are wired end-to-end through the CLI, printing paths and counts and exiting non-zero on quarantine when `--strict` is set.
- The real ingest ran twice under operator review: first at 210 games / 17,736 plays (hudl empty by worktree design, sportapp/legacy-sportapp WC24 fallback, ifaf snapshots, legacy CSV minus the three placeholder-only games), approved as-is; then, after seeding `legacy,OPP,OPP` / `legacy,TM1,TM1` / `legacy,TM2,TM2` mapping rows, at 257 games / 21,437 plays with the full 47-game legacy corpus included.

## Decisions Made

- **OPP/TM1/TM2 kept as pseudo-canonical placeholders.** The operator explicitly chose to map these anonymized legacy opponent labels as their own canonical codes rather than resolving them to real teams (impossible from the available data) or excluding the affected games (would shrink the legacy corpus below what plan 01.2-16's migration-equivalence test expects, and below what the original notebook processed). Documented per the operator's instruction: OPP/TM1/TM2 are anonymized placeholders, not real teams, and the real opponent for each of these games is permanently unknown from the source data. This has no EP modelling impact since team identity is not a model feature.
- **First run's quarantines/warnings accepted as correctly-explained source-data characteristics**, not defects: the 10 IFAF quarantines are all `downs_range` failures caused by null `down` values on penalty/PAT plays (a real property of the IFAF feed, not a validation bug), and the 5 legacy-sportapp warnings are `monotonic_drive_ids`/`half_assigned` warnings on a warn-only source that never blocks ingestion.
