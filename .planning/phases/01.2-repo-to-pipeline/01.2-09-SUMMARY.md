# Phase 01.2 Plan 09: New-Format Hudl Ingest Summary

**Hudl export folder -> conformed canonical frames via exact-token RESULT grammar and the contract's TEAM1/ODK posteam rule, replacing the notebook's substring matching and first-drive-is-home heuristic**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-08-17
- **Tasks:** 3
- **Files modified:** 3 (2 created source files, 1 created test file)

## Accomplishments

- `parse_filename` handles both the primary ISO-date pattern and the year-only fallback (with collision ordinal preserved in `game_id` but stripped from `competition`), raising `FilenameError` naming both patterns on no match
- `read_export` reads `;`-delimited utf-8-sig exports with every column as Utf8, strips a BOM from the first column name, and raises `WrongDelimiterError` on a comma-delimited file instead of silently returning a single-column frame
- `ingest_file` validates the header and column domains against `docs/data-contract.schema.json` before any mutation runs, materializing missing optional columns and recording (never raising on) unknown columns and domain violations
- `parse_result_tokens` implements the contract's exact-token RESULT grammar (split on `", "`, case-sensitive membership) with zero `str.contains` calls anywhere in the module, fixing the documented `Incomplete`/`Complete` and `TD`/`Def TD` substring traps
- `derive_outcome_columns` derives `play_type`, `sack`, `interception`, `complete_pass`, `incomplete_pass`, `touchdown`, `def_touchdown`, `penalty`, `safety`, `no_good`, `fumble`, and the one/two-point conversion and defensive-two-point-conversion flags; an empty RESULT on a non-PAT play now yields `play_type = null` plus a notice instead of the legacy silent `"pass"` default
- `derive_posteam_defteam` implements the contract's TEAM1/ODK rule (`posteam = TEAM1` when `ODK == "O"`, else `TEAM2`; `home_team`/`away_team` = filename order), replacing the legacy "first-drive-is-home" heuristic for this path; `ODK == "K"` rows get `play_type = "kickoff"`
- `derive_drive_id` increments on an ODK O/D possession flip or after a drive-closing RESULT token (`TD`, `Def TD`, `Safety`, `Interception`, `Fumble`), even without a flip
- `derive_half` joins `half_boundaries` on the export filename, with a null `half` plus an explicit "no half boundary" notice when no matching row exists
- The scoring chain (`add_scoring_play_team(credit_defense=True)`, `add_score_columns`) is wired in, so defensive touchdowns/safeties correctly credit the defending team
- `ingest_file` finishes with `conform_to_canonical`, producing a frame whose columns exactly equal `CANONICAL_COLUMNS`
- `ingest_dir` ingests every `*.csv` in a directory, isolating a bad-filename or missing-core-column file (reported via `messages`, `df=None`) without aborting the rest of the run

## Decisions Made

- Reordered the pipeline internally so identity casts (`down`, `yards_to_go`, `yardline_50`) happen before RESULT-token/outcome derivation, since `derive_outcome_columns` depends on both columns for PAT and conversion logic. The plan's task-grouping order ("task 2: RESULT tokens" before "task 3: derivations") describes which task adds the code, not the runtime call order — documented explicitly in `ingest_file`'s docstring.
- `read_export`'s wrong-delimiter detection uses `df.width <= 1` unconditionally rather than gating on whether the raw header line contains `;`, since every real Hudl export has at least 8 columns — this is simpler, catches both semicolon-containing and comma-only malformed headers, and still satisfies the plan's behavior requirement.
- `team_mapping`/`half_boundaries` are optional (`None` default) on `ingest_file`/`ingest_dir` so lower-scope tests don't need full reference data; production use (via the `ffep` CLI in plan 14) will always supply both.

## Follow-up for the schema owner

`no_good`, `incomplete_pass` and `fumble` are computed by `derive_outcome_columns` but have no column in `canonical.CORE_COLUMNS` or `canonical.NULLABLE_EXTRAS`. Per the plan's explicit instruction, this plan does **not** add them to `NULLABLE_EXTRAS` — they are computed as intermediate columns and silently dropped by `conform_to_canonical`'s final `select()`, recorded in `ConformReport.dropped_unknown`. A future plan (or the schema owner) should decide whether these three flags deserve a canonical home, particularly `fumble` given its DEFERRED-ANALYST possession-change ambiguity.
