<objective>
Give the IFAF source the same per-game failure containment hudl and sportapp already have, so one malformed play cannot silently delete every IFAF game from a run.

Purpose: closes the single remaining blocking gap in `01.2-VERIFICATION.md` (Truth 5, `partial`) — independently reproduced there and in `01.2-REVIEW.md` WR-01. `ifaf._play_sort_key` is `(play.get("playNumber", index), index)` with no null/type safety, so a play with `"playNumber": null` raises `TypeError: '<' not supported between instances of 'NoneType' and 'int'` out of `sorted(...)` inside `flatten_unified_plays`. `ingest_snapshots`'s per-game loop only guards `load_snapshot` (catching `UnparseablePayload`); everything after it runs unguarded. `pipeline._ingest_ifaf` then catches that exception around the *whole* `ingest_ifaf_snapshots()` call, dropping all 32 real WM-2026 games for one bad row. Plan 20 fixed this exact failure shape for hudl/sportapp but its `files_modified` never listed `ifaf.py`.

Output: a null/type-safe sort key, per-game containment in `ingest_snapshots` mirroring `sportapp.ingest_snapshots`, an explicit whole-source-drop notice in `_ingest_ifaf`, regression tests at unit and `run_ingest` level, and a `docs/pipeline.md` containment paragraph that covers all three sources rather than just Hudl.

Requirement mapping: REQ-S1-05 (the per-game validation report is only trustworthy if a source cannot vanish from it) and REQ-S1-06 (IFAF is one of the three sources this phase must merge into the canonical dataset) are the substantive ones; REQ-S1-04 is touched only because the fix lives inside the migrated package (`src/flag_football_ep/ingest`, `src/flag_football_ep/pipeline.py`).
</objective>
