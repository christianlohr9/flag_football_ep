# Phase 01.2 Plan 23: Cross-Source Data-Correctness Gap Closure Summary

**Fixed IFAF defensive two-point conversion misrouting (WR-03) and unified the play_type vocabulary across hudl/legacy/sportapp/WC24 with a cross-source contract test (WR-11)**

## Accomplishments
- IFAF `pointsScored == 2` now splits on `outcome.turnover` exactly like the existing `pointsScored == 6` touchdown/def_touchdown split, so a defense-returned two-point conversion sets `defensive_two_point_conv` and its 2 points land on `defteam`'s cumulative score instead of the offense's — the score chain and `score_reconstruction` no longer drift for a whole IFAF game because of a parser artifact
- Added `canonical.PLAY_TYPE_VOCABULARY = {"run", "pass", "no_play", "qb_kneel", "extra_point", "kickoff"}` as the single cross-source definition of the `play_type` column's value set
- Normalized sportapp's own `"rush"` literal to the canonical `"run"` on both the fresh-ingest path (`add_event_columns`) and the grandfathered WC24 CSV path (`read_mutated_sportapp_snapshot`) — a downstream `play_type == "run"` filter now selects sportapp run plays too
- Added `tests/test_cross_source_vocabulary.py`, a contract test asserting every non-null `play_type` emitted by hudl and sportapp is a member of `PLAY_TYPE_VOCABULARY` and never `"rush"` — fails loudly if a future source invents its own synonym
