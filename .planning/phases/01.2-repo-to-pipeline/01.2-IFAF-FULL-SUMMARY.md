# Phase 01.2: IFAF Full Snapshot + Yardage/Yards-to-Go Derivation Summary

**Snapshotted all 96 cpx.studio games (both ffwc26-women and ffwc26-men) via two never-before-fetched endpoints with PII redaction, derived both yards_gained (65.0% coverage) and yards_to_go (100% coverage, from IFAF's own four-downs-to-midfield/four-downs-to-score rule) for accepted IFAF plays, and fixed a live-corpus data-quality regression per-game via a real-validation-suite-driven snapshot choice — unlocking genuine EP/WP model output for ~98-100% of IFAF rows, up from ~0%.**

## Performance

- **Tasks:** 5 initial (fetch layer, yardage derivation, ingest/score re-run, video marks, docs) + 2 follow-up (yards_to_go derivation, corpus-regression fix)
- **Files modified/created:** 12 (7 source/test files modified, 3 created, 2 docs created) — no new files in the follow-up round, only further edits to `ingest/ifaf.py`/its tests and the docs
- **Commits:** 6 production commits (see below) + this summary

## Accomplishments

- All 96 games (48 women + 48 men) snapshotted with `game_{id}.json`/`plays_{id}.json` added alongside the existing `unified-plays_{id}.json`/`events_{id}.json` — 389 files total, all PII-redacted at the fetch layer
- `yards_gained` derivation with explicit, tested priority rules (penalty > touchdown > safety > turnover-shaped > same-drive > null)
- `yards_to_go` derivation from IFAF's own four-downs-to-midfield/four-downs-to-goal rule — field position alone determines the line to gain; empirically validated against the events feed's own MIDDLE/GOAL marker (98.2% agreement for the simple per-play version chosen, vs. 74.3% for a "sticky" drive-persistent alternative that was tried and rejected on the evidence)
- `play_type` coverage raised via a sequence-derived fallback, using only already-contract-approved tokens
- **Real EP/WP model output unlocked for IFAF**: `ep`/`epa` non-null on 97.9% of accepted rows, `wp` on 100%, `wpa` on 99.0% — up from ~0% (structural, `yards_to_go` being a required EP_FEATURES column) before the `yards_to_go` derivation existed
- Discovered, quantified, and then **fixed** a live-corpus data-quality regression between the 2026-08-17 and 2026-09-06 snapshots (11 women's games had fewer plays and gained null `down` values) via a per-game "use whichever snapshot the real validation suite accepts" policy — women's-bracket acceptance restored to exactly 32/48, matching the original 2026-08-17 baseline
- Built a per-play video-mark table (5,522 plays, 62 games, 70% with a resolvable video URL); confirmed one sampled video is publicly reachable via HEAD request (no download)

## Decisions Made

- `yards_to_go` IS derivable from field position alone (IFAF's own four-downs-to-midfield/four-downs-to-goal rule) — reversing the initial-round finding that it was structurally unavailable. The initial finding was correct about the API's own `yardsToGo` field (still a hardcoded `10` everywhere), but wrong to conclude the *value* couldn't be derived from other already-available fields.
- Between a "sticky" (drive-persistent) and a "non-sticky" (per-play recompute) crossing rule, chose non-sticky based on a direct empirical comparison against the events feed's own `MIDDLE`/`GOAL` marker (98.2% vs. 74.3% agreement) — a live-data finding that IFAF's own engine does not persist a first-down-style achievement across a drive.
- The 2026-08-17/2026-09-06 corpus regression is fixed per-game by ingesting both candidate snapshots through the real `validation.checks.run_checks` suite and keeping whichever one the check suite accepts, rather than a blanket revert (which would have discarded 31 women's games' worth of otherwise-fine 2026-09-06 data and had no fallback at all for the men's tournament).
- `all_games`/`include_full` added as opt-in parameters defaulting to `False` so every existing test and caller of `fetch_tournament` is unaffected — new behavior is purely additive.
- `redact_pii` placed as a single choke point inside `_write_json` rather than at each call site, so no future endpoint addition can accidentally skip redaction.
- Video-marks table kept as a standalone artifact outside the canonical schema (it has no equivalent in `CANONICAL_COLUMNS` and isn't meant to feed the model — it's a film-review aid).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `all_games=True` never fetched the men's tournament's metadata**
- **Found during:** Task 3 (first `ffep score` run raised `UnmappedCompetitionError: (source='ifaf', competition=None)`)
- **Issue:** `fetch_tournament(all_games=True)` processed every game in `/games` regardless of `tournamentId`, but only ever fetched `/tournaments/{tournament}` for the single primary tournament argument — a men's-bracket game's `competition`/`season`/`gender` all resolved to `None`, which `add_competition_tier_features` rejects at score time rather than at fetch/ingest time.
- **Fix:** `fetch_tournament` now also fetches `tournament_{id}.json`/`_teams.json` for every other `tournamentId` present in the `/games` response when `all_games=True`.
- **Files modified:** `src/flag_football_ep/fetch/ifaf.py`, `tests/test_fetch_ifaf.py`
- **Verification:** new regression test (`test_all_games_true_also_fetches_other_tournament_metadata`); re-ran the live fetch for the men's tournament metadata, then re-ran `ffep ingest`/`ffep score` successfully with zero errors
- **Committed in:** `f00da49`

**2. [Rule 1 - Bug] `cum_max()` unsupported on Boolean in the installed Polars version**
- **Found during:** the follow-up `yards_to_go` work (first draft, the "sticky" version)
- **Issue:** `reached_midfield_signal.cum_max().over("drive_id")` raised `InvalidOperationError: cum_min operation not supported for dtype bool` in this project's pinned Polars version.
- **Fix:** cast to `Int8` before `cum_max()`, compare back to boolean (`> 0`). Moot in the final version (the sticky approach was abandoned on empirical grounds, not because of this bug), but fixed along the way since it blocked testing the sticky variant at all.
- **Files modified:** `src/flag_football_ep/ingest/ifaf.py` (superseded by the final non-sticky rewrite)
- **Verification:** full test suite passed with the sticky version before it was replaced
- **Committed in:** folded into `f956a9b` (the sticky version was never committed on its own)

## Issues Encountered

- The live corpus itself regressed in quality between the two snapshot dates (fewer plays, more null `down` values, on exactly 11 women's games) — not something this session's code could or should paper over silently. Fixed per-game via a validation-suite-driven snapshot choice (see Decisions Made); the underlying "why did the provider's data get worse" question is still open and documented for the provider.
- The initial-round conclusion that `yards_to_go` was structurally unavailable was corrected in the same session once the IFAF ruleset's own down structure was considered — a good example of an assumption (trusting only the API's own fields) being wrong until a domain-rule-based derivation was tried and empirically validated.
