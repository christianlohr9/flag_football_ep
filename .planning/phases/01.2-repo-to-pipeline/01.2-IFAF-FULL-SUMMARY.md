# Phase 01.2: IFAF Full Snapshot + Yardage Derivation Summary

**Snapshotted all 96 cpx.studio games (both ffwc26-women and ffwc26-men tournaments, not just women) via two never-before-fetched endpoints with PII redaction, derived yards_gained for 71% of accepted IFAF plays with a 97.8% cross-check agreement rate, and confirmed yards_to_go is structurally unavailable from this API (blocking real EP/WP scoring for the source, not just a cosmetic gap).**

## Performance

- **Tasks:** 5 (fetch layer, yardage derivation, ingest/score re-run, video marks, docs)
- **Files modified/created:** 12 (7 source/test files modified, 3 created, 2 docs created)
- **Commits:** 5 production commits (see below) + this summary

## Accomplishments

- All 96 games (48 women + 48 men) snapshotted with `game_{id}.json`/`plays_{id}.json` added alongside the existing `unified-plays_{id}.json`/`events_{id}.json` — 389 files total, all PII-redacted at the fetch layer
- `yards_gained` derivation with explicit, tested priority rules (penalty > touchdown > safety > turnover-shaped > same-drive > null) — 71.1% non-null coverage, 97.8% agreement against the new `/plays` endpoint's own `ballOn` where both sides have usable data
- `play_type` coverage raised from ~39.8% to 86.0% via a sequence-derived fallback, using only already-contract-approved tokens
- Confirmed, with new evidence (the events feed's `DISTANCE_CHANGE`), that `yards_to_go` is unavailable everywhere in this API — a structural (not cosmetic) blocker on real EP/WP scoring for IFAF
- Discovered and quantified a live-corpus data-quality regression between the 2026-08-17 and 2026-09-06 snapshots (11 women's games lost plays and gained null `down` values), explaining a drop in game-acceptance rate that is not caused by this session's code
- Built a per-play video-mark table (5,522 plays, 62 games, 70% with a resolvable video URL); confirmed one sampled video is publicly reachable via HEAD request (no download)

## Decisions Made

- Followed the plan's own instruction: `yards_to_go` stays null since no field in this API carries real per-play distance data (now confirmed for a third time, across a third field — `context`, `games.json`, and the `events` feed's `DISTANCE_CHANGE`)
- `all_games`/`include_full` added as opt-in parameters defaulting to `False` so every existing test and caller of `fetch_tournament` is unaffected — new behavior is purely additive
- `redact_pii` placed as a single choke point inside `_write_json` rather than at each call site, so no future endpoint addition can accidentally skip redaction
- Video-marks table kept as a standalone artifact outside the canonical schema (it has no equivalent in `CANONICAL_COLUMNS` and isn't meant to feed the model — it's a film-review aid)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `all_games=True` never fetched the men's tournament's metadata**
- **Found during:** Task 3 (first `ffep score` run raised `UnmappedCompetitionError: (source='ifaf', competition=None)`)
- **Issue:** `fetch_tournament(all_games=True)` processed every game in `/games` regardless of `tournamentId`, but only ever fetched `/tournaments/{tournament}` for the single primary tournament argument — a men's-bracket game's `competition`/`season`/`gender` all resolved to `None`, which `add_competition_tier_features` rejects at score time rather than at fetch/ingest time.
- **Fix:** `fetch_tournament` now also fetches `tournament_{id}.json`/`_teams.json` for every other `tournamentId` present in the `/games` response when `all_games=True`.
- **Files modified:** `src/flag_football_ep/fetch/ifaf.py`, `tests/test_fetch_ifaf.py`
- **Verification:** new regression test (`test_all_games_true_also_fetches_other_tournament_metadata`); re-ran the live fetch for the men's tournament metadata, then re-ran `ffep ingest`/`ffep score` successfully with zero errors
- **Committed in:** `f00da49`

**Impact on plan:** Necessary for `ffep score` to complete on the full both-tournaments corpus at all; no scope creep — the fix is scoped exactly to the gap it closes.

## Issues Encountered

- The live corpus itself regressed in quality between the two snapshot dates (see "Corpus data-quality regression" in the docs Nachtrag) — not something this session's code could or should paper over; documented and flagged as the top open question for the data provider.
- `ffep score`'s EPA coverage for IFAF stayed near-zero despite the yardage-derivation work, because EPA requires `yards_to_go` (a separate, structurally-unavailable field) as a model feature, not `yards_gained`. This is an honest, expected outcome given what the API exposes — not a bug in this session's derivation logic (verified: `ep`/`wp` are 0% non-null; the 5.1% non-null `epa` comes entirely from the conversion-attempt constant branches, which never reference `ep`).

None - no external service configuration required. `CPX_API_KEY` remains unset and unnecessary; every request in this session succeeded with no auth header.
