## Shared Patterns

### De-facto RESULT vocabulary (the thing the contract formalizes)
**Source:** `Python/helper_add_hudl_mutations.py` lines 49–93 (`make_hudl_mutations`)
**Apply to:** spec vocabulary section + schema `RESULT` tokens

```python
pl.when(pl.col('RESULT').str.contains("Rush")).then(pl.lit("run"))
.when(pl.col('RESULT').str.contains("Penalty")).then(pl.lit("no_play"))
.when(pl.col('RESULT').str.contains("KNEEL")).then(pl.lit("qb_kneel"))
.when(pl.col('down') == 0).then(pl.lit("extra_point"))
.otherwise(pl.lit("pass"))          # <- empty RESULT lands here (23% of legacy plays)
```

Case-sensitivity and substring accidents to document as exact-token semantics instead (lines 68–82):
- Line 68/69: `contains("Complete")` vs `== "Incomplete"` — only safe because polars `str.contains` is case-sensitive.
- Line 75: TD = `contains("TD") & not contains("Def")` — `TD` ⊂ `Def TD` handled by explicit exclusion.
- Line 80: `contains("Def TD")`.

### PAT semantics (Good/No Good + spot rules)
**Source:** `Python/helper_add_hudl_mutations.py` lines 95–107; baselines in `Python/helper_add_ep_wp.py` lines 57–78
**Apply to:** spec RESULT section (`Good`/`No Good`) + schema range notes for PAT spots

```python
# helper_add_hudl_mutations.py:95 — exact match, not contains (why "No Good" accidentally works)
pl.when((pl.col('RESULT') == "Good") & (pl.col("down") == 0) & (pl.col("yardline_50") == 45)).then(pl.lit(1))  # 1pt
# line 102: same with yardline_50 == 40  -> 2pt
```

```python
# helper_add_ep_wp.py:57,64 — hardcoded baselines the spec's PAT section should reference
.then(1 - pl.lit(0.5))   # Tries von der 5 Yard Linie sind zu 50% gut
.then(2 - pl.lit(0.92))  # Tries von der 10 Yard Linie sind zu 46% gut (2 * 0.46 = 0.92)
```

Contract facts: `down == 0` marks PAT plays; `yardline_50` 45 = 1-pt spot, 40 = 2-pt spot; `Good` is exact-match.

### Manual-field casts (the six fields being replaced by derivation)
**Source:** `Python/helper_add_hudl_mutations.py` lines 28–33
**Apply to:** spec derivation table + schema `derived_fields` dtypes

```python
pl.col("DN").cast(pl.Int32()).alias("down"),
pl.col("DIST").cast(pl.Int32()).alias("yards_to_go"),
pl.col("YARD LN").cast(pl.Int32()).alias("yardline"),
```

All six manual fields are Int32 except `posteam` (str). `yardline_50` rule verified in RESEARCH.md: `-x if x < 0 else 50 - x` (3,656/3,658 legacy rows match).

### Synthetic time (what the time-data section must reference)
**Source:** `Python/helper_add_hudl_mutations.py` lines 397–402 (`prepare_wp_data`) — NOT `helper_add_ep_wp.py` as RESEARCH.md states
**Apply to:** spec time-data section (REQ-S1-02 unavailability record)

```python
.with_columns(play_id_half = pl.col("helper_one").cum_sum().over(["game_id","half"]))
.with_columns(play_time = pl.when(play_id_half=1).then(0).otherwise(1200 / pl.col('play_id_half').max()).over(['game_id', 'half']))
```

### CSV dialect duality
**Source:** `data_raw.csv` line 1 (verified: starts with UTF-8 BOM byte sequence U+FEFF, `;` delimiter) vs `team_roster.csv` line 1 (plain UTF-8, `,`)
**Apply to:** schema `file_format` block (exports: `;` + `utf-8-sig`) and half-boundaries format (plain `,` CSV)

```
<U+FEFF BOM>PLAY #;ODK;OFF FORM;Off Str;OFF PLAY;DN;DIST;YARD LN;RESULT;Drive Success;TARGET ROUTE;RECEIVED BY;GN/LS;Thrown By;YAC;QB;C;X/H;Y/CAT;Z;Target;Drop;B;yardline_50;game_id;play_id;drive_id;half;posteam
1;Slot Left;Slot;Left;Dagger;1;20;-5;Complete;0;FADE;RIESS;32;THIELE;0;;;;;;RIESS;;;5;1;1;1;1;GER
```

(`<U+FEFF BOM>` above marks the invisible byte-order mark present in the actual file — do not paste it literally.) This header is also the legacy column canon the grandfathered 1.2 path keeps supporting, and the first data row is live evidence of the polluted-ODK pitfall (`ODK` = "Slot Left" — columns shifted/repurposed in some legacy games). Note the legacy manual columns (`yardline_50`…`posteam`) appended at the end and the player-name columns (`RECEIVED BY`, `Thrown By`, `QB`) the spec should mention for the DSGVO note.
