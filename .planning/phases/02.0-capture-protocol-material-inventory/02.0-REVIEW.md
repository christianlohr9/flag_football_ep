## Summary

All 30 gate tests pass locally (`uv run pytest tests/test_capture_artifacts.py tests/test_capture_protocol_docs.py tests/test_capture_reference_docs.py`). No blockers.

### Warnings

#### WR-01: material-inventory.md prose contradicts its own registered inventory

**File:** `docs/material-inventory.md:23` and `docs/material-inventory.md:62`
**Issue:** The document was updated on 2026-08-24 to register the actual inventory (table rows at lines 19–21: 61/60/51 clips, "gehasht und registriert"), but two prose passages still describe the pre-registration state:

- Line 23: "Die tatsächlichen Bestandszahlen entstehen erst, wenn Material gesichtet und gesichert wurde" — the Bestandszahlen already exist in the table directly above.
- Line 62: "Solches Material wird stattdessen in der Tabelle unter „Domänen & Bestand" in Prosa geführt (aktuell: „unbekannt — beim Videoanalysten/Staff, nicht gesichtet")" — the quoted "unbekannt …" entry no longer exists anywhere in the table.

This is exactly the doc/CSV drift failure mode `tests/test_capture_reference_docs.py` was written to prevent, but neither passage is guarded by a test, so the contradiction shipped silently. A later reader (Phase 2.1 selecting pilot material) gets conflicting statements about whether registered material exists.
**Fix:** Rewrite line 23 to describe the current state (e.g. "Die Bestandszahlen oben entsprechen dem am 2026-08-24 registrierten Ist-Bestand; neue Zahlen entstehen erst, wenn weiteres Material gesichtet und gesichert wurde.") and drop or rephrase the stale "(aktuell: …)" quotation at line 62 so it describes the mechanism without asserting a table entry that no longer exists.

#### WR-02: Path gate is weaker than the documented local_path contract

**File:** `tests/test_capture_artifacts.py:132-141`
**Issue:** `docs/material-inventory.md:36` mandates that `local_path` is "repo-relativ unter `data/video/`, nie ein absoluter Benutzerpfad". The gate `test_video_inventory_paths_stay_repo_relative` only rejects a leading `/`, a leading `~`, and the substrings `/Users/` and `/home/`. All of the following violate the contract but pass the gate: `../outside/clip.mp4` (repo escape), `C:\Users\me\clip.mp4` (Windows user path), `foo/bar.mp4` (relative but not under `data/video/`). The current 172 rows are all compliant (verified), so this is a latent gap, not a live defect — but the gate exists precisely to catch future hand-edits.
**Fix:**
```python
assert local_path.startswith("data/video/"), (
    f"local_path must be repo-relative under data/video/: {local_path!r}"
)
assert ".." not in Path(local_path).parts, f"local_path escapes the repo: {local_path!r}"
assert "\\" not in local_path, f"local_path uses backslashes: {local_path!r}"
```

#### WR-03: video_sync.video_file → video_inventory.local_path referential rule is unenforced

**File:** `tests/test_capture_artifacts.py:144-154` (missing check); contract at `docs/sync-convention.md:37`
**Issue:** `docs/sync-convention.md` requires that `video_file` "zeigt auf genau eine registrierte Videodatei" (a `local_path` value from `video_inventory.csv`). No test enforces this. A sync row with a typoed or unregistered `video_file` passes every gate today and only surfaces much later in Phase 2.3 as an anchor that resolves to no verifiable file — the same silent-failure class as the dtype join pitfall this module otherwise guards so carefully. `video_sync.csv` is header-only right now, so the gate would be green, but the first hand-entered anchor row is exactly when it is needed.
**Fix:** Add to `test_video_sync_rows_are_anchored` (or a new test):
```python
registered = set(
    pl.read_csv(INVENTORY_CSV, schema_overrides=INVENTORY_SCHEMA)["local_path"].drop_nulls()
)
assert row["video_file"] in registered, (
    f"video_file {row['video_file']!r} is not a registered local_path in video_inventory.csv"
)
```

#### WR-04: No uniqueness gate on local_path / content_sha256 in the inventory

**File:** `tests/test_capture_artifacts.py:116-129`
**Issue:** `docs/material-inventory.md:56` defines the CSV as the "Zeiger- und Verifikationsschicht" — `local_path` + `content_sha256` make a clip findable and verifiable. A copy-pasted duplicate row (same `local_path`, or two rows claiming different hashes for the same path) breaks those semantics and passes all current gates. With 172 hand-maintained rows appended in batches, duplicate paste is the most likely future editing error. Verified clean today (0 duplicate paths, 0 duplicate hashes).
**Fix:**
```python
assert df["local_path"].drop_nulls().is_duplicated().sum() == 0, "duplicate local_path rows"
assert df["content_sha256"].drop_nulls().is_duplicated().sum() == 0, "duplicate content_sha256 rows"
```

### Info

#### IN-01: 0.57-second clip registered as a per-play clip

**File:** `data/reference/video_inventory.csv` (row for `data/video/2026-08-14_WC_GERvsMEX_GoPro_9676542/Wide - Clip 057.mp4`)
**Issue:** `duration_seconds` is `0.57` — the only clip under 3 s in 172 rows, and far below any plausible play length for a "Clip pro Play" playlist. Likely a mis-cut Hudl re-encode fragment. Registration is legitimate per the "Material, das keine Stufe trifft" rule, but the anomaly is invisible in the notes.
**Fix:** Append a marker to that row's `notes` (e.g. "Fragment, kein vollständiger Play") so Phase 2.1 does not pick it as pilot material.

#### IN-02: Header gate crashes with IndexError on an empty CSV instead of asserting

**File:** `tests/test_capture_artifacts.py:104`
**Issue:** `raw.decode("utf-8").splitlines()[0]` raises `IndexError` if a reference CSV is ever truncated to zero bytes. The test still fails loudly, but as an unexplained traceback rather than a diagnostic assertion message.
**Fix:** `lines = raw.decode("utf-8").splitlines(); assert lines, f"{path} is empty"` before indexing.

#### IN-03: Tier-count gate can miss a dropped table tier

**File:** `tests/test_capture_protocol_docs.py:82-89`
**Issue:** `test_protocol_doc_states_all_three_tiers_per_parameter` counts raw substring occurrences of "Ideal"/"Brauchbar"/"Unbrauchbar" with threshold >= 9. Prose mentions (the "Wie die Stufen zu lesen sind" section and Begründung lines) inflate the count above 9, so deleting one tier row from one parameter table still passes.
**Fix:** Count table-cell occurrences instead, e.g. `text.count(f"| {tier} |")`, and assert >= 8 per tier for the drone tables plus the second-domain header check.

#### IN-04: game_id source description understates the actual vocabulary

**File:** `docs/material-inventory.md:31`, `docs/sync-convention.md:35`
**Issue:** Both documents describe `game_id` as derived from the Hudl export filename convention (`YYYY-MM-DD_{TEAM1}-vs-{TEAM2}_{COMP}`). But `plays.parquet` also carries ifaf-constructed ids of form `ifaf-<slug>` (`docs/ifaf-field-mapping.md`, `make_game_id("ifaf", ...)`), and the inventory's own quarantined candidates (`ifaf-ffwc26-wa1`, `ifaf-ffwc26-wb1` in `notes`) use that shape. The binding rule ("muss exakt dem plays.parquet-Wert entsprechen") is correct and takes precedence, but the filename-only source description will confuse whoever promotes those candidates into the `game_id` column.
**Fix:** Note in both column tables that ifaf-sourced games use the `ifaf-<id>` convention from `docs/ifaf-field-mapping.md`; the exact-match rule against `plays.parquet` is the invariant.

#### IN-05: Roster-name gates use naive substring matching

**File:** `tests/test_capture_artifacts.py:211-218`, `tests/test_capture_protocol_docs.py:138-143`, `tests/test_capture_reference_docs.py:102-108`
**Issue:** All three roster-leak gates do lowercase substring matching over 644 roster names. Today every `player_name` is a multi-token full name (min length 8, all contain a space), so false positives are unlikely — but a future roster entry with a short single token (e.g. "Ana") would match inside unrelated text ("Panama") and fail the suite spuriously. This is a test-reliability risk, not a current failure.
**Fix:** Match with word boundaries, e.g. `re.search(rf"\b{re.escape(name.lower())}\b", text)`.
