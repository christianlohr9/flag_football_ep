# Phase 02.0 Plan 02: Material Inventory & Sync Convention Docs Summary

**`docs/material-inventory.md` and `docs/sync-convention.md` explain the two Plan-01 reference CSVs end to end — column model, registration procedure with `ffprobe`/`shasum`, and the game_id/play_id join contract against `plays.parquet` — backed by a 7-test mechanical gate file guarding both against section loss and CSV-header drift.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3/3 completed
- **Files modified:** 3 (all created)

## Accomplishments

- `docs/material-inventory.md` (70 lines): explains all ten `video_inventory.csv` columns in a `Spalte | Typ | Pflicht | Hinweise` table, the fixed `domain` vocabulary (`drone`/`sideline`/`broadcast`), a 5-step clip registration procedure using `ffprobe` and `shasum -a 256`/`sha256sum` with an explicit multi-minute hashing-time caveat, the `data/video/` gitignore/PII policy, and a DEFERRED-ANALYST ratification block owned by the user
- `docs/sync-convention.md` (71 lines): documents that a video play anchors to an *existing* Hudl PBP play and never redefines one (D-10), that zero staff cooperation is required (D-09), Variant A (Hudl upload, wish, deferred) vs Variant B (manual snap anchor, always available, one anchor per play per D-11), the full `video_sync.csv` column/dtype model matching `SYNC_SCHEMA` from `tests/test_capture_artifacts.py` exactly, and the join contract against `data/processed/plays.parquet` including the silent-zero-row dtype-mismatch failure mode (RESEARCH Pitfall 1)
- `tests/test_capture_reference_docs.py` adds all seven named gates (8 collected test IDs after parametrizing the column-drift check over both doc/CSV pairs): required-section presence for each doc (line-exact match, not substring), CSV-column-drift detection for both doc/CSV pairs, DEFERRED-ANALYST block + ownership presence, sync-doc join-dtype and variant-marker presence, inventory-doc registration-command and domain-vocabulary presence, and roster-name PII leak detection across both docs
