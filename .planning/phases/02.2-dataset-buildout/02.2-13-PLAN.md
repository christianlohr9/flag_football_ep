<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CVAT export → tracked repo | Exports contain PII frames; only pointers and statistics may be tracked |
| local dataset → DVC remote | `dvc push` moves label data off the machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2.2-38 | Information Disclosure | `git add` of label data | mitigate | `dvc add` writes the `.gitignore` entry; the plan asserts `git check-ignore` on the dataset directory and that only the `.dvc` pointer appears in `git status` |
| T-2.2-39 | Information Disclosure | DVC remote push | mitigate | Push is an explicit command, never automatic; the remote holds labels and frames only, never raw video (guarded by tests/test_dvc_layout.py) |
| T-2.2-40 | Tampering | dataset provenance | mitigate | Both hashes recorded: `dataset_hash()` for the MLflow training-run parameter, the DVC MD5 for data movement |
| T-2.2-41 | Repudiation | "verified frames" claim | mitigate | Uncorrected frames are trimmed from `instances.json` and the manifest, following the 2.1 precedent, so the frame count means what it says |
</threat_model>
