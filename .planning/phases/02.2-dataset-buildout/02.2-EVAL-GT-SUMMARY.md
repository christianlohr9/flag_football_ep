- `frames.sample_eval_gt_frames` implemented: draws a fixed, deterministic `frames_per_clip` count from every `frozen_eval` clip in a domain (never a duration-proportional AL/training budget), on the same evenly-spaced jittered grid `sample_training_frames` uses per clip. Wired to a new `ffep cv eval-gt-sample` CLI command.
- Ran it for real: **90 drone frames** (18 clips × 5, session `2026-05-16_FRIENDLY-GER-vs-PANAMA-ROJO-DRONE`, clips 5/6/7/11/15/16/21/22/28/33/36/40/43/49/52/54/55/56) and **72 GoPro/sideline frames** (12 clips × 6, session `2026-08-14_WC-GER-vs-MEX-GOPRO`, clips 8/11/16/19/24/27/34/36/37/38/50/52), seed `20260516` — exactly the 18/12 frozen_eval clip sets in `data/reference/frozen_eval_clips.csv`, verified by direct set comparison after the run, not assumed.
- Prelabelled both with `ffep cv prelabel --backend finetuned` (no `--run-id` override needed: the champion alias still resolves to the Phase-2.1 champion `87a8a5222f7a472787875e974d089c44`, since iteration 1 was never promoted, plan 02.2-15) — drone: 1805 boxes over 90/90 frames, GoPro/sideline: 496 boxes over 66/72 frames, 6 frames with zero detections (clips 24/27, documented as 2026-09-02 far-field skip candidates, not treated as a labeling failure).
- Pushed two new, clearly named CVAT tasks: **id 6 `eval-gt-drone`** (90 frames), **id 7 `eval-gt-sideline`** (72 frames) — separate from every `al-1-*`/`al-2-*` task, confirmed live via a real `client.tasks.list()` call against the running self-hosted CVAT instance.

- Extended `detect._load_domain_ground_truth` to prefer the new domain-scoped `data/labels/eval/<domain>/corrected/` source over the legacy session-scoped `data/labels/<session_id>/corrected/` convention when present, so `ffep cv eval-domains` will read the genuinely-held-out ground truth once the user verifies it in CVAT, never silently mixing it with the (potentially train-contaminated) pilot-era convention.

## Decisions Made

- 5 frames/clip (drone) / 6 frames/clip (GoPro/sideline), both within the stated 5-6 range, matching the "~90 + ~70" estimate in `docs/dataset-buildout.md`'s own Korrektur section closely (90 exact, 72 vs. ~70).
- `sample_eval_gt_frames` resolves the session id from the frozen_eval rows of `frozen_eval_clips.csv` directly, not from the full `video_inventory.csv` — the drone domain alone has 3 registered sessions there, and only one backs any frozen_eval clip. This was found by actually running the command against the real inventory (it raised `EvalSplitError` naming 3 sessions), not anticipated in the initial design — fixed before any frame was sampled.
- The 6 GoPro zero-detection prelabel frames were left in place rather than dropped or re-sampled: a fixed, committed-to eval-GT sample must cover every frozen_eval clip's allotted frame count; the far-field skip decision is the user's per-frame judgment call during CVAT verification, documented explicitly in both `docs/dataset-buildout.md` and this summary rather than silently resolved either way.
- `assert_no_frozen_eval_clips` no-ops when `frozen_eval_clips.csv` does not exist, so it is safe to wire unconditionally into every `validate_coco` call (both real production entry points now do) without an ordering dependency on the eval split existing first, and without changing behaviour for any pre-existing call site that omits the new keyword.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `sample_eval_gt_frames`'s first design resolved sessions from the full video inventory, not the frozen split**
- **Found during:** the real `ffep cv eval-gt-sample --domain drone` invocation (not a test — the synthetic test fixtures only ever register one session per domain)
- **Issue:** `_read_domain_session_ids(config, domain)` reads every session registered for `domain` in `video_inventory.csv`; the drone domain has 3 (training camp, the Panama friendly, Puerto Rico), and only the Panama friendly backs any `frozen_eval` clip — the function raised `EvalSplitError: domain 'drone' spans 3 session(s)` before extracting a single frame.
- **Fix:** Read `session_id` directly off the `role == "frozen_eval"` rows of `frozen_eval_clips.csv` for the domain instead, which is inherently 1:1 for every domain that actually has a frozen split.
- **Files modified:** `src/flag_football_ep/cv/frames.py`
- **Verification:** real re-run succeeded for both domains (90 + 72 frames, correct clip sets); `uv run pytest tests/test_cv_frames.py -q` green (39 passed)
