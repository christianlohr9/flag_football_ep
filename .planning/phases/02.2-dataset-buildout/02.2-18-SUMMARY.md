## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `train_detector` had no way to override `validate_coco`'s image-count band, unlike `ffep cv dataset`**
- **Found during:** Task 1, the very first real training attempt against dataset v2
- **Issue:** `_prepare_dataset_layout(coco_dir, manifest, output_dir, *, eval_split_path=...)` called `validate_coco(coco_dir, manifest, eval_split_path=eval_split_path)` with no `min_images`/`max_images`, silently defaulting to the Phase-2.1 single-domain `[250, 600]` band -- identical class of gap to the one plan 02.2-13 closed for the standalone `ffep cv dataset` CLI command, but never applied to the training path itself. Dataset v1.2 (572 images) happened to fall inside `[250, 600]` by coincidence, so this never surfaced until dataset v2 (755 images) made it impossible to train at all.
- **Fix:** Added `min_images`/`max_images` keyword parameters (default `None`, preserving every existing call site's behavior) to both `_prepare_dataset_layout` and `train_detector`, threaded through to `validate_coco`; added matching `--min-images`/`--max-images` options to `ffep cv train`.
- **Files modified:** `src/flag_football_ep/cv/detect.py`, `src/flag_football_ep/cv/commands.py`, `tests/test_cv_contracts.py` (frozen signature contract update, a necessary consequence of the intentional signature extension)
- **Verification:** `uv run pytest tests/test_cv_detect_train.py tests/test_cv_contracts.py -x -q` (both green); real re-run with `--min-images 1 --max-images 3000` against dataset v2 completed training end-to-end (30 epochs, MLflow run registered)
- **Committed in:** `73ca21d`
