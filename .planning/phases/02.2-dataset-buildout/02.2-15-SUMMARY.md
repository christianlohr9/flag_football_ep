## Accomplishments

- `evaluate_per_domain` implemented: runs a loaded detector over each domain's `frozen_eval` clips and scores predictions with `torchmetrics.detection.MeanAveragePrecision` against human-corrected ground truth at `data/labels/<session_id>/corrected/instances.json`, filtered to that domain's frozen clip numbers — never a pooled number alone, and raises `EvalGroundTruthMissing` naming any domain with zero available ground-truth frames rather than reporting a metric over an empty set
- Two real, previously-undiscovered `train_detector` bugs fixed while wiring this up for the real multi-domain dataset:
  1. `_resolve_manifest_path` always read the fixed Phase-2.1 pilot manifest (`data/labels/frames/manifest.json`, 404 drone-only frames) regardless of the `--dataset` path passed — `ffep cv train --dataset data/labels/dataset` would have silently trained on stale pilot frames. Now prefers `<dataset_dir>/manifest.json` when present.
  2. `checkpoint_best_total.pth` is never written by RF-DETR's own `BestModelCallback.on_fit_end` when no validation epoch ever improves — which is unavoidable for every Phase-2.2 AL-iteration dataset (no `val` split exists by design; evaluation runs separately against frozen eval clips). Discovered by running the real training end-to-end: it failed at the post-training checkpoint check after a full, successful 30-epoch run. Fixed with a documented fallback to `checkpoint_best_ema.pth` ("a guaranteed" file per RF-DETR's own docstring), with the source recorded in `params["checkpoint_source"]`.
- Iteration-1 detector trained end-to-end on dataset v1.2 (572 images) on the primary M5 Max machine (`--device mps`, D-21's documented fallback), registered as `cv_detector_model` version 2, MLflow run `be854a1adebf4eb4b01d98dc39022ee1`, `dataset_content_sha256` logged as a parameter and matching the dataset v1.2 hash exactly
- Both the Phase-2.1 champion and the new iteration-1 run evaluated on the identical 76-image drone frozen-eval subset (the 13 of 18 frozen clips the pilot's own corrected dataset happens to cover): iteration-1 regressed on every metric (`mAP_50_95` -0.0476, `mAP_50` -0.0354, `AP_player` -0.0688, `AP_referee` -0.0264)
- GoPro/sideline confirmed genuinely unmeasurable this iteration — a real `EvalGroundTruthMissing` raise against the production `frozen_eval_clips.csv` (not just the test fixture), because no AL-1 correction ever touched a `frozen_eval` clip (by design) and no dedicated eval-ground-truth labeling session has happened for this domain
- Stopping-rule verdict applied and recorded: drone's metric verdict is `nein` (regression, not the required +0.010 improvement), but the 1,500-frame floor (572/1,500, 38%) is mandatory regardless of metric verdict, so iteration 2 proceeds for every domain anyway — exactly the case the plan itself anticipated
- Not promoted to `champion`; `resolve_champion('cv_detector_model', config)` and `resolve_frozen('cv_detector_model', config)` both re-verified after the evaluation runs and both still return `87a8a5222f7a472787875e974d089c44` (the Phase-2.1 champion, unchanged)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `train_detector` resolved its manifest from a fixed Phase-2.1 pilot path, ignoring `--dataset`**
- **Found during:** Task 1, wiring `evaluate_per_domain`/reviewing `train_detector` before the real Task 2 training run
- **Issue:** `_resolve_manifest_path(config)` always returned `config.paths.labels / "frames" / "manifest.json"` (the 404-frame, drone-only Phase-2.1 pilot manifest) regardless of the `dataset_dir` argument actually passed to `train_detector`. Training against `data/labels/dataset` (the real multi-domain v1.2 dataset) would have silently used the wrong, stale manifest instead.
- **Fix:** `_resolve_manifest_path(config, dataset_dir)` now checks `dataset_dir/manifest.json` first (the Phase-2.2 growing-dataset convention already used by `ffep cv dataset --manifest`) and only falls back to the pilot path when absent — preserving every existing Phase-2.1 test/call site unchanged.
- **Files modified:** `src/flag_football_ep/cv/detect.py`
- **Verification:** `uv run pytest tests/test_cv_detect_train.py -q` (17 passed); real training run against `data/labels/dataset` in Task 2 confirmed the correct 572-frame manifest was used (`dataset_content_sha256` in the registered run's params matches the dataset v1.2 hash exactly)
- **Committed in:** `53ba641`

**2. [Rule 1 - Bug] `checkpoint_best_total.pth` is unwritable for any zero-validation-split dataset, which is every Phase-2.2 AL-iteration dataset**
- **Found during:** Task 2, the real end-to-end training run — 30 epochs completed cleanly, then registration raised `WeightsNotFound: expected checkpoint not found ... checkpoint_best_total.pth`
- **Issue:** RF-DETR's real `BestModelCallback.on_fit_end` (verified against the installed `rfdetr==1.9.3` source) only copies a checkpoint to `checkpoint_best_total.pth` when at least one validation epoch actually improved the monitored metric. Every Phase-2.2 AL-iteration dataset carries zero `val`-split frames by design (evaluation happens separately against the frozen eval-clip split), so a validation epoch never improves and this file is never written — `train_detector` would have failed identically for any future AL iteration's training run, not just this one.
- **Fix:** `train_detector`/`_register_from_artifacts` now fall back to `checkpoint_best_ema.pth` ("a guaranteed" file per RF-DETR's own docstring, confirmed present in the real run's output directory) when `checkpoint_best_total.pth` is absent, and record which source was actually used in `params["checkpoint_source"]` for provenance.
- **Files modified:** `src/flag_football_ep/cv/detect.py`
- **Verification:** `uv run pytest tests/test_cv_detect_train.py -q` (17 passed, including a new dedicated regression test); the real run registered successfully afterward (`be854a1adebf4eb4b01d98dc39022ee1`, `params["checkpoint_source"] == "best_ema_fallback_no_val_split"`)
- **Committed in:** `05694d8`
