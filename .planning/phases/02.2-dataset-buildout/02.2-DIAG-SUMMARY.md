# Phase 02.2 Ad-hoc Diagnosis: Iteration-1 Drone Regression Root Cause Summary

**Two decisive ablation runs on the verified held-out eval ground truth show the iteration-1 drone regression is not explained by the missing val split or the multi-domain training mix (ablation A: 0.8884/0.7076 mAP_50/mAP_50_95, nearly identical to iteration-1's 0.8881/0.7073) and only marginally by champion-weight initialization (ablation B: 0.8926/0.7283) — AL-1's per-clip frame density (up to 12 frames from 43 pool clips vs. the champion's 322 frames spread across 46 clips) is the strongest remaining explanation, with label-convention drift ruled out by near-identical box statistics between the pilot and AL-1 corrections.**

- **Cheap hypotheses checked and ruled out/confirmed without GPU:**
  - Manifest/frames actually trained on by `be854a1a…` confirmed correct: `dataset_content_sha256` param matches dataset v1.2's own hash exactly, and the run started (2026-09-04 13:45) after commit `53ba641` (11:26) fixed `_resolve_manifest_path` to prefer `dataset_dir/manifest.json` — the stale-pilot-manifest bug does not explain the gap.
  - No labelling-convention drift between the pilot's corrected dataset and the AL-1 corrections: boxes/image (21.76 vs 19.69), referee share (9.86% vs 10.23%), box area (median 3537 vs 3585 px²), box width/height (44.6×86.2 vs 43.8×88.5) are all nearly identical.
  - Frame-density-per-clip comparison surfaced the real difference: champion trained on 322 frames across 46 clips (median 7/clip, duration-proportional over the full 60-clip pool); v1.2 drone draws 450 frames from only 43 pool clips (median 12/clip, at `_MAX_CANDIDATES_PER_CLIP`'s cap of 12) — more raw frames, lower effective diversity.
- **Minimal code addition:** `train_detector` gained an `init_weights: Path | None` parameter (`RFDETRSmall(pretrain_weights=...)`, the same mechanism `cv.registry.RFDETRWrapper.load_context` already uses to rebuild a model from a stored checkpoint — not a new loading path), a CLI `--init-weights` flag, provenance recorded in `params["init_weights"]`, and a regression test (`tests/test_cv_detect_train.py`) — committed (`94f0572`) before the training it was needed for.
- **Ablation A** (drone-only 450-frame subset of v1.2, unchanged images, seeded clip-level 10% val split — seed `20260905`, 5 of 43 clips, 45/450 frames = exactly 10.0% — otherwise the champion's exact settings: 30 epochs, 896px, batch 4, grad-accum 4, MPS): MLflow run `702ab0b5baaf422fa0c21e3988daa4a4`, `checkpoint_source = best_total` (the val split worked — real best-of-30-epochs selection, not the EMA fallback). Held-out drone result: `mAP_50 0.8884`, `mAP_50_95 0.7076` — within noise of iteration-1's original `0.8881`/`0.7073`. This directly falsifies both candidate 1 (no val split) and candidate 2 (multi-domain mix) as the cause: removing both simultaneously changed nothing.
- **Ablation B** (v1.2 full, unchanged 572 frames, 0 val frames — same as iteration-1 — but initialized from the champion's own `checkpoint_best_total.pth` via the new `init_weights` parameter instead of RF-DETR's default COCO-pretrained backbone): MLflow run `689d5f1dc2c2450785be0f1a1bac9491`, `checkpoint_source = best_ema_fallback_no_val_split` (as expected, no val split in v1.2). Held-out result: drone `mAP_50 0.8926` (+0.0044 vs iteration-1), `mAP_50_95 0.7283` (+0.0210); sideline `mAP_50 0.7644` (+0.0396), `mAP_50_95 0.5655` (+0.0363). Champion-weight initialization contributes a real but small improvement — nowhere near closing the gap to the champion's own drone score (`mAP_50_95 0.9423`).
- Per the objective's own decision rule ("if A closes the gap, split them with run C"), ablation C was not run: A did not close the gap, so there is nothing left to disambiguate between candidates 1 and 2.
- **Open, flagged-not-resolved anomaly:** the champion — trained on zero GoPro/Hinterfeld frames, pure zero-shot domain transfer from drone — outperforms iteration-1 (200 real GoPro training frames) on every sideline metric (`mAP_50 0.7971` vs `0.7248`, `mAP_50_95 0.7813` vs `0.5292`). ## Decisions Made

- Ran only 2 of the objective's allowed 3 ablation runs (A and B). Ablation C was explicitly conditioned in the objective on "if A closes the gap" — it did not, so C (which would only have disambiguated candidates 1 vs 2 within A's result) had nothing left to disambiguate.
- Ablation A's val-split seed (`20260905`) is deliberately new, not the project's `20260516` sampling/eval-freeze seed — a fresh partition of already-sampled frames for a one-off diagnostic split, not a new frame draw.
- Implemented `init_weights` as a minimal, tested addition to `train_detector`/`ffep cv train` rather than overloading `--resume`: `resume` restores full Lightning training state (optimizer/scheduler, continuing at the checkpoint's own epoch count); `init_weights` starts a fresh 30-epoch run from a prior detector's *weights only*, matching what candidate 4 ("champion-Feintuning") actually needs to test.
- Located the champion's real checkpoint file via the `cv_detector_model` registry's model-version source (`mlruns/artifacts/models/<model-id>/artifacts/artifacts/checkpoint_best_total.pth`), not the run's own artifact listing (empty for this MLflow logged-model storage layout) — verified by direct file existence check before use.
- Did not run a sideline-only ablation to chase the champion-beats-iteration-1-on-GoPro anomaly — outside this diagnosis's primary drone-regression scope and the 3-run budget; documented as an explicit open question rather than silently left unexplained.
