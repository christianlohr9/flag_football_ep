Telekom Cloud's S3-compatible object storage with credentials that never touch tracked config,

    - After upload the function re-reads the remote object's size and compares it against the local file, raising `BundleError` on mismatch

    Implement `deliver_bundle(config, archive, remote)` on top of the S3 client stack `dvc-s3`
    already installs (`s3fs`/`boto3`) — do not hand-roll request signing. Construct the client with
    `endpoint_url=config.cv.dvc_remote_endpoint`, region from the config, and credentials from
    `secret()`. Upload with multipart handling left to the library, then verify by re-reading the
    object size (and the ETag when the upload was single-part) and comparing against the local file
    and the bundle manifest's `content_sha256` record.

    On a signature or addressing failure, raise `BundleError` whose message states the two
    documented first remedies (path-style addressing, `listobjects`) without echoing any credential.

|----------|-------------|
| local machine → OTC OBS | PII-bearing bundles leave the machine |
| environment → tracked config | Credentials must not cross this line |
| bucket policy → the public internet | A misconfigured bucket exposes player footage |
