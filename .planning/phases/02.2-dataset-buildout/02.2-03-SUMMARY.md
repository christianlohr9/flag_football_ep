## Decisions Made

- **Clip 56 note:** replaced the corrupted cell (invalid 0x86 byte) with the user-specified ASCII text `Spielerinnen werden verloren ohne Ueberlagerung`, matching the ASCII style of the other 60 notes.
- **Outcome vocabulary:** added `completion` (caught pass without a registered flag-pull -- covers both out-of-bounds and self-surrender), `interception` (turnover), and `unknown` (outcome not determinable from the overlay) to the fixed vocabulary in both the doc and the schema gate, honoring how the user actually labelled the clips rather than forcing a re-label onto the original 5-value vocabulary.
- **Multi-puller support:** `puller_track_id` now accepts a single int or a `/`-separated list of ints (clip 33: `13/8`, two players involved in the pull). Schema changed from `Int32` to `Utf8`; a semicolon-based encoding was rejected since it collides with the field separator.
- **CSV dialect (deviation, see below):** normalised both label CSVs back to the project's comma/LF dialect instead of adapting the test suite to tolerate the semicolon/CRLF dialect the user's spreadsheet tool produced.
- **Flag-pull bonus:** not dropped. Fully labelled by the user.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Normalised both label CSVs from a semicolon/CRLF dialect back to the project's comma/LF dialect**
- **Found during:** Task 2 (re-verifying the schema gate after the labelling session)
- **Issue:** Both `data/reference/continuity_review.csv` and `data/reference/flag_pull_events.csv` came back from the user's labelling session in a `;`-delimited, CRLF-terminated dialect (the user's spreadsheet tool's locale default). A prior continuation of this plan had provisionally decided to adapt the test suite's read logic to that dialect instead. Running the existing test suite surfaced a pre-existing, explicitly named guard -- `tests/test_cv_continuity.py::test_continuity_review_csv_uses_comma_dialect` -- which forbids `;` in `continuity_review.csv` specifically because it is the dialect of a different data source ("Hudl-export dialect must not leak here"). Keeping the semicolon dialect would have left this established correctness contract permanently broken and `summarise_review`/`_load_existing_human_columns` (which assume comma-separated input) silently unable to read the real file on a pipeline re-run.
- **Fix:** Read both CSVs with the actual (`;`) dialect via polars, then wrote them back out with polars' default writer (comma, LF, correct quoting for embedded commas in `reviewer_note`) -- content-preserving, including the clip 56 and clip 33 fixes. Reverted the test file's semicolon-adaptation approach and instead added the same "Hudl-dialect must not leak" guard for `flag_pull_events.csv` that already existed for `continuity_review.csv`.
- **Files modified:** data/reference/continuity_review.csv, data/reference/flag_pull_events.csv, tests/test_cv_benchmark_labels.py
- **Verification:** `uv run pytest tests/test_cv_continuity.py tests/test_cv_gate_artifacts.py tests/test_cv_benchmark_labels.py -q` -- all 35 tests pass, including the dialect guards for both files
- **Committed in:** feedf2b (Task 2 commit)

**2. [Rule 2 - Missing critical] Added a Hudl-dialect guard for `flag_pull_events.csv`**
- **Found during:** Task 2, alongside the deviation above
- **Issue:** `continuity_review.csv` already had an explicit test rejecting `;` in the file; `flag_pull_events.csv` (introduced by this plan's Task 1) had no equivalent guard, so the same regression could silently recur for the newer file without being caught.
- **Fix:** Added `test_flag_pull_events_csv_uses_comma_dialect`, mirroring the existing continuity guard.
- **Files modified:** tests/test_cv_benchmark_labels.py
- **Verification:** Test passes against the normalised file; fails (by design, manually verified) against a semicolon-delimited copy.
- **Committed in:** feedf2b (Task 2 commit)
