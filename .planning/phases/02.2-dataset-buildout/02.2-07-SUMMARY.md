- `cv/freeze.py`'s contract stub fully implemented: `freeze`/`resolve_frozen` set/resolve `FROZEN_ALIAS` ("hackathon-frozen") exactly mirroring `registry.py::promote`/`resolve_champion`'s MLflow lookup and error-wrapping shape, but on the sibling alias so a later `champion` promotion never moves it

## Decisions Made

See frontmatter `key-decisions` for the full rationale on each of the four decisions below:
- `write_freeze_pin` resolves `model_version` internally rather than accepting it as a parameter (contracted signature has no room for it).
- `force` lives only at the CLI layer (`ffep cv freeze --force` deletes the conflicting file first); `write_freeze_pin` itself never exposes a bypass, to keep its signature byte-for-byte matching `tests/test_cv_contracts.py`'s exact-parameter guard.
- The CLI's default pin path was changed from the gitignored `data/processed/` stub default to the tracked `data/reference/hackathon_freeze.json` -- required by the plan's own acceptance criteria, treated as a Rule 1 bug fix since `commands.py` wiring (from plan 02.2-05) pointed at the wrong default.
- The live MLflow alias-set operation against the real store could not run in this isolated worktree; the tracked pin file was populated directly with already-verified documented values instead (see "Next Phase Readiness").
