## Decisions Made

- `FreezeError` reuses `flag_football_ep.model.registry.RegistryError` as its base directly (not a new `CvError`-rooted type), per the plan's explicit `<interfaces>` instruction — the sole exception-hierarchy divergence from the rest of the `cv/` package's `CvError` convention.
- `schema.py`'s `DETECTION_*` surface is implemented for real in this plan (not left as a stub) because it is pure column/dtype mirroring of the existing `TRACKING_*` schema — no CV-specific logic to defer to a later plan, and the plan's own acceptance criteria (`empty_detection_frame().schema` must print a real schema) require working code, not `NotImplementedError`.
- `prelabel_frames`'s new `backend="finetuned"` path calls `_load_finetuned_backend(device, config, None)` since that loader's real signature (`device, config, run_id`) differs from the two zero-shot loaders' `(device)`-only shape; the `_BACKENDS` dict's type annotation was widened to `Callable[..., ...]` to reflect this.
- The `freeze`/`bundle` CLI verbs each call two `cv/*` functions (`freeze`+`write_freeze_pin`; `read_freeze_pin`+`build_bundle`) rather than exactly one, matching the plan's own `+`-joined delegate notation for `freeze` and existing multi-call precedent elsewhere in `commands.py` (`teams`, `overlay`, `radar` all call more than one `cv/*` function) — the "delegate to exactly one function" guidance in PATTERNS.md is a simplification, not a hard per-verb rule.
