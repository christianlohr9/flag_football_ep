## Decisions Made

- **Floor-only for all three domains:** none of drone/sideline/broadcast had a `ja` (continue-to-mix) verdict -- drone's formal verdict was `nein` (measured regression, `mAP_50_95` delta -0.0476), sideline/broadcast had no applicable verdict yet, and `docs/dataset-plan.md ## 3` mandates floor-only labelling for both regardless of verdict availability.
- **GoPro target deliberately capped below its literal floor-remainder** (150 requested vs. 378 needed to close the floor): iteration 1 drew 200 raw GoPro frames and only 22 (11%) were near/mid-field and thus labelable; a naive 378-frame request risked repeating that painful, mostly-wasted labelling session at nearly double the scale. This is a documented override of the plan's own floor-gap-only sizing instruction (see Deviations).
- Drone's request (450, the full floor-remainder) was passed as-is and naturally capped by `select_al_frames`'s own candidate-pool ceiling (183 actual, since the fixed 43-clip pool at the new lower cap can produce at most 258 candidates) -- no code change needed, the function's documented behavior (deliver fewer than `target` when the pool is exhausted, never an error) handled this correctly.
- `_MAX_CANDIDATES_PER_CLIP` was lowered globally (not scoped per-iteration), since it is a between-iteration tuning knob by design, not a frozen contract value; iteration-1's own already-persisted manifest is unaffected (constants only govern future draws).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Combined iteration-1 manifest built for the exclusion-lookup directory mismatch**
- **Found during:** Task 1, before the first `select_al_frames` call
- **Issue:** `select_al_frames`'s iteration-N-1 exclusion reads `out_dir.parent / f"iteration-{iteration-1}" / "selection_manifest.json"`, a sibling directory literally named `iteration-<N-1>`. Iteration 1's real per-domain directories (`data/labels/al-iteration-1/<domain>`) don't match that convention -- calling `select_al_frames` with `iteration=2` as originally planned would have raised `ActiveLearningError` (manifest not found) on the first domain.
- **Fix:** built one combined manifest (all three iteration-1 domains' frames merged, via `write_selection_manifest`, never hand-edited) at the exact sibling path all three iteration-2 domain calls share (`data/labels/al-iteration-2/iteration-1/selection_manifest.json`). Cross-domain entries are harmless since exclusion keys never collide across sessions.
- **Files modified:** none tracked (gitignored data artifact only)
- **Verification:** all three domain draws confirmed zero intersection with their own domain's iteration-1 selection (quoted in Accomplishments); confirmed 750 combined frames match the sum of the three real per-domain manifests exactly
- **Committed in:** not applicable (gitignored artifact)

**2. [Rule 1 - Bug] Updated the one active_learning test whose fixture assumed the old 12-frame cap**
- **Found during:** Task 1, first test run after lowering `_MAX_CANDIDATES_PER_CLIP`
- **Issue:** `test_select_al_frames_iteration_2_excludes_iteration_1_selection` used a single 12-frame test clip with `target=6` for both iterations -- with the old cap (12), the grid yielded 12 distinct candidates (6 for each iteration); with the new cap (6), the grid yields only 6 candidates total, so iteration 1 alone consumed the entire candidate pool, leaving iteration 2 with zero and raising `ActiveLearningError`.
- **Fix:** halved the test's target to 3 (still exactly half the new cap, preserving the test's original ratio and intent), updated the final assertion accordingly.

### User-directed deviation (not a Rule 1-3 auto-fix)

**4. GoPro/sideline target reduced from the literal floor-remainder (378) to 150**
- **Found during:** Task 1's target derivation
- **Issue:** the plan's own sizing instruction ("label only as much as the floor still requires") would compute 378 for GoPro -- but iteration 1's 200-frame GoPro draw only yielded 22 (11%) usable near/mid-field frames, and a mid-session instruction explicitly directed keeping the GoPro batch small given that painful experience.
- **Fix:** requested 150 instead of 378 for the GoPro domain; the lowered per-clip cap plus this smaller target together increased distinct-clip coverage (47/48 vs. 40/48 in iteration 1) while keeping the raw batch below even iteration 1's own 200-frame draw.
- **Impact:** the projected dataset size after this iteration, using actual (not aspirational) draw counts, is 572 + 183 + 150 + 101 = 1,006 -- short of the plan's stated [1,500, 3,000] target range. Using the plan's own literal floor-gap arithmetic (450 + 378 + 100 = 928, projected 1,500) the range would technically be met on paper, but that number was never realistic given iteration 1's ~11% GoPro yield and the drone pool's hard 258-candidate ceiling at the new cap. The honest, stated-in-docs position: this iteration makes real progress (fuller clip coverage, lower per-clip correlation, lower median uncertainty across all three domains) but does not close the 1,500-frame floor in one draw; a further iteration, a GoPro-specific top-up session, or a third registered drone game (DATA-01, still pending per ABGLEICH.md conflict 2) will be needed.
- **Files modified:** none (a sizing decision, not a code change)
- **Verification:** arithmetic and reasoning both recorded in `docs/dataset-buildout.md ## Iteration 2 ### Ehrlicher Floor-Stand nach dieser Ziehung`
