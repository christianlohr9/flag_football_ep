- Merged the eight per-session prelabel packages into three per-domain push packages (session-tag-prefixed file names to avoid clip-number collisions across sessions) and pushed four CVAT tasks: drone split automatically into two (451 frames > the 300-image cap), sideline and broadcast each one task.

## Decisions Made

- Domain targets split proportionally to each session's pool-clip count, since the `selection_to_frame_manifest` bridge requires one `select_al_frames` call per session (its `FrameSampleManifest.split` is keyed by bare `clip_number`, which would collide across sessions sharing clip numbers if combined into one call).
- Per-clip cap lowered 6->4, continuing the frame-diversity trend established at iteration 2 (12->6) -- verified safe against every AL-3 session's own pool size before drawing.
- The domain-wide (not session-scoped) frozen-eval clip exclusion in `select_al_frames` was deliberately left unchanged even though it over-excludes some valid clips in non-pilot sessions whose number happens to collide with a frozen pilot clip number (confirmed: drone-trainingcamp lost 9/30 clips, sideline-trainingcamp lost 6/30, GoPro-MEX lost some too) -- this mirrors `dataset.assert_no_frozen_eval_clips`'s own documented, intentional, safety-favoring design (D-19), and narrowing it would change a cross-cutting safety guard used everywhere in the codebase, well outside this ad-hoc task's scope. All sub-targets remained reachable regardless.
- The per-domain prelabel-package merge was implemented as a temporary, uncommitted script rather than new `src/` code, following the project's own precedent for one-off analysis/merge steps that don't need to become a permanent pipeline stage (e.g. the GoPro near/mid/far zone analysis noted in `docs/material-sighting.md`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `frames._read_stratum_ids` used `domain == "drone"` alone to decide the hover-position source**
- **Found during:** Task 2, first `active-learn` call against a non-pilot drone session (`2026-05-17_FRIENDLY-GER-vs-PANAMA-AZUL-DRONE`)
- **Issue:** every additional drone session has its own `sighting_<session_id>.csv` (plan 02.2-02's per-session convention, already used correctly for the 2026-01-03 trainingcamp and 2026-05-16 Puerto Rico sessions), but this function still looked in the shared, pilot-only `hover_positions.csv` for ANY drone-domain session, raising `EvalSplitError: ... is missing hover_position_id for clip(s) [...]`. Never triggered before AL-3 because no prior selection/eval-split call ever named a second drone session.
- **Fix:** added `and session_id == config.cv.pilot_session_id` to the branch condition.
- **Files modified:** `src/flag_football_ep/cv/frames.py`, `tests/test_cv_frames.py` (11 fake session ids replaced with `cfg.cv.pilot_session_id` so the fixtures match real pilot-session behavior), `tests/test_cv_active_learning.py` (8 fake session ids, same fix, plus f-string-prefix corrections on the file-path literals that referenced `{session_id}`)
- **Verification:** `uv run pytest tests/test_cv_frames.py tests/test_cv_active_learning.py -q` -- all green; real `active-learn` calls against all four drone sessions succeeded afterward
- **Committed in:** `4968cdf`

**2. [Rule 1 - Bug] `frames.extract_frames` trusted ffmpeg's exit code alone, missing a silent zero-byte failure mode**
- **Found during:** Task 2, `active-learn` for `2026-01-03_TRAININGCAMP-GER-vs-GER-SIDELINE` (first symptom: non-zero exit with a confusing mjpeg pixel-format error) and, after the first fix, a subsequent `prelabel` call for `2026-03-01_FRIENDLY-GER-vs-MEX-GOPRO` (second, more serious symptom: `PrelabelBackendUnavailable: sampled frame missing on disk`)
- **Issue:** VFR-encoded footage can compute a last-selected-frame timestamp a few hundredths of a second past the container's own `format.duration` (real decode frame count / cv2's average FPS vs. ffprobe's nominal `r_frame_rate`-derived FPS disagree). Two failure modes confirmed against real footage: (a) ffmpeg exits non-zero with a downstream image-encoder error unrelated to the real cause; (b) **ffmpeg exits 0** with "Output file is empty, nothing was encoded" and writes nothing at all -- the old code only checked `returncode != 0`, so this second mode passed silently, leaving two GoPro selection-manifest entries pointing at files that never existed, discovered only when `prelabel` tried to open them.
- **Fix:** two-stage. First pass (`8c62921`) added a single backward-nudged retry on non-zero exit. Second, complete pass (`375f970`) replaced the exit-code check with `_extraction_succeeded` (file exists AND has non-zero size) and retries at progressively larger nudges (0.1/0.25/0.5s) regardless of exit code; the two originally-missing GoPro frames were re-extracted with the fixed code and verified present.
- **Files modified:** `src/flag_football_ep/cv/frames.py`, `tests/test_cv_frames.py` (4 new tests: non-zero-exit retry, exit-0-empty-file retry, final-failure with original error, final-failure naming the "wrote no bytes" case)
- **Verification:** `uv run pytest tests/test_cv_frames.py -q` -- 45 passed; direct re-extraction of both originally-missing frames confirmed present and non-empty; a full sweep of all 902 AL-3 frames across all eight selections confirmed 0 missing/zero-byte files
- **Committed in:** `8c62921` (first pass), `375f970` (complete fix)
