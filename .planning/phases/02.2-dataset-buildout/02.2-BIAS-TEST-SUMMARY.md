# Phase 02.2 Ad-hoc Plan: Prelabel Bias Test for the Verified Eval Ground Truth Summary

**Drew a deterministic 30-frame subset (20 drone/10 sideline) from the already-verified eval ground truth, pushed it to CVAT as a zero-annotation task (id 11, `eval-bias-test`, confirmed 0 shapes) for the owner to label completely from scratch, and implemented `ffep cv eval-bias` to measure, once labelled, both box-level agreement and per-run mAP against the existing prelabel-derived GT and the new from-scratch GT side by side — quantifying the prelabel-bias caveat every prior comparison in this phase has flagged but never measured.**

keying is correct (numbers stand); added an on-field-only evaluation mode

prelabel-derived GoPro GT) into `data/labels/eval/sideline/corrected/instances.json` and
re-ran `ffep cv eval-domains` on the corrected GT; confirmed the "every visible person" labelling
convention with the owner and documented it. See `## Ergebnis (2026-09-11 Follow-up)` below.

## Decisions Made

- Seed `20260911` (the decision date), `max_per_clip=2` — drone (20/18 clips) touches every clip, sideline (10/12 clips) touches 10 of 12, both stratified rather than concentrated.
- Reused `ffep cv cvat-push` unmodified for the actual network push; `eval-bias-sample` only builds the package. Consistent with `cv-setup.md`'s existing CVAT round-trip division of labour.
- IoU thresholds (0.5 matched / 0.95 near-identical) reused verbatim from the existing 2026-09-04 prelabel-diff methodology already documented, not reinvented.
- `detect.evaluate_domain_frames` made public rather than duplicating the `torchmetrics.MeanAveragePrecision` scoring loop in `bias.py` — a deliberate departure from this codebase's usual small-private-helper duplication precedent (`_IMAGE_SUFFIXES` etc.), justified because this helper is large, third-party-library-backed, and now has two real callers.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test fixtures initially wrote non-decodable fake JPEG bytes**
- **Found during:** first `pytest tests/test_cv_bias.py` run
- **Issue:** `_write_eval_gt_coco`'s and the `evaluate_bias_test` integration test's synthetic image files were written as arbitrary text bytes (`f"fake-jpeg-{file_name}".encode()`), which `cv2.imread` cannot decode — `evaluate_domain_frames` raised `EvalGroundTruthMissing` mid-test rather than exercising the real scoring path.
- **Fix:** Write real (tiny, all-zero) JPEG bytes via `cv2.imwrite`, mirroring `tests/test_cv_detect_train.py::_write_corrected_coco`'s own fixture technique.
- **Files modified:** `tests/test_cv_bias.py`
- **Verification:** `uv run pytest tests/test_cv_bias.py -q` green (15 passed)
- **Committed in:** `19f1687` (fixed before the commit, not a separate follow-up)

**2. [Rule 1 - Bug] `_load_new_gt_for_domain` raised a raw `FileNotFoundError` instead of a named `BiasTestError` when the bias-test CVAT export had not been pulled yet**
- **Found during:** `test_evaluate_bias_test_raises_when_bias_gt_not_pulled_yet`
- **Issue:** The function read `bias_gt_dir / "instances.json"` unconditionally; a not-yet-pulled directory surfaced as an unhandled `pathlib` exception rather than the project's own named error convention (every other missing-input case in this module raises `BiasTestError`).
- **Fix:** Added an explicit existence check before the read, raising `BiasTestError` naming the domain and the expected `cvat-pull` command.
- **Files modified:** `src/flag_football_ep/cv/bias.py`
- **Verification:** `uv run pytest tests/test_cv_bias.py -q` green
- **Committed in:** `19f1687` (fixed before the commit, not a separate follow-up)
