<objective>
Switch the private hackathon test set from the D-07 fallback (18 withheld Panama Rojo clips, same
game as the dev set) to the real second drone game: `2026-05-16_FRIENDLY-GER-vs-PUERTORICO-DRONE-WIDE`,
61 WIDE clips, registered 2026-09-02. Dev and test then differ by GAME, not by clip — which is what
DATA-04 asks for and what ABGLEICH.md records as conflict 1.

Purpose: with a clip-level split, every team tunes on the same game they are graded on; opponent,
jersey set, lighting and hover geometry are shared, so a memorised appearance model scores as if it
generalised. A second game removes that shortcut and makes the end scoring mean what the challenge
claims it means. The material arrived on 2026-09-02, so the fallback is no longer the honest option.
Output: a hackathon-role split that is separate from the detector eval split, a tracked
training-pool exclusion for the test game, real Puerto Rico detections/tracks/overlays, the user's
continuity + flag-pull ground truth in the label vault, rebuilt dev and test bundles with new
content hashes, and the German documentation to match.
</objective>

Why the exclusion must be session-level, not clip-level: `select_al_frames` computes
`frozen_numbers = set(eval_split.clips_by_domain.get(domain, []))` -- keyed by DOMAIN, not by
session. Puerto Rico is `drone` and reuses clip numbers 1..63, so adding its clips to
`frozen_eval_clips.csv` would (a) be refused by the file-wide seed invariant and (b) if forced,
empty the pilot session's own candidate pool. A session-level exclusion is the only correct shape.
