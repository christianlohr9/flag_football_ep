<objective>
Make the first three measurable methods of BASE-01 produce real numbers under identical conditions:
BoT-SORT (re-scored from the existing frozen tracks Parquet, not re-run), ByteTrack and CBIoU
(both from `trackers==2.6.0`, Apache-2.0, already installed — no new dependency). Same frozen
detections in, same 8-column contract out, same unmodified `score_tracks.py` on top, per-clip rows
kept for M2-4.

This plan also fixes the comparability trap this phase would otherwise walk into: `score_tracks.py`
prints TWO numbers, and only one of them reacts to `--tracks`. Verified on the existing baseline
Parquet this session:

```
Automatische Kontinuitaet (auto_flag=ok): 57/61 (93.44%)
Referenz-Baseline (Human-Urteile, aus --review): 15/61 (24.59%)
```

The 15/61 line is read straight out of `--review` and is IDENTICAL for every submitted tracks file —
it is the human verdict on BoT-SORT overlays, not a property of the tracks being scored. Any table
that puts 15/61 next to a ByteTrack number in the same column would be fabricated. This plan
therefore records, per method: the automatic rate (comparable across methods, but saturated at
57/61 for BoT-SORT — record it, do not sell it), descriptive per-clip track statistics, and a
`human_pass` cell that is filled for BoT-SORT only and left empty everywhere else.

Purpose: BASE-04 needs a defensible comparison, and a comparison built on a metric that cannot
distinguish the methods would be worse than none.
Output: two scripts, one test file, and two committed result files under
`data/reference/baseline-methods/`.
</objective>
