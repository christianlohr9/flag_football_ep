# Phase 01.4 Plan 07: WP Review Page Summary

**Per-game WP review page (`reports/wp_review.py` + `templates/wp_review.html.j2`) pairing the annotated WP curve with a home-perspective swing table, a repeated synthetic-clock notice, a path-safe filename derived from an allow-listed `game_slug`, and a data-derived provenance sentence resolved via `attach_wp_provenance` (out-of-fold for historical plays, champion model for new ones, never mixed for the same play).**

## Accomplishments
- `game_slug`/`wp_review_filename`: allow-list sanitisation of an analyst-controlled `game_id` into a path-safe filename, re-validated against `GAME_SLUG_PATTERN` before returning (mirrors `model/score.py::_validate_run_id`'s discipline)
- `build_wp_review_page`: assembles the embedded WP chart, a home-perspective swing table, a header summary (final score / biggest swing / lead changes) or an explicit `keine WP-Daten` notice, and a data-derived provenance sentence into a standalone HTML string with zero filesystem writes
- `wp_review.html.j2`: standalone, escaped, script-free, external-reference-free page extending `base.html.j2`, with the synthetic-clock caveat repeated in prose whenever it's on the chart
- `attach_wp_provenance`: resolves `wp`/`home_wp`/`away_wp`/`wpa` per play from `oof_predictions_wp.parquet` first (historical), then the champion-scored frame only for the OOF-unmatched subset (new games) -- structurally incapable of mixing the two sources for one play

### Auto-fixed Issues

**1. [Rule 1 - Bug] `.gitignore`'s unanchored `reports/` rule also matched `src/flag_football_ep/reports/`**
- **Found during:** Task 1 (staging `src/flag_football_ep/reports/wp_review.py` for commit)
- **Issue:** `.gitignore` line 23 was a bare `reports/` (no leading slash), which git treats as "any directory named `reports` at any depth" -- not just the intended top-level generated-output directory `ffep.toml`'s `reports = "reports"` points at. This silently made `git add src/flag_football_ep/reports/wp_review.py` a no-op (git ignores staging attempts on ignored paths that were never tracked), which would have produced an empty commit or, worse, a commit that looked complete in the diff summary but omitted the new source file entirely. `reports/__init__.py` and `reports/render.py` from plan 02 remained tracked only because they were added to git *before* this ignore rule existed (a later plan in wave 1 introduced it) -- git does not retroactively untrack already-tracked files that later match a new ignore rule, so the bug was latent until the next new file in that directory.
- **Fix:** Anchored the rule to the repo root: `reports/` -> `/reports/`, with a comment explaining why (the source package must stay trackable; only the top-level generated-output directory should be ignored).
- **Files modified:** `.gitignore`
- **Verification:** `git check-ignore -v src/flag_football_ep/reports/wp_review.py` now exits 1 (not ignored); `git status --short` shows the new file as untracked (`??`) instead of invisible; the file staged and committed successfully.
