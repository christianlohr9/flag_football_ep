# Phase 01.4 Plan 11: Opponent Tendency Report Rendering Summary

**`build_opponent_page` turns plan 08's `OpponentReportData` into one self-contained, path-safe-named German HTML file per opponent -- summary block first, four tendency sections below with pre-formatted rate/share cells, greyed-not-hidden thin cells, and embedded share-bar charts -- with no filesystem writes and no leaked matplotlib figures.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 2/2 completed
- **Files modified:** 3 (1 created, 2 modified)

## Accomplishments

- `team_slug`/`opponent_filename` sanitise a hand-edited-CSV-sourced team code into a safe filename (`opponent-{slug}.html`), mirroring plan 07's `wp_review.game_slug` shape and satisfying `reports.render.write_report_run`'s separator/`..`/null-byte filename-key rejection rule
- `build_opponent_page` converts `OpponentReportData` into a render context with every rate/share cell pre-formatted (`XX% (n=K)` or `keine Daten`, no decimal places) and a row-level `muted` boolean, so `opponent_report.html.j2` contains zero arithmetic or formatting logic
- Formation-tendencies and route-distribution sections each embed one `render_share_bars` chart via `fig_to_data_uri`; play-call and 4th-down/PAT sections stay table-only per CONTEXT's lock, and every embedded figure is closed (`matplotlib.pyplot.get_fignums()` empty after every call)
- `opponent_report.html.j2` extends `base.html.j2`: the `.summary-block` (30-second read) always precedes every `<h2>`, a `.warning-block` for degradation notices renders only when non-empty, muted cells carry `muted-cell` with a one-line legend under the first table naming `MUTED_MIN_N`, and footnotes state the field-zone boundaries, the `±6` score-state margin, Clopper-Pearson, and the Hudl-only vs all-sources split
- A zero-film opponent renders a page containing every section's `empty_notice` and raises nothing; a team name or charted label containing markup renders escaped, never as live HTML, via the environment's `select_autoescape`

## Deviations from Plan

### Process deviation (documented, not a Rule 1-4 fix)

**Task 1 ships a minimal stub `opponent_report.html.j2`, task 2 replaces it wholesale.** The plan assigns the template file to task 2's `<files>`, but task 1's own required tests call `build_opponent_page`, which renders through `render_page("opponent_report.html.j2", ...)` -- there is no way to verify task 1's acceptance criteria (DOCTYPE prefix, summary sentences present, one chart per non-empty share section, no leaked figures, zero-film notices, no external references) without the template file existing. This mirrors plan 02's own documented Rule 3 precedent (a minimal `base.html.j2` stub in its task 1, replaced wholesale in its task 2). Task 1's stub covers exactly what its tests need (title/subtitle/summary-block/notices/section headings/chart embed/empty-notice text) and omits table markup, the muted-cell legend, and footnotes -- all of which are task 2's responsibility and are added when the stub is replaced.

**Total deviations:** 0 auto-fixed bugs; 1 documented process deviation (stub-then-replace template sequencing), directly mirroring plan 02's precedent for the same underlying reason (a task 1 test suite that must render through a template task 2 owns).
**Impact on plan:** None on scope or correctness -- both tasks' acceptance criteria are independently met and test-covered; the git history shows two atomic per-task commits as the plan specifies.

## Issues Encountered

- `page.index("summary-block")` / `page.count("<h2>")`-style assertions had to account for `base.html.j2`'s stylesheet always defining the `.warning-block` CSS rule (present in every page regardless of whether any element uses the class) -- tests check for `class="warning-block"` rather than the bare substring `"warning-block"` to avoid a false positive against the always-present CSS rule.
- Summary sentences generated by plan 08's `top_tendency_sentences` legitimately contain a literal `&` (e.g. `"... 1. & Short 1-3 ..."`); Jinja2's autoescape correctly renders this as `&amp;` in the output HTML. Tests compare against `markupsafe.escape(sentence)` rather than the raw sentence string, since asserting the raw (unescaped) form would be asserting broken escaping.
- Full-suite `pytest tests/ -q` was not run in this worktree per the parallel-executor environment note. Verified instead: `uv run pytest tests/test_reports_opponent_page.py tests/test_reports_opponent.py tests/test_reports_aggregate.py tests/test_reports_render.py tests/test_charts_tendency.py -q` -- all 111 tests passed (one pre-existing `RuntimeWarning` about matplotlib's open-figure count from `test_charts_tendency.py`'s own suite, unrelated to this plan's changes since `fig_to_data_uri` always closes its figure in a `finally` block). Orchestrator should run `uv run pytest tests/ -q` post-merge as the deferred full-suite gate.
