<objective>
Turn the annotated WP curve from plan 04 into REQ-S1-15's per-game review product: one
standalone HTML page per game, with the chart, a short swing table, an explicit synthetic-clock
notice, a filename that is safe to write, and WP values whose provenance is resolved the same
honest way plan 09 resolves own-team EPA — out-of-fold for historical plays, the promoted
champion for new ones.

Purpose: the WP chart alone is an image. The review page is what the staff opens next to the
film — curve on top, the plays that moved it listed underneath with their WP change, so a
swing on the chart can be found on the tape. And because a review page is read as evidence
about decisions the team already made, an in-sample WP curve on a game the champion trained on
would flatter exactly the moments the staff is reviewing; PATTERNS.md's "same OOF-vs-champion
split as `own_team.py`'s EPA source" applies here for the same reason it applies there.
Output: `reports/wp_review.py` and `templates/wp_review.html.j2`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `game_id` (derived from an analyst-controlled export filename) → output filename under `reports/` | the untrusted half of the write path |
| charted team codes / play labels → HTML page | source-derived strings interpolated into a document |
| synthetic WP timeline → coaching conclusion | a curve that looks time-based but is play-indexed |
| model predictions → post-hoc game review | an in-sample curve on a training-set game would flatter the very decisions being reviewed |
