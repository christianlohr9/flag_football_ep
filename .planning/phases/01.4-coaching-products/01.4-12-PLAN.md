<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hand-charted player names → HTML page opened in a browser | the highest-cardinality free-text field in the corpus reaches this page directly |
| model provenance → a self-assessment page | a page that does not say which model produced its EPA invites in-sample numbers being read as honest |
| generated page → filesystem / sharing | the page contains player names (PII) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.4-51 | Tampering | markup injection via a charted player name | mitigate | plan 02's `select_autoescape`; asserted with a `<script>` payload in a player name |
| T-1.4-52 | Repudiation / misrepresentation | EPA provenance left implicit | mitigate | the footnotes render a numeric provenance sentence (out-of-fold count, champion count, unattributed count) built from the `epa_source` distribution; asserted in tests |
| T-1.4-53 | Spoofing (identity) | an unmapped spelling silently treated as a distinct athlete without the reader noticing | mitigate | the unmapped list renders in a `.warning-block` above the tables, naming the file to edit; asserted for both empty and non-empty cases |
| T-1.4-54 | Information disclosure | the PII-bearing page committed or served | mitigate | `reports/` is git-ignored (plan 01, T-1.4-02); the page embeds all assets and makes no external request, asserted by the no-`http(s)` check |
| T-1.4-55 | Denial of service | an empty corpus aborting the run | mitigate | a fully-empty data object still renders a page with notices |
</threat_model>
