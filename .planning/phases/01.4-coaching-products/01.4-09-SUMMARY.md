# Phase 01.4 Plan 09: Own-Team Efficiency Data Summary

**`reports/own_team.py`: own-team EPA resolved from persisted out-of-fold predictions (historical) or champion scoring (new), broken out by formation/play-call/route and per QB/receiver with YAC shares, drive outcomes derived fresh (never from `drive_success`), and a basic defense section -- REQ-S1-13's full data object.**

## Accomplishments

- `attach_epa` gives every own-team play a single, documented `epa_source` (`"oof"` | `"champion"` | null) by joining persisted out-of-fold predictions for historical plays and deriving `ep`/`epa`/`wp`/`home_wp`/`wpa` through the same `prepare_ep_data`/`prepare_wp_data` -> `add_ep_variables`/`add_wp_variables` pipeline `model.score.score_plays` uses -- never hand-rolled arithmetic. The champion join is applied only to the OOF-unmatched partition, so no play can ever draw a non-null EPA value from both sources (asserted directly by a conflicting-value test).
- `efficiency_by_call` breaks EPA/play out by `off_form`, `off_play` and `target_route` with a current-cycle-vs-all-time comparison, each dimension individually restricted to its Hudl-charted subset.
- `player_efficiency` canonicalises `qb`/`thrown_by`/`received_by`/`target` per source via `map_players` before any rollup, so an unmapped spelling still appears verbatim in the table and in the returned unmapped tuple -- the locked "the report never breaks on an unmapped name" contract. QB completion rate and receiver YAC shares (summing to 1.0 within a role) round out the per-player table, sorted by current-cycle EPA/play descending.
- `drive_outcomes` classifies every drive fresh (TD / Turnover / Downs / Halbzeitende / Sonstiges) from `touchdown`/`interception`/4th-down/half-boundary flags, deliberately never reading the canonical `drive_success` column (RESEARCH Pitfall 4 -- populated only for `legacy` with different binary semantics), with a `punkte_pro_drive` headline.
- `defense_section` reports EPA/play allowed by `def_front` and `coverage` plus interception/defensive-touchdown takeaway counts, filtered to `defteam == team`.
- `build_own_team_data` assembles all four sections into `OwnTeamReportData`, degrading every failure mode (missing OOF files, a missing player-mapping file, an absent own team, any empty section) to a German-language notice instead of raising.

## Decisions Made

- `attach_epa` derives `ep`/`epa`/`wp`/`home_wp`/`wpa` from the joined out-of-fold probability columns through the exact same feature pipeline `model.score.score_plays` uses (`prepare_ep_data`/`prepare_wp_data` -> `add_ep_variables`/`add_wp_variables` with `estimate_pat_baselines(plays)`), never reimplementing the arithmetic.
- A play's `epa_source` is decided by the EP out-of-fold file match alone; the WP out-of-fold file is expected to cover the same historical corpus, and this is documented explicitly in `attach_epa`'s docstring rather than silently assumed.
- Player identity canonicalisation groups the input frame by `source` and calls `map_players` once per source (a mapping row is keyed by `(source, source_player)`), accumulating the union of unmapped labels -- matching the interface's stated per-source call pattern.
- `drive_outcomes`/`defense_section` broadcast their headline scalars (`punkte_pro_drive`/`drive_count`, `interceptions_n`/`def_touchdowns_n`) onto every row of the section's table rather than inventing a new field on `ReportSection`, since the locked interface only exposes `key`/`heading`/`table`/`basis`/`empty_notice`.

**2. [Rule 1 - Bug] `build_own_team_data` runs `attach_epa` on the full corpus before filtering to the own team, not after**

- **Found during:** Task 3, implementing `build_own_team_data` per the plan's literal action text ("filter to the configured `config.report.own_team` ... call `attach_epa` with `config.paths.processed` and `scored`")
- **Issue:** `add_ep_variables`/`add_wp_variables` (which `attach_epa` calls) derive `epa`/`wpa` via `shift(-1)`/`backward_fill()` scoped `.over("game_id")`. This requires true play-by-play adjacency across BOTH teams' snaps within a game -- nflfastR-style EPA is `EP(next real play) - EP(current play)`, regardless of which team has the ball on the next play. Filtering `plays` down to `posteam == team` (or `defteam == team`) BEFORE calling `attach_epa`, as the plan's action text literally orders it, would silently corrupt every derived EPA value: `shift(-1)` would look at the next *own-team* play in the filtered frame, not the actual next play of the game, and `backward_fill` would pull `ep` across removed opponent snaps as if they were adjacent.
- **Fix:** `build_own_team_data` calls `attach_epa(plays, ...)` once on the full, unfiltered corpus, then filters the EPA-attached OUTPUT to `posteam == team` / `defteam == team` for the four section builders. `attach_epa`'s own docstring states this requirement explicitly ("Deliberately operates on `plays` as a whole... callers must filter the OUTPUT of `attach_epa`, never its input, to a team subset") so a future caller cannot reintroduce the bug by ignoring the plan's original wording.
- **Files modified:** `src/flag_football_ep/reports/own_team.py`
- **Verification:** Functional smoke tests during development confirmed `attach_epa` on a full 8-play single-drive fixture (mixed posteam) produces the expected non-degenerate `epa` sequence with correct `shift`/`backward_fill` adjacency; `TestBuildOwnTeamData` exercises the full assembled path end-to-end without raising.
- **Committed in:** `e681dfd` (Task 3 commit)
