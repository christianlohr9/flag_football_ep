# Phase 01.4 Plan 06: Game Decisions Cheat Sheet Summary

**Standalone, printable "game decisions" page assembling the PAT break-even and 4th-down conversion-by-distance charts with plain-German readings that carry sample sizes and an honest three-branch go/no-go verdict.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 2/2 completed
- **Files created:** 3 (decisions.py, decisions_cheatsheet.html.j2, test_reports_decisions.py)

## Accomplishments

- `build_decisions_page(plays, *, generated_on=None) -> str` composes `estimate_pat_baselines`/`estimate_fourth_down_rates` (both reused, neither reimplemented), renders both charts via `render_pat_breakeven`/`render_fourth_down`, embeds each through `reports.render.fig_to_data_uri`, and returns one self-contained HTML string with zero filesystem writes.
- A corpus with zero PAT attempts (`InsufficientPatAttempts`) degrades gracefully: the page still renders with the 4th-down half intact and an explicit German `Hinweis` in place of the PAT chart, never raising.
- The 2-point go/no-go reading has three explicit branches derived from the observed rate's Clopper-Pearson CI against the break-even rate: clearly-above (`Empfehlung: 2-Punkte-Versuch`), clearly-below (`Empfehlung: 1-Punkt-Versuch`), and straddling (`Zu dünne Datenlage für eine klare Empfehlung.`) — the straddling case is the honest default, never a false-confidence call.
- The 4th-down reading names the best/worst distance bucket by conversion rate (excluding zero-attempt buckets from that comparison, so an empty bucket never reads as a 0% conversion) plus the pooled overall rate, each with its `n`.
- `decisions_cheatsheet.html.j2` extends `base.html.j2`: a `summary-block` with the plain-German readings sits above two `chart-block` sections (PAT, 4th down), each with a `section-basis` line, followed by a footnotes block naming the Clopper-Pearson method and the `FOURTH_DOWN_DISTANCE_BUCKETS` boundaries.

## Decisions Made

- **Docstring avoids the literal string `savefig`.** The plan's own acceptance criteria run `grep -c "savefig" src/flag_football_ep/reports/decisions.py` and require `0`. An early docstring draft explaining the `fig_to_data_uri`-only discipline used the phrase "never `fig.savefig` directly" — accurate prose, but it tripped the literal grep. Reworded to "never the Figure's own direct PNG export" to preserve the explanation without the substring.
- **Task 1 shipped a minimal placeholder template**, mirroring the exact precedent documented in plan 02's own SUMMARY (deviation #3: `base.html.j2` needed to exist a task before its assigned task, because `render_page`'s own tests load it). `build_decisions_page`'s Task 1 tests call `render_page("decisions_cheatsheet.html.j2", ...)`, so the template had to exist — a bare `summary-block`/chart-img shell sufficed for Task 1's structural assertions, and Task 2 replaced it wholesale with the full spec'd layout (headings, chart-block wrappers, section-basis lines, footnotes).
- **`git add -f` for both new files under `src/flag_football_ep/reports/`.** `.gitignore` line 23 (`reports/`) is scoped to the *generated report output* directory but, written without a leading slash, also matches the source package path `src/flag_football_ep/reports/`. `render.py`/`__init__.py` from plan 02 are already tracked under this same force-add — followed the established precedent rather than reworking the ignore rule (out of scope for this plan).
