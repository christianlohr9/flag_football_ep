    `build_reports(plays, scored, *, config, opponents=None, products=None) -> dict[str, str]`:
    - resolve the opponent list: when `opponents` is None, take every `canonical_team` from
      `load_group_opponents(config.reference.group_opponents)`; when it is provided, validate

      allow-list check happens before `opponent_filename` is called, and `team_slug` remains the
      second layer.

      `DECISIONS_FILENAME`; one `build_wp_review_page(...)` per distinct `game_id` in `scored`
      keyed by `wp_review_filename(game_id)`.
    - a per-product failure must not abort the batch: wrap each page build in a try/except that
      records a German notice naming the product and the exception text and continues. A run
      that produces four of five products is worth far more the evening before a tournament than
      a run that produces none. Re-raise nothing except a `ValueError` from the allow-list
      validation, which is a caller error and must fail fast.

      produce, matching `run_all`'s stated discipline)
    - stage `score`: `score_plays(plays, config)` with NO `ep_run`/`wp_run` arguments, so
      `resolve_run` falls through to `registry.resolve_champion`; write the result to
      `config.paths.processed / "plays_scored.parquet"`. Let `RegistryError` propagate unchanged

      built from an unpromoted model is exactly what CONTEXT forbids.
    - stage `report`: `build_reports(...)` then `write_report_run(rendered,
      config.paths.reports)`
    - return `ReportRunResult` with both directories, the sorted filenames, the durations dict
      and the accumulated notices.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument (`--opponent`, `--product`) → filesystem path and dispatch | the only genuinely caller-supplied input in the whole phase |
| MLflow model registry → the numbers on every report page | which model scored a report determines what the staff believes about their team |
| report run folder → `reports/latest/` | the folder the HC actually opens |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.4-56 | Tampering | path traversal via a crafted `--opponent` value | mitigate | `build_reports` validates every opponent against the closed `canonical_team` set from `load_group_opponents` before any path construction; `team_slug` (plan 11) and `write_report_run`'s key rejection (plan 02) are the second and third layers |
| T-1.4-57 | Elevation of privilege (model provenance) | a never-reviewed, freshly trained model silently scoring a report | mitigate | `score_plays(plays, config)` is called with no run ids so only the promoted `champion` alias resolves; `run_all`/`train_*` are never called; a monkeypatched-`train_*`-raises test proves it |
| T-1.4-58 | Denial of service | a missing `champion` alias failing opaquely | accept | `RegistryError` propagates unchanged; its existing message already names `ffep promote` as the fix, which is the correct operator action |
| T-1.4-59 | Denial of service | one failing product aborting the whole pre-tournament run | mitigate | per-product try/except records a notice and continues; allow-list `ValueError`s still fail fast as caller errors |
| T-1.4-60 | Tampering | a half-written report set presented as `latest/` | mitigate | `write_report_run` (plan 02) completes the dated folder before replacing `latest/`; the end-to-end test asserts `latest/` is replaced, not merged |
| T-1.4-61 | Information disclosure | an unexpected network call during a report run | mitigate | the end-to-end test monkeypatches `socket.socket.connect` to raise; report generation reads only local snapshots, matching the snapshot-first ingest design |
</threat_model>
