  <action>
    Add `FourthDownBucket`, `FourthDownRates`, `FOURTH_DOWN_DISTANCE_BUCKETS` and
    `estimate_fourth_down_rates(plays)` to `features/mutations.py`, placed directly after
    `estimate_pat_baselines` so the two small-sample estimators sit together.

    Attempt definition: a row with `down == 4` and `play_type` in `{"run", "pass"}` — a 4th-down
    play the offense actually ran. Exclude `play_type == "no_play"` and rows with `penalty == 1`
    (a play wiped out by a penalty is neither a conversion nor a failure) and exclude
    `down == 0` PAT rows, which the PAT estimator already owns. State each exclusion in the
    docstring with its reason.

    Conversion definition: `first_down == 1` OR `touchdown == 1` on that row. A 4th-down
    touchdown is a conversion even when `first_down` is 0, because scoring ends the series
    successfully — say so in the docstring.

    Bucketing: `FOURTH_DOWN_DISTANCE_BUCKETS` as declared in the interfaces block above,
    applied with a chained `pl.when(...).then(...).otherwise(...)` expression over
    `yards_to_go`, matching the module's polars idiom (never a Python-level row loop). Rows with
    `yards_to_go < 1` or a null `yards_to_go` are excluded from every bucket and counted in a
    docstring-documented way — do not silently fold them into the `1-3` bucket.

    Per bucket compute `attempts`, `conversions`, `rate = conversions / attempts`, and
    `ci = binomtest(conversions, attempts).proportion_ci()` as a `(low, high)` tuple — the same
    Clopper-Pearson call `estimate_pat_baselines` uses, never a normal approximation. When a
    bucket has zero attempts set `rate=None` and `ci=None`; the bucket still appears in
    `buckets` so the chart can render an explicit gap. Unlike `estimate_pat_baselines`, an empty
    bucket must NOT raise — a corpus legitimately may contain no 4th-and-11+ attempts, and the
    decision cheat sheet still has to render. Set `overall_rate=None` when `total_attempts == 0`.

    `buckets` is a tuple in `FOURTH_DOWN_DISTANCE_BUCKETS` order, always full length.

    Add a `TestEstimateFourthDownRates` class to `tests/test_features_mutations.py` following
    the file's existing class-per-function convention, with hand-built polars frames (or
    `canonical_plays` with `overrides`) covering: bucket assignment at every boundary
    (yards_to_go 1, 3, 4, 6, 7, 10, 11, 25); a 4th-down touchdown with `first_down == 0` counted
    as a conversion; `no_play` and `penalty == 1` rows excluded from attempts; `down == 0` PAT
    rows excluded; an empty bucket yielding `attempts == 0, rate is None, ci is None` and not
    raising; the returned `buckets` tuple always having `len(FOURTH_DOWN_DISTANCE_BUCKETS)`
    entries; and `ci` bracketing `rate` for a populated bucket.
  </action>
