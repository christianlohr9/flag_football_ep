<objective>
Compute REQ-S1-13's own-team efficiency data: EPA by formation, play-call and route, EPA per QB
and receiver, YAC shares, drive success, and the basic defense section CONTEXT adds on top.

Purpose: this is the internal half of the coaching products — where the staff sees what their
own offense actually produces. The locked 1.3 contract says EPA for historical plays must come
from out-of-fold predictions (a model that never saw that play's game), because in-sample EPA
would flatter the team's own numbers exactly where the staff is least able to notice.
Output: `reports/own_team.py` producing an `OwnTeamReportData`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model predictions → own-team self-assessment | in-sample EPA would systematically flatter the team's own numbers; this is the one report where the reader cannot sanity-check the bias |
| hand-charted player spellings → per-player rankings | a mis-merged or split identity attributes production to the wrong athlete |
| own-team report content → repository / sharing | player names are PII |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.4-36 | Tampering (data integrity) | in-sample EPA presented as honest own-team performance | mitigate | `attach_epa` joins persisted out-of-fold predictions for historical plays and applies the champion join only to the OOF-unmatched subset; a conflicting-value test asserts OOF wins and no play is coalesced |
| T-1.4-37 | Tampering (data integrity) | reusing the canonical `drive_success` column, nulling out every non-legacy game | mitigate | drive outcomes are derived fresh per drive from `touchdown`/`interception`/4th-down/half flags; asserted by an all-null-`drive_success` regression test and a `grep` acceptance criterion |
| T-1.4-38 | Spoofing (identity) | an unmapped or mis-mapped player spelling silently merging or splitting athletes | mitigate | `map_players` never fuzzy-matches; unmapped spellings pass through verbatim and are surfaced as a warning list the page must render |
| T-1.4-39 | Denial of service | a missing player-mapping file or missing OOF parquet aborting the report run | mitigate | both are caught and turned into notices with an empty mapping / no historical plays; asserted in tests |
| T-1.4-40 | Information disclosure | the own-team report (player names, PII) committed or shared beyond the staff | mitigate | `reports/` is git-ignored (plan 01, T-1.4-02); distribution beyond that is an operational control outside this codebase — accepted |
