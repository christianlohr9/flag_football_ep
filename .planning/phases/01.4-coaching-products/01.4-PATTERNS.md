### `src/flag_football_ep/charts/fourth_down.py` (utility, transform)

**Analog:** `src/flag_football_ep/charts/pat_breakeven.py` (full file, 117 lines — read in one pass)

**Module-level docstring + headless-Agg-before-pyplot convention** (lines 1-23):

```python
    matplotlib.use("Agg")
    import matplotlib.pyplot as plt

```
`fourth_down.py` must set `matplotlib.use("Agg")` inside the render function, before
`import matplotlib.pyplot as plt`, exactly like this — never at module import time (mirrors
`model/evaluate.py`'s convention too).

**Render-function signature + return contract** (lines 26-89): a `render_fourth_down(...)  ->
"Figure"` function that never calls `plt.show()`, never saves — building, annotating and
`fig.tight_layout()`-ing a single `Axes`, then `return fig`. `write_*` is a separate function.

**Write-once-guard + close-in-finally pattern** (lines 92-117):
```python
def write_pat_breakeven(
    baselines: PatBaselines, out_path: Path, overwrite: bool = False
) -> Path:
    out_path = Path(out_path)
    if out_path.exists() and not overwrite:
        raise FileExistsError(
            f"refusing to overwrite existing PAT break-even chart: {out_path}"
        )
    out_path.parent.mkdir(parents=True, exist_ok=True)

    fig = render_pat_breakeven(baselines)
    try:
        fig.savefig(out_path)
    finally:
        import matplotlib.pyplot as plt
        plt.close(fig)
    return out_path
```
Copy this `write_*` shape verbatim for `write_fourth_down` (standalone-PNG use case, e.g. a
future `ffep fourth-down` command) — but see the Shared Patterns section below: the *report*
pipeline should call `render_fourth_down` directly and go through `reports/render.py`'s
`fig_to_data_uri` helper instead of `write_fourth_down`, per RESEARCH Pattern 1/Pitfall 6.

**Small-sample CI reuse:** `fourth_down.py`'s conversion-rate-by-distance bars must reuse
`scipy.stats.binomtest(...).proportion_ci()` the same way `estimate_pat_baselines` does
(`features/mutations.py` lines ~175-176) — do not hand-roll a normal-approximation CI.

**Analog 1:** `src/flag_football_ep/charts/pat_breakeven.py` (Agg convention, Figure-return

**Analog 2:** `src/flag_football_ep/model/evaluate.py::render_reliability_figure` (lines

```python
def render_reliability_figure(curves: Sequence[ReliabilityCurve], title: str) -> "Figure":  # noqa: F821
    import matplotlib
    matplotlib.use("Agg")
    import matplotlib.pyplot as plt

    n = len(curves)
    fig, axes = plt.subplots(1, n, figsize=(4 * n, 4), squeeze=False)
    for ax, curve in zip(axes[0], curves):
        ax.plot([0, 1], [0, 1], linestyle="--", color="gray", label="perfect calibration")
        ax.plot(curve.prob_pred, curve.prob_true, marker="o", label=curve.name)
        ax.set_xlabel("mean predicted probability")
        ax.set_ylabel("observed frequency")
        ax.set_title(curve.name)
        ax.legend(fontsize="small")
    fig.suptitle(title)
    fig.tight_layout()
    return fig
```
For the annotated WP line (per-game, markers at top-|EPA| swings + a synthetic-time-flag
label), follow `render_pat_breakeven`'s `ax.annotate(...)` calls (lines 59-64, 74-82) for the
annotation-with-`xytext`-offset idiom, and this function's `ax.plot(..., marker="o", ...)`

text annotation/title suffix (e.g. `ax.set_title(f"{title} (synthetic clock)")`), not a
per-row column lookup — `prepare_wp_data`'s production path (`real_clock=False`, the only
path `score_plays`/`ffep report` ever calls) is unconditionally synthetic today
(`features/mutations.py` lines 391-427), so there is no per-play boolean to join.

**Data source for the WP line:** `home_wp`/`wpa` columns from `add_wp_variables`

**Analog:** `src/flag_football_ep/features/mutations.py` (930 lines — read targeted sections

```python
two_point_ci = binomtest(two_point_successes, two_point_attempts).proportion_ci()
```

Every tendency/efficiency rate cell in `opponent.py`/`own_team.py` (formation×down&distance,
route distribution, play-call by score state, 4th-down/PAT) must carry `(rate, n, ci)` in this
same shape — a small `@dataclass` per cell type, mirroring `PatBaselines`, is the right
pattern to copy, not a bare float. This directly satisfies CONTEXT's "every rate carries its

**Field-zone / score-state bucketing:** no existing zone-bucket helper in `mutations.py`
today — Open Question 1 in RESEARCH flags this as new derivation work. Follow the module's
own `pl.when(...).then(...).otherwise(...)` chained-condition style used throughout
`add_ep_variables`/`add_wp_variables` (module is polars-`when/then` idiomatic end to end) for
the 3-zone + red-zone bucket and the trailing/close/leading score-state bucket, rather than a
Python-level loop.

**Out-of-fold EPA join (own_team.py's EPA source, locked 1.3 decision):** join key and column
contract from `model/evaluate.py::oof_frame` docstring (lines ~300-309): `(game_id, play_id)`
join key, EP columns = `EP_PROB_LABELS` (hyperparams.py), WP column = `"wp"`
(`WP_PROBABILITY_COLUMN`). Historical plays: read `oof_predictions_ep.parquet` /
`oof_predictions_wp.parquet` under `config.paths.processed` and left-join onto `plays.parquet`
on `(game_id, play_id)`. New games: read `plays_scored.parquet` (already has `ep`/`epa`/`wp`
columns from `score_plays`, see `model/score.py` lines 248-260) — `own_team.py` must pick the
right EPA source per play (historical → OOF, new → champion-scored), never mix the two for the
same play.

**Drive-outcome breakdown (Pitfall 4 — do NOT reuse `drive_success`):** derive TD / turnover /
downs / half-end fresh, per drive, from `touchdown`, `interception`, `down`==4 non-conversion,
and `half` boundary flags in `canonical.py`'s `CORE_COLUMNS` (lines 17-62), grouped by
`drive_id` within `game_id` — `drive_success` (in `NULLABLE_EXTRAS`, line 91) is populated
only for the `legacy` source and has different (binary) semantics; a plan that aggregates it
directly will silently null out every non-legacy game.

**Roster/player-mapping join (own_team.py only):** see `reference.py` pattern below — apply
`map_players` (new function, modeled on `map_teams`) to `thrown_by`/`received_by`/jersey
columns before any per-player rollup; unmapped names must render as-is with the loud warning
list CONTEXT locks, never raise and never silently drop.

**Schema-typed loader with duplicate-key guard** (lines 49-53, 114-129):

```python
_TEAM_MAPPING_SCHEMA: dict[str, pl.DataType] = {
    "source": pl.Utf8,
    "source_team": pl.Utf8,
    "canonical_team": pl.Utf8,
}

def load_team_mapping(path: Path) -> pl.DataFrame:
    """Load `source,source_team,canonical_team`. Rejects duplicate (source, source_team)."""
    df = _read_reference_csv(path, _TEAM_MAPPING_SCHEMA)
    if df.height:
        dupes = (
            df.group_by(["source", "source_team"])
            .agg(pl.len().alias("n"))
            .filter(pl.col("n") > 1)
            .select(["source", "source_team"])
            .rows()
        )
        if dupes:
            raise ValueError(f"duplicate (source, source_team) pair(s) in {path}: {dupes}")
    return df
```

```python
    if unmapped:
        details = "; ".join(...)
        raise UnmappedTeamError(f"unmapped team label(s): {details}")
    ...
```
`map_players` copies the same unmapped-collection loop and `lookup = dict(zip(...))`
construction, but instead of `raise UnmappedTeamError`, it must (a) leave the unmapped value
as-is in the output column (`.replace(lookup)` on polars already does this for keys absent
from the mapping — no `.otherwise` needed, matching the "appear as-is" requirement) and (b)
return the sorted-unmapped list alongside the mapped frame (e.g. a small `PlayerMappingResult`
dataclass with `frame: pl.DataFrame` and `unmapped: list[str]`) so `own_team.py`/`build.py` can
render the "prominent warning" block. This is the one place this phase's reference-loading code
should diverge from `map_teams`'s raise-on-unmapped precedent — call it out explicitly in the
plan, don't silently copy the exception-raising branch.

**`load_group_opponents`:** same `_read_reference_csv`-with-schema shape as
`load_sportapp_games` (lines 132-134, simplest loader in the file — no dedup/validation logic
at all): `{"canonical_team": Utf8, "team_name": Utf8}` per RESEARCH Open Question 2's
