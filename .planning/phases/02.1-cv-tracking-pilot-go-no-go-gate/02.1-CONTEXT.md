# Phase 2.1: CV Tracking Pilot (Go/No-Go Gate) - Context

**Gathered:** 2026-08-24
**Status:** Ready for planning

<domain>
## Phase Boundary

One scrimmage proves (or disproves) that the drone → XY-coordinates pipeline works, closing Milestone 1's Strand-2 half with an explicit gate decision (REQ-S2-02). The full pilot chain on the best available drone material: zero-shot pre-labels (Grounding DINO) → CVAT+SAM2 correction of ~300–500 frames (`player`, `referee`, no ball) → RF-DETR-Small fine-tune → OC-SORT tracking + SigLIP/UMAP/KMeans team clustering → manual 4–8-point homography → XY output in field coordinates + top-down radar demo → go/no-go recorded against C-09 (≥ 90% of a play trackable without ID switch, position error ~≤ 1 m, inference < 1 h/game). A clear miss routes back to Phase 2.0 (capture setup), never to more training labels (D-06).

**Material reality this phase works with:** the only drone material is 61 Hudl-re-encoded per-play clips (1920×1080, 30 fps, ~10.3 s each, ~10.5 min total) from the friendly GER vs Panama Rojo 2026-05-16 — registered in `data/reference/video_inventory.csv`, no Hudl-PBP for that game, capture altitude/hover positions unknown. The capture protocol rates 1080p above ~40 m as *Unbrauchbar* for the drone domain; the pilot proceeds anyway (user decision, see D-01 below) — if the material regime breaks detection, that is exactly what the gate exists to reveal.

Not this phase: dataset buildout / active learning / formal dataset versioning (2.2), snap detection and coaching metrics (2.3), player identity (2.4), broadcast footage (2.5), any Strand-1 changes.

</domain>

<decisions>
## Implementation Decisions

### Pilot material
- **D-01 Proceed on the Hudl re-encodes as-is.** Hudl is the sharing channel for everything — re-encoded per-play clips ARE the realistic material pipeline, so the pilot tests what will actually arrive, not a hypothetical raw-4K path. No hunting for originals, no waiting.
- **D-02 Clip index is the play key.** The friendly has no Hudl-PBP, so the pilot keys plays as `session_id` + clip number (pseudo play key). The `plays.parquet` join is Phase 2.3's job on properly charted games; the XY schema must stay forward-compatible with the `video_sync.csv` join (`game_id` + `play_id`) once charted games arrive.
- **D-03 Sighting pass first.** Nobody knows the hover position(s) or altitude. Step one of the plan is sighting all 61 clips: group by apparent camera position (drives homography count per D-05 project decision), estimate altitude/angle against the `docs/capture-protocol.md` tiers, record findings (inventory `notes` and/or the gate doc).
- **D-04 Soft time-box.** The ~2-weekend budget (C-04) is a guideline, not a guillotine: the gate is decided when the pipeline has run end-to-end on the pilot material, even if that takes longer. D-06 (project) still stands: a clear miss goes back to 2.0.

### Compute & tooling
- **D-05 Machine split: M5 Max primary, Dell CUDA for training.** User hardware is a MacBook M5 Max (128 GB unified memory) and a Dell Windows box with an 8 GB CUDA GPU. Everything interactive and CPU/MPS-friendly runs on the M5 Max (sighting, labeling, OC-SORT tracking, SigLIP team split, homography, radar rendering); the RF-DETR fine-tune runs on the Dell (best-supported CUDA path, no sleep risk); Colab Pro is the fallback if 8 GB VRAM pinches (C-10 budget).
- **D-06 CVAT self-hosted via Docker Compose on the M5 Max**, with the serverless (nuclio) add-on for SAM2-assisted annotation. Footage never leaves the user's machines — cleanest DSGVO posture. Apple-silicon Docker quirks are the known setup risk; researcher should verify the current CVAT+SAM2-on-ARM story.
- **D-07 Code lives in `src/flag_football_ep/cv/`** (exact subpackage name Claude's discretion) with a uv **optional dependency group** (e.g. `cv`: torch, rfdetr, boxmot, SAM2 tooling, SigLIP/UMAP deps). Core pipeline installs stay lean; a no-go leaves one deletable subpackage + extras group.
- **D-08 Full Strand-1 engineering conventions.** Config surface via `flag_football_ep.config.Config`, pytest coverage, Typer subcommands on the existing `ffep` entry point (e.g. `ffep cv sight/prelabel/train/track/calibrate/radar` — exact verbs Claude's discretion), MLflow logging. The user explicitly chose the full rigor over a throwaway pilot ("enterprise level" preference carried from 1.3).

### Gate measurement
- **D-09 Track continuity on all 61 clips, manual review.** Run tracking on every clip; eyeball each play's track overlay for a per-play pass/fail on ID switches plus per-track continuity %. The whole game is the denominator for the ≥ 90% claim — no cherry-picked subset.
- **D-10 Position error via a full ground-truth labeling week.** The user explicitly offered up to a week of labeling time (and more when needed). Build a dense hand-labeled evaluation set: player ground positions (feet) across many plays, field zones, and both teams; the gate reports measured median/p90 error in meters against these marks. Landmark reprojection (field features not used for calibration) additionally validates homography quality. This GT set doubles as a Phase 2.3 metric-validation asset. **D-06 (project) stays locked:** evaluation labeling inside the pilot is fine, but a clear gate miss means back to 2.0 — not more *training* labels.
- **D-11 Inference gate measured on the M5 Max** — the machine the pipeline will routinely run on. Extrapolate end-to-end throughput (detection + tracking + team split) from the ~10.5 min of clips to a full game (~40–60 min of footage); Dell/Colab numbers are reference only.
- **D-12 Gate decision recorded as a German doc in `docs/`** (style of the existing docs: criteria, measured numbers, verdict, consequences; filename Claude's discretion, e.g. `docs/pilot-gate-decision.md`). The radar reel goes to the HC asynchronously; the analyst demo carries a DEFERRED-ANALYST block (analyst unavailable). The demo is evidence attached to the decision, not a gate condition.

### XY output & artifacts
- **D-13 Coordinates in yards, Strand-1 aligned.** x in yards on the same axis `yardline_50` ∈ [0, 50] uses, y in yards across the field width. Coaching-native units everywhere; EPA joins read directly in 2.3. CV code converts internally from meters/pixels; the ≤ 1 m gate threshold is converted accordingly for reporting.
- **D-14 Parquet canonical + CSV export.** Tracks land under `data/processed/tracking/` as typed Parquet (same pattern and dtype-safety discipline as `plays.parquet`; gitignored); `ffep cv export` (or equivalent) emits CSV for eyeballing/external tools. This satisfies plan-2's "XY-CSV" wording without re-introducing the dtype-mismatch join risk `docs/sync-convention.md` warns about.
- **D-15 Labels + weights via MLflow + local COCO dir.** Labeled frames as a COCO export under a gitignored `data/labels/` (content hash noted in the training run); training runs, params, metrics, and weights logged to the existing MLflow store; the fine-tuned detector registered with the champion-alias pattern so `ffep cv` resolves weights exactly like Strand-1 scoring does (REQ-S1-11 spirit: nothing silently overwritten). Formal dataset versioning (Roboflow/DVC) stays in 2.2.
- **D-16 Radar demo = side-by-side showcase reel.** One mp4 of the 3–5 best plays: drone video with track overlays next to the synchronized top-down radar view. Instantly convincing for a non-technical HC; doubles as a stakeholder/hackathon pitch asset. Stored with the other gitignored video-derived outputs (exact location Claude's discretion).

### Claude's Discretion
- Exact subpackage name/layout under `src/flag_football_ep/`, `ffep cv` verb names, optional-dependency-group name.
- Frame-sampling strategy for the ~300–500 training labels across the 61 clips; train/val split discipline (clip-level, no leakage).
- Whether SAHI tiling is needed at 1080p — decide from the sighting pass (apparent object sizes), per C-05 per-domain inference settings.
- GT labeling tool/format for the position-error set (may reuse CVAT points or a lighter tool) and its storage layout.
- Homography point-picking tool and calibration storage format (per hover position, re-usable by 2.3).
- Gate-doc filename and exact structure; radar reel rendering details (layout, fps, annotations).
- Extrapolation formula for the < 1 h/game inference number (documented in the gate doc).

- "Hudl is for sharing everything" — the re-encode pipeline is not a degradation to work around but the actual production path; the pilot must be honest about it.
- The user offers real labeling capacity: "I'm open to label some footage for a week or any time given" — plans can budget generous *evaluation* labeling (GT positions) without guilt; training-label escalation past ~500 frames stays gated by D-06.
- The user has an annual hackathon with "massig GPU power" and wants a challenge for it — see Deferred Ideas; the showcase reel (D-16) intentionally doubles as pitch material.
- Full Strand-1 engineering rigor was an explicit choice over a cheap throwaway pilot — plan waves accordingly (this is not a notebooks-only phase).
