# Phase 02.1 Plan 11: Champion-Resolved Detector Inference & Runtime Benchmark Summary

**`cv.detect.load_detector`/`detect_video` (champion-alias weight resolution, full-frame or SAHI-tiled per-frame inference with per-stage timing) and `cv.benchmark.extrapolate_game_runtime` (linear stage-timing extrapolation with a human-checkable formula), measured on the primary machine over three real clips: full-frame stays at ~39.7 of the 60-minute C-09 budget, SAHI blows past it at ~260.7 minutes, so `[cv] sahi` stays `false`.**

## Accomplishments

- `cv.detect.load_detector(config, run_id=None)`: resolves the `champion` alias via `registry.resolve_champion` by default (verified: `resolve_champion` is called with a monkeypatch), loads through `mlflow.pyfunc.load_model(f"runs:/{run_id}/model")`, accepts no filesystem weights path at all (`inspect.signature` asserts `{"config", "run_id"}` exactly, T-2.1-15), wraps any resolution/load failure in `WeightsNotFound` naming the run id and tracking store uri
- `cv.detect.detect_video(config, clip, model, *, resolution, sahi)`: opens the clip with `cv2.VideoCapture` eagerly (so `MissingClipError` raises synchronously, not on first iteration), yields one `DetectionBatch` per frame in order including empty ones (D-09 -- the whole game is the denominator), full-frame path runs one model call per frame while the SAHI path slices via `sahi.slicing.slice_image` per `config.cv.sahi_slice`/`sahi_overlap`, shifts each tile's boxes back to full-frame coordinates, and de-duplicates cross-tile double-counts with `supervision.Detections.with_nms`; every detection's `class_id` is validated against `cv.dataset.CLASS_NAMES`, raising `InvalidDetectionClass` naming the offending id and frame otherwise
- `DetectionRun.timings()`: a `StageTiming` accessor (`decode`/`detect`/`postprocess`) readable at any point during or after iteration -- verified non-zero on a real synthetic clip and on a real pilot clip
- `cv.benchmark.extrapolate_game_runtime(stages, footage_seconds, game_seconds)`: sums per-stage real-time factors (`stage.seconds / footage_seconds`) into a total factor, multiplies by `game_seconds`, returns a `BenchmarkResult` (`stages`, `footage_seconds`, `game_seconds`, `machine`, `extrapolated_game_minutes`, `formula`) whose `formula` string spells out the arithmetic with every actual number substituted; raises `InvalidBenchmarkInput` on a non-positive duration or empty `stages`; `ffep cv benchmark --tracks ... --game-minutes 50` (already wired by an earlier plan's CLI stub) runs end-to-end against a synthetic stage-timing Parquet
- Ran the champion detector over three real clips chosen from `data/reference/hover_positions.csv` to span the sighting pass's measured apparent-player-size range (clip 001, p50=25px smallest; clip 052, p50=30px median; clip 003, p50=61px largest), once full-frame and once SAHI-tiled, both at the approved `resolution=896`; fed the summed timings through `extrapolate_game_runtime` for a 50-minute game
- `docs/cv-setup.md`'s new `## Inferenz-Durchsatz` section (German) records the machine (`Apple M4 Max`/`platform.node()`), the measured table for both modes, the kept `[cv] sahi = false` decision with a one-sentence reason, and an explicit disclaimer that this three-clip sample is not the C-09 gate measurement (that comes from the full 61-clip run in plan 02.1-12, recorded in the plan 02.1-17 gate doc)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `RFDETRWrapper.predict` silently dropped the pyfunc `params` channel**
- **Found during:** Task 1, while designing `detect_video`'s resolution control path
- **Issue:** `cv/registry.py`'s `RFDETRWrapper.predict(self, context, model_input, params=None)` (plan 02.1-06) ignored `params` entirely, calling `self.model.predict(model_input)` unconditionally -- MLflow's pyfunc `params` side-channel exists precisely so a caller of a loaded model can pass per-call options through
- **Fix:** `self.model.predict(model_input, **(params or {}))` -- `None`/`{}` is a no-op, fully backward compatible (verified: all 14 existing `tests/test_cv_registry.py` tests still pass unchanged)
- **Files modified:** `src/flag_football_ep/cv/registry.py`
- **Commit:** `77a8fa0`
- **Caveat:** this alone does not make `resolution` controllable through the real champion model today -- MLflow's own outer `PyFuncModel.predict` drops `params` before they reach this wrapper unless a `ModelSignature` `params_schema` was declared at registration time (`register_detector_model` does not declare one). Documented as a known follow-up in `_call_model`'s docstring and in Decisions above, not fixed here (registration-time change, outside this plan's files).

**2. [Rule 1 - Bug] `sv.Detections.merge` raised on conflicting per-tile metadata in the SAHI path**
- **Found during:** Task 3's real three-clip SAHI throughput sample (first real, non-synthetic exercise of `_detect_tiled`)
- **Issue:** RF-DETR's real `predict(..., include_source_image=True)` (the pyfunc wrapper's default) attaches the entire input crop under `metadata["source_image"]` plus a `data["source_shape"]` entry; every SAHI tile has a different crop, so `sv.Detections.merge([...])` raised `ValueError: Conflicting metadata for key: 'source_image'` the moment two tiles' detections were merged. Not reproducible with the fake test model (which never populates `.metadata`/`.data`) -- only surfaced against the real model.
- **Fix:** `_call_model` now strips `.metadata = {}` / `.data = {}` off every `Detections` object it returns, before any confidence filtering or merging -- `DetectionBatch` never used either field, so this is also a memory-hygiene improvement for the full-frame path (drops a whole embedded source-image array from every frame's detections)
- **Files modified:** `src/flag_football_ep/cv/detect.py`
- **Commit:** `6426aa9`
- **Verification:** re-ran the SAHI throughput sample after the fix -- all three clips completed; `tests/test_cv_detect_infer.py`'s existing SAHI-merge test (built against the fake model, which never exercised this path) still passes unchanged
