# Phase 02.1 Plan 05: Tracking Schema, Conform, Atomic Writer & CSV Export Summary

**The typed XY tracking Parquet contract (`cv.schema`) that the rest of Strand 2 writes to and reads from, keyed on `session_id`+`clip_number` (D-02) with nullable canonical-dtype `game_id`/`play_id` for the future `video_sync.csv` join, plus its atomic writer, a deterministic `synthetic_tracks` test factory, and a one-way CSV export (D-14).**

## Performance

- **Duration:** ~70 min (~25 min implementation; ~45 min full-suite verification queued behind CPU contention from three concurrent sibling parallel-executor worktrees each running their own full `pytest -q`)
- **Completed:** 2026-08-24T20:17:41Z
- **Tasks:** 3
- **Files modified:** 5 (2 created, 3 modified)

## Accomplishments

- `cv/schema.py`: `TRACKING_COLUMNS`/`TRACKING_SCHEMA` filled with the plan's 21-column `<interfaces>` contract; `game_id`/`play_id` dtypes read directly from `canonical.CORE_COLUMNS` (never re-declared), so the join-safety guarantee from `docs/sync-convention.md` holds by construction, not convention
- `conform_tracking`: reorders/casts to the declared schema, raises `MissingTrackingColumns` for an absent required column, `NullTrackingValues` for a null in a not-null column, `InvalidTrackClass` for any `class_name` outside `{"player", "referee"}` (the pilot detects no ball, C-12); absent nullable columns are materialized as typed nulls
- `write_tracking_parquet`: copies `pipeline._atomic_write_parquet`'s `.tmp` sibling + `os.replace` + `finally` cleanup verbatim; conform runs before any file operation, so a conform failure never touches a pre-existing file
- Dtype-mismatch join regression test inner-joins a conformed tracking frame against both a `video_sync.csv`-shaped fixture and a `plays.parquet`-shaped fixture (via `testing.canonical_plays`) on `["game_id", "play_id"]`, asserting non-zero height and naming `docs/sync-convention.md` in the failure message
- `flag_football_ep.testing.synthetic_tracks(...)`: deterministic, seeded tracking-frame factory mirroring `canonical_plays`'s shape; `with_teams`/`with_field_coords`/`with_pbp_keys` each fill exactly their own columns; output already passes `conform_tracking` unchanged
- `cv/export.py`: `export_tracking_csv` reads the Parquet, conforms it, writes a 4-decimal-precision CSV in `TRACKING_COLUMNS` order (nulls render as empty fields via polars' default); `TrackingParquetNotFound` names the missing path; the module never contains `read_csv`, keeping the export one-way per D-14
- `ffep cv export --help` (with `--extra cv` installed) shows the pre-wired `--tracks`/`--out` option surface from plan 02.1-02 unchanged

## Decisions Made

- `conform_tracking`'s not-null validation covers every `TRACKING_COLUMNS` entry outside `NULLABLE_COLUMNS` (14 columns: `session_id`, `clip_number`, `frame_index`, `timestamp_s`, `track_id`, `class_name`, `confidence`, `bbox_x1..y2`, `foot_x_px`, `foot_y_px`, `detector_run_id`, `tracked_at`), matching the `<interfaces>` block's per-column "not null" markings exactly rather than only the plan action text's illustrative 6-column example subset
- `conform_tracking` returns a `pl.DataFrame` only (no `ConformReport` tuple like `canonical.conform_to_canonical`) to match plan 02.1-02's fixed signature guard (`("df",)` in `tests/test_cv_contracts.py`)
- `synthetic_tracks`: track index 0 is the one referee per clip; remaining tracks are players moving at constant per-frame pixel velocity for monotone, checkable geometry; field-yard bounds (`_FIELD_LENGTH_YARDS=50.0`, `_FIELD_WIDTH_YARDS=25.0`) and frame-pixel bounds (`1920x1080`) are internal factory constants, not part of the public contract

## Issues Encountered

- The final `uv run pytest -q` full-suite verification took far longer than the implementation work itself (~45 min) because this machine was concurrently running full `pytest -q` suites for three sibling parallel-executor worktrees (plans 02.1-03, 02.1-04, 02.1-06), each independently verifying their own changes at the same time — pure CPU contention (12 concurrent pytest processes observed via `ps aux` at peak), not a defect in this plan's code.
