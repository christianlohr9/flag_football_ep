  <action>
Implement `TeamClassifier` following the roboflow/sports `sports/common/team.py` pattern quoted in
RESEARCH Pattern 2: `SiglipVisionModel.from_pretrained("google/siglip-base-patch16-224")` +
`AutoProcessor` for crop embeddings, `umap.UMAP(n_components=3)` for reduction,
`KMeans(n_clusters=2)` for the split. Do not implement jersey-colour HSV thresholding as a fallback —
RESEARCH explicitly rejects it because the capture protocol already flags exposure variance as a
domain risk.

Two deviations from the reference implementation, both required here:
1. Dependency injection for testability: the constructor signature is
   `TeamClassifier(device="cpu", embedder=None, seed=20260516)`. When `embedder` is `None`, the SigLIP
   model and processor are constructed lazily on first use (function-local import of `transformers`,
   never at module level). When `embedder` is provided, it is a callable `crops -> np.ndarray` of
   shape `(n, d)` and no SigLIP weights are ever downloaded. This is what lets the test suite run
   without a network round trip, per RESEARCH's Validation Architecture rule.
2. Determinism and sample-size guards: pass the seed to both `UMAP(random_state=...)` and
   `KMeans(random_state=..., n_init=10)`. `fit` raises a named exception (subclassing `CvError`) when
   fewer than 20 crops are supplied, naming the count and the minimum — UMAP on a handful of points
   produces meaningless projections and would silently poison every team assignment downstream.
   `predict` before `fit` raises a named exception too.

Batch the embedding extraction (default batch size 32) and mean-pool the last hidden state, matching
the reference implementation. Document in the module docstring that cluster label 0/1 is arbitrary —
which cluster is which team is decided by plan 02.1-12 when it joins the labels back to tracks, and
must never be assumed stable across clips fitted separately.

tests/test_cv_teams.py, all with an injected `embedder` returning synthetic feature vectors:
- two well-separated Gaussian blobs of 40 vectors each cluster into exactly two groups with the
  correct partition (compare as a set partition, not by label value, since 0/1 is arbitrary)
- the same input fitted twice with the same seed produces the same partition
- `fit` with 19 crops raises the named exception naming the count and the minimum
- `predict` before `fit` raises the named exception
- `predict` on unseen vectors from the same blobs assigns them to the matching clusters
- `import flag_football_ep.cv.teams` pulls in neither `transformers` nor `torch` (module-level import
  guard, same shape as the plan 02.1-02 contract guard)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/`Config` strings -> MLflow URIs | model name, alias and run id are interpolated into `models:/{name}@{alias}` and `runs:/{id}/...` |
| MLflow artifact store -> process | `mlflow.pyfunc.load_model` deserializes and executes stored model code |
| HuggingFace hub -> process | SigLIP weights are fetched from a remote registry on first real use |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2.1-03 | Tampering | model-name/alias/run-id interpolation in `cv/registry.py` | mitigate | Task 1 imports `_validate_model_name`/`_validate_alias`/`_validate_run_id` from the Strand-1 modules; acceptance criterion asserts `re.compile` appears nowhere in the file, so no second, looser validator can exist |
| T-2.1-15 | Spoofing | loading detector weights from an arbitrary filesystem path | mitigate | Task 1 exposes no path-based load: weights enter the store through `register_detector_model` inside an active run and leave it only via `resolve_champion`; `cv/detect.py`'s loader (plan 02.1-11) consumes a run id, not a path |
| T-2.1-16 | Tampering | MLflow registry silently no-op'ing against a `file:` store | mitigate | Task 1 routes every call through `mlflow_store.configure(config)`; acceptance criterion asserts `set_tracking_uri` appears nowhere |
