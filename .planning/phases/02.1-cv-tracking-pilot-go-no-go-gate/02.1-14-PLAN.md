<objective>
Produce the evidence for C-09's first gate criterion: a watchable track overlay for every clip,
automatic continuity statistics to steer the review, and a human pass/fail verdict per play recorded
against the full 61-clip denominator.

Purpose: D-09 is explicit — tracking runs on all 61 clips and the per-play verdict is a human eyeball
judgement on ID switches, with the whole game as the denominator. Automatic metrics can prioritise
that review; they cannot substitute for it, because "tracked without an ID switch" is a visual
property this pipeline has no ground truth for.
Output: `cv/overlay.py`, `cv/continuity.py`, `data/reference/continuity_review.csv` with verdicts, and
the measured continuity percentage.
</objective>

  <action>
Implement `render_track_overlay(config, clip, tracks, out_path)`: decode the clip with
`cv2.VideoCapture`, and for each frame draw every track row belonging to that `frame_index` — the
bounding box, the `track_id` as text, and the ground-contact point as a filled dot. Colour by
`team_id` (two distinct colours), with a third colour for `class_name == "referee"` and a fourth for a
null `team_id`, and burn a small legend plus the clip number and frame index into the corner so a
reviewer always knows what they are looking at. Write with `cv2.VideoWriter` at the source fps to
`out_path`, and return the path.

Follow the repo's render/write split: a pure `draw_frame(frame, rows, config)` function returning the
annotated array, and the writer wrapper around it. That keeps the drawing testable on a single numpy
array without producing a video file.

Output location is `config.paths.labels / session_id / "overlays"` — overlays are rendered player
footage and therefore PII, so they belong under the gitignored label tree, never under `reports/`.

Raise `MissingClipError` (from `cv.detect`) naming the path when the clip cannot be opened, and raise a
named exception when the tracks frame contains no rows for that clip number — rendering an overlay
with nothing on it would look like a rendering bug rather than a tracking gap.

tests/test_cv_overlay.py with `synthetic_tracks` and a generated clip:
- `draw_frame` returns an array of the same shape and dtype and differs from the input (something was
  drawn)
- boxes of two different `team_id` values produce two different colours at their box borders (assert
  on sampled pixels)
- a referee row and a null-`team_id` row each get their own colour
- `render_track_overlay` writes a file whose frame count matches the source clip
- an unopenable clip raises `MissingClipError` naming the path
- a clip number with no rows raises the named exception
