Implement `track_session(config, session_id, *, run_id=None, resolution=None, sahi=None, out_path=None)`:

- Load the detector once via `detect.load_detector(config, run_id)` and reuse it across clips. Record
  the resolved detector run id; every output row carries it in `detector_run_id`.
- Iterate clips from `frames.clip_paths(config, session_id)` in clip-number order. Each clip gets its
  OWN tracker instance from the `trackers` package (the OC-SORT class name recorded in
  `docs/cv-setup.md`) — track ids are per-clip because each clip is a separate play (D-02). Never
  import `boxmot`; do not write a Kalman filter or a Hungarian matcher.
- Per frame: feed `detect_video`'s detections into the tracker's update call and emit one output row
  per tracked box with `bbox_x1..bbox_y2`, `confidence`, `class_name`, `track_id`, `frame_index`,
  `timestamp_s = frame_index / fps`, `foot_x_px = (bbox_x1 + bbox_x2) / 2`, `foot_y_px = bbox_y2`
  (the ground-contact point the homography needs) and the clip's `hover_position_id`. Leave
  `team_id`, `x_yards`, `y_yards`, `game_id` and `play_id` null — later plans fill them.
- Containment: wrap each clip in its own try/except. A failure appends a notice naming the clip number
  and the exception message and the loop continues, exactly as `run_ingest` does per source. Append a
  notice as well for a clip that yields zero tracks, and for a clip whose decoded frame count
  disagrees with the inventory-declared duration by more than 2 frames. The gate needs to know which
  clips are missing and why; a silently short run would inflate the continuity percentage.
- Timing: accumulate per-stage seconds (decode, detect, track, write) across the session into
  `TrackResult.stage_seconds`, in the shape `cv.benchmark.extrapolate_game_runtime` consumes.
- Write through `schema.write_tracking_parquet` to
  `config.paths.tracking / f"{session_id}_tracks.parquet"` unless `out_path` overrides it, and return
  `TrackResult` with the path, clip count, distinct-track count, notices and stage timings.

Implement `assign_teams(tracks, config, *, crops_by_track)`:

- Fit ONE `TeamClassifier` per session, not per clip. KMeans cluster labels are arbitrary per fit, so a
  per-clip fit would produce team ids that mean different things in different clips and would silently
  corrupt any later possession or formation analysis. Sample crops evenly across clips, capped at a
  configurable number per track so one long track cannot dominate the fit, fit once, then predict for
  every crop.
- Assign per TRACK, not per frame: take the majority cluster over that track's predicted crops and
  write it as `team_id` on all of that track's rows. Record the majority share; a track whose majority
  share is below 0.6 gets `team_id` null plus a notice naming the track id, because a coin-flip
  assignment is worse than an admitted gap.
- `class_name == "referee"` rows always get `team_id` null, and referee crops are excluded from the fit
  — officials belong to no team and their crops would pull the clusters.
- Return the tracks frame with `team_id` filled, passed through `conform_tracking`, plus the notices.
- Document in the docstring that cluster label 0/1 is arbitrary: which integer means which team is
  read off the radar reel by a human (plan 02.1-16), and nothing downstream may assume a fixed mapping.

Extend tests/test_cv_teams.py with an injected embedder so no weights are downloaded:
- two clearly separated crop groups yield exactly two team ids, and every row of a given track shares
  one `team_id`
- referee rows have null `team_id` and their crops never reach the fit (assert with a spy embedder that
  records the crops it received)
- a track whose crops split evenly between clusters gets null `team_id` and produces a notice naming
  the track id
- a session-wide fit produces the same partition regardless of clip iteration order
- the returned frame still passes `conform_tracking`
