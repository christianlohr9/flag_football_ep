<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CVAT HTTP service -> network interfaces | a self-hosted annotation server serving PII footage |
| credentials -> process and logs | CVAT username/password resolved at runtime |
| CVAT export archive -> filesystem | a downloaded zip is unpacked into the working tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2.1-05 | Information disclosure | CVAT bound to a routable interface, exposing player footage on the LAN | mitigate | Task 1 verifies loopback-only binding and changes the published port to `127.0.0.1:8080` if the compose default is `0.0.0.0`; acceptance criterion asserts the LAN address does not answer |
| T-2.1-20 | Information disclosure | CVAT credentials in exception messages, echoed CLI output or tracked files | mitigate | Task 2 resolves credentials through `config.secret()` env vars, `.env.example` carries names with empty values, and a test asserts the password string is absent from the raised `DatasetError` |
| T-2.1-21 | Tampering | archive extraction from a CVAT export (path traversal via crafted zip entries) | mitigate | Task 2 extracts only into `out_dir` and rejects members whose resolved path escapes it; `DatasetError` names the offending member |
| T-2.1-22 | Tampering | vendoring the CVAT source tree into this repository | mitigate | Task 1 clones outside the repo; acceptance criterion asserts `git status` stays clean of a CVAT tree |
| T-2.1-01 | Information disclosure | frames uploaded to a hosted annotation service instead of the local one | mitigate | D-06 forbids hosted annotation; the host always comes from `config.cv.cvat_host` (loopback) and a test asserts no hard-coded URL exists in the module |
</threat_model>
