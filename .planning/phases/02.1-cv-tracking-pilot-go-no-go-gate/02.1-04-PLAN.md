<objective>
Build the manual-homography half of the pipeline: the pixel -> field-yards transform, its
hand-maintained per-hover-position calibration data, and the tooling that lets a human pick the
4-8 point correspondences. No video and no tracking output is needed for any of it, which is why this
runs in parallel with the sighting pass.

Purpose: D-05 (project) locks manual homography per hover position; D-13 locks yards as the output
unit; D-10 wants held-out landmarks as an independent quality check. All three are properties of this
module, and the calibration data it loads is reused unchanged by Phase 2.3 for any later footage from
the same hover setups.
Output: `cv/homography.py`, `data/reference/homography_calibration.csv`, `tests/test_cv_homography.py`.
</objective>

<interfaces>
Calibration CSV schema (`data/reference/homography_calibration.csv`), one row per
(hover position, landmark) — a small hand-maintained anchor CSV in the exact shape
`docs/sync-convention.md` names as the structural precedent (`half_boundaries.csv`):

hover_position_id : Utf8   — matches an ID in data/reference/hover_positions.csv
landmark          : Utf8   — a key from FIELD_LANDMARKS
source_x_px       : Float64
source_y_px       : Float64
target_x_yards    : Float64
target_y_yards    : Float64
use_for_fit       : Boolean — false = held out for the independent reprojection check (D-10)
notes             : Utf8

Field coordinate convention (D-13, established in plan 02.1-01):
x_yards 0.0 = west goal line, 50.0 = east goal line (negative / > 50 = end zones);
y_yards 0.0 = south sideline, 25.0 = north sideline. 1 m = 1.0936 yards.
</interfaces>

  <action>
Implement `ViewTransformer` exactly as the roboflow/sports `sports/common/view.py` pattern quoted in
RESEARCH Pattern 3 (`cv2.findHomography` for the fit, `cv2.perspectiveTransform` for points,
`cv2.warpPerspective` for full-frame warping), raising `CalibrationError` instead of a bare
`ValueError` when `cv2.findHomography` returns `None`. Do not derive a DLT solver by hand.
`transform_points` returns an empty array unchanged for empty input.

Add module constant `FIELD_LANDMARKS`: a function `field_landmarks(config) -> dict[str, tuple[float, float]]`
computing the canonical target coordinates from `config.cv.field_length_yards` (50.0),
`field_width_yards` (25.0) and `endzone_yards` (10.0). Include at minimum: the four playing-field
corners (`goalline_west_south`, `goalline_west_north`, `goalline_east_south`, `goalline_east_north`),
both end-zone back-line corners, the sideline intersections of the 10/20/30/40-yard lines on both
sidelines, and the two midfield sideline points. Landmark names are the vocabulary the calibration
CSV's `landmark` column must use — an unknown landmark name is a load-time error.

Implement `load_calibration(path)` on the `reference._read_reference_csv` pattern: typed
`schema_overrides` for every column in `<interfaces>`, `MissingReferenceFile` when absent, a
header-only warning via `warnings.warn` when empty. Validate on load and raise `CalibrationError`
naming the offending `hover_position_id`:
- fewer than 4 rows with `use_for_fit = true` for a hover position
- any `landmark` not in `field_landmarks(config)`
- a `target_x_yards`/`target_y_yards` pair that disagrees with `field_landmarks` for that landmark
  by more than 0.01 yards (the CSV must not silently redefine the field)
- `source_x_px`/`source_y_px` outside the frame bounds of the inventory-declared resolution
- a fit point set whose points are collinear (rank of the centred coordinate matrix < 2 or a
  near-zero convex-hull area) — this is the case where `cv2.findHomography` would otherwise return a
  garbage matrix rather than `None`

Implement `transformer_for(hover_position_id, calibration)`: filter to `use_for_fit = true` rows for
that ID, build the `ViewTransformer`, raise `CalibrationError` naming the ID when it is absent from
the calibration frame.

Implement `reprojection_error_yards(transformer, source, target)`: transform `source` pixel points and
return the per-point Euclidean distance to `target` in yards. Its intended use is the held-out
(`use_for_fit = false`) landmarks — document that in the docstring and note the 1 m = 1.0936 yards
conversion so the C-09 threshold is readable straight off the output.

Create `data/reference/homography_calibration.csv` as a header-only file with exactly the columns in
`<interfaces>` (plan 02.1-13 fills the rows after a human picks the points).

tests/test_cv_homography.py — pure math, no video, no model weights:
- a synthetic known homography (build 4 pixel corners from a known projective transform of the field
  corners) round-trips through `ViewTransformer.transform_points` to within 1e-3 yards
- `transform_points` on an empty array returns an empty array
- fewer than 4 fit points raises `CalibrationError` naming the hover position
- collinear fit points raise `CalibrationError` naming the hover position
- an unknown landmark name raises `CalibrationError` naming the landmark
- a `target_*_yards` value contradicting `field_landmarks` raises `CalibrationError`
- `field_landmarks` returns coordinates consistent with `config.cv` field dimensions (east goal line
  at x = 50.0, north sideline at y = 25.0, end-zone back line at x = -10.0)
- `reprojection_error_yards` returns all-zero for the exact synthetic case and a known non-zero value
  for a point perturbed by a known pixel offset
- the checked-in `data/reference/homography_calibration.csv` loads as a header-only typed frame with
  the exact expected column names

  <action>
Implement `pick_points(clip, hover_position_id, out_csv, *, at_second)` with two input modes, because
the interactive path cannot be assumed to work in every environment:

1. Reference-frame export (always runs first): extract the frame at `at_second`, draw a labelled
   pixel grid every 100 px with axis numbers, print the ordered landmark checklist from
   `field_landmarks`, and write the annotated frame to `data/labels/calibration/{hover_position_id}_ref.jpg`
   (gitignored — the frame shows players). This alone lets a human read pixel coordinates off the
   image and hand-edit the CSV, which is the documented fallback.
2. Interactive picking (when an OpenCV window is available): open the frame, consume left-clicks in
   the printed landmark order, ESC to finish, and append the collected rows.

Appending rows: read the existing calibration CSV if present, drop any rows for the same
`hover_position_id` (re-picking replaces, never duplicates), append the new rows, sort by
`hover_position_id, landmark`, and write atomically (tmp sibling + `os.replace`). Validate the result
by calling `load_calibration` on the written file before returning — a pick session that produced an
invalid set must fail loudly with `CalibrationError` rather than leaving a broken CSV behind. Return
the CSV path.

Guard the interactive branch: wrap the `cv2.imshow`/`setMouseCallback` path in a try/except for
`cv2.error` and fall back to reference-frame-only mode with a clear message naming the export path
and telling the operator to hand-edit the CSV. Never leave the process hanging on a window that
cannot open.

Extend tests/test_cv_homography.py with the non-interactive coverage: `pick_points` in
reference-frame-only mode writes the annotated JPEG and leaves an unchanged CSV; a direct row-append
helper replaces (does not duplicate) an existing hover position's rows; appending an invalid set
raises `CalibrationError` and leaves the previous CSV content byte-identical on disk. Use a synthetic
generated clip, never real footage.
