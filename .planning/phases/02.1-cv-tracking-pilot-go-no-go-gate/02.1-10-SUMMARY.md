# Phase 02.1 Plan 10: RF-DETR Detector Training & Cross-Machine Registration Summary

**`train_detector` (train+register / remote-train-only / registration-only / chunked-resumable) fine-tunes RF-DETR-Small on the corrected 304-frame pilot dataset via `rfdetr[train]`'s real PyTorch Lightning stack; the resulting checkpoint is registered as `cv_detector_model` version 1 and promoted to `champion` (run `87a8a5222f7a472787875e974d089c44`, `mAP_50=0.9571`, `mAP_50_95=0.8112`).**

## Performance

- **Duration:** ~100 min total session, of which ~41 min was real training wall-clock (2026-08-28T22:10:46Z–22:51:58Z, six 5-epoch chunks toward a 30-epoch target)
- **Tasks:** 3 planned (Task 2's human-action checkpoint was redirected to an in-session MPS training attempt instead of pausing)
- **Files modified:** 6 (1 created, 5 modified)

## Accomplishments

- `cv/detect.py::train_detector` implemented against `rfdetr==1.9.3`'s real, verified API (`RFDETRSmall.train()`/`.evaluate()` on a PyTorch Lightning stack, not the plan's illustrative snippet): dataset-layout preparation from the manifest's clip-level split, training, validation-split evaluation, `metrics.json`/`params.json`/checkpoint output, and MLflow registration inside one entry point across three modes (train+register, `--no-register` remote-training, `--from-artifacts` registration-only) plus a new `--resume` mode for chunked training.
- `tests/test_cv_detect_train.py` (13 tests, offline, monkeypatched `rfdetr.RFDETRSmall`, `tmp_path` MLflow store): dataset-layout train/valid split integrity, manifest-oversamples-dataset tolerance, nested-image-directory tolerance, abort-before-trainer-call on an invalid dataset, named resolution-validation exception, `register=True`'s single-run/dataset-hash/per-class-AP/no-alias behavior, `register=False`'s no-MLflow-call behavior, `from_artifacts`'s no-retrain/missing-file behavior, `resume` forwarding, and the CLI's `--dataset`-required-unless-`--from-artifacts` guard.
- Real end-to-end training executed on the primary machine via MPS (a documented, user-approved deviation from D-05 for this run): 30 epochs, `resolution=896`, `batch_size=4`, `grad_accum_steps=4` (effective batch 16, matching the planned Dell-box setting), chunked into 6 foreground `ffep cv train` calls of 5 epochs each via the new `--resume` flag (a full PyTorch Lightning checkpoint, optimizer/LR-scheduler state included, needed because a single 30-epoch call exceeds this environment's per-command wall-clock limit). No MPS-unsupported-operator fallback was ever observed despite `PYTORCH_ENABLE_MPS_FALLBACK=1` being set defensively.
- Final validation metrics (val split: 65 images / 10 clips): `mAP_50=0.9571`, `mAP_50_95=0.8112`, `AP_player=0.8266`, `AP_referee=0.7958` -- `params.json`'s `dataset_content_sha256` (`ab3a9673d61bc348d37ce298ba12d18b76395d1ade82a735c5b3d82d2e46aec0`) matches plan 02.1-09's recorded hash exactly, so the registered detector is provably traceable to that exact label set.
- Registered via `ffep cv train --from-artifacts` (MLflow run `87a8a5222f7a472787875e974d089c44`, `cv_detector_model` version 1, exactly one version -- no duplicate registration) and, per an explicit orchestrator decision (rationale recorded in `docs/cv-setup.md` and this SUMMARY's Decisions), promoted to `champion` via `ffep cv promote`. `resolve_champion` verified: resolves to `87a8a5222f7a472787875e974d089c44`.
- `docs/cv-setup.md`'s new `## Detector-Training` section records the machine/deviation, resolved settings, dataset hash, wall-clock, per-class metrics with their statistical-honesty caveats (single game, single annotator, `referee` class-frequency context), the MLflow run id, and the promotion rationale -- all in German, matching the doc's existing style.

## Deviations from Plan

### Auto-fixed Issues (Rules 1-3)

**1. [Rule 1 - Bug] `_prepare_dataset_layout` rejected a manifest that legitimately oversamples the dataset**
- **Found during:** the real training attempt against `data/labels/2026-05-16_FRIENDLY-GER-vs-PANAMA-ROJO-DRONE/corrected` (304 images) against the full 404-frame sampling manifest
- **Issue:** `validate_coco` requires an exact manifest/COCO image-set match; plan 02.1-09's corrected export legitimately covers only 304 of 404 sampled frames (a documented, sanctioned early-stop labelling session, D-04) -- the full manifest still lists all 404, so training against the real dataset raised `DatasetError` on 100 "missing" frames it never claims to cover.
- **Fix:** `_filter_manifest_to_dataset` restricts the manifest to the frames present in `coco_dir` before calling `validate_coco`; a genuine mismatch (a foreign COCO image name) still raises, since the filter only ever removes manifest entries.
- **Files modified:** `src/flag_football_ep/cv/detect.py`, `tests/test_cv_detect_train.py`
- **Commit:** `869e667`

**2. [Rule 1 - Bug] `_prepare_dataset_layout` assumed images sit directly beside `instances.json`**
- **Found during:** the same real training attempt, immediately after fix 1 -- `FileNotFoundError` copying the first image
- **Issue:** a real CVAT COCO export (`cv/dataset.py::export_cvat_task`) nests image files under `images/default/`, not directly beside `instances.json`; `dataset_hash` already tolerates this via `rglob`, but the dataset-layout builder did not.
- **Fix:** `_index_images_by_name` indexes every image file by basename via `rglob` before copying into the `train`/`valid` layout.
- **Files modified:** `src/flag_football_ep/cv/detect.py`, `tests/test_cv_detect_train.py`
- **Commit:** `7df320d`

**3. [Rule 1 - Bug] `ffep cv train --dataset` was unconditionally required**
- **Found during:** running Task 3's own `ffep cv train --from-artifacts <dir>` command as written in the plan
- **Issue:** `--dataset` was declared `typer.Option(...)` (required) regardless of mode, so the `--from-artifacts` registration-only path -- explicitly named in Task 3's own action text -- could not run through the CLI at all.
- **Fix:** `--dataset` defaults to `None`; a `typer.BadParameter` fires only when both `--dataset` and `--from-artifacts` are absent.
- **Files modified:** `src/flag_football_ep/cv/commands.py`, `tests/test_cv_detect_train.py`
- **Commit:** `33d0165`

### Auto-added Missing Functionality (Rule 2)

**4. [Rule 2] Added `--resume`/chunked-training support**
- **Found during:** a 1-epoch MPS smoke test confirmed real training worked but took ~2 minutes/epoch, meaning the full 30-epoch target would exceed this execution environment's ~10-minute per-command wall-clock limit.
- **Addition:** `resume: Path | None` threaded through `train_detector` into `RFDETRSmall.train(resume=...)` (rfdetr's own `TrainConfig.resume`, a full PyTorch Lightning checkpoint including optimizer/LR-scheduler state); `--resume` added to `ffep cv train`. `epochs` remains the total target across resumed calls -- Lightning restores `current_epoch` from the checkpoint rather than adding `epochs` more.
- **Files modified:** `src/flag_football_ep/cv/detect.py`, `src/flag_football_ep/cv/commands.py`, `tests/test_cv_detect_train.py`
- **Commit:** `c528b8d`
- **Rationale:** required for the redirected Task 2 (real training in this session) to be executable at all within the environment's constraints; additive to `train_detector`'s contract, does not change any existing call site's behavior.

- **Outcome:** Real MPS training succeeded end-to-end with no unsupported-operator issues; documented in `docs/cv-setup.md` as an explicit, one-off deviation from D-05 for this run, with the Dell/Colab paths left unchanged and still the documented default (Task 2's own printed command in prior turns remains valid and available).
