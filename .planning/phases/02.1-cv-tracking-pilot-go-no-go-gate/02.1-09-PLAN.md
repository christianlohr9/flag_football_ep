  <action>
Implement `validate_coco(coco_dir, manifest) -> DatasetStats`, raising `DatasetError` naming the
offender for each failure:
- `categories` is exactly `CLASS_NAMES` (`player`, `referee`) in that order — an extra class (for
  example a stray `ball`) is an error, not data to keep (constraint C-12)
- the `images[].file_name` set equals the manifest's frame set; report missing and extra file names
  separately in the message
- every annotation references an existing image id and an existing category id
- every bbox is `[x, y, w, h]` with `w > 0`, `h > 0` and the box fully inside the image dimensions
- `n_images` below 250 raises, naming the count and the ~300-500 target from REQ-S2-02
- `n_images` above 600 raises, naming D-06 explicitly: the pilot does not answer problems with more
  training labels; evaluation labelling (plan 02.1-15) is a separate, allowed budget
- both `train` and `val` splits (derived from the manifest's clip-level split) must contain at least
  one `player` box; a split with zero boxes raises naming the split

`DatasetStats` carries `n_images`, `n_boxes` per class, `split_counts` per split, and
`content_sha256`. Zero-annotation images are legal (a frame can genuinely contain no visible player
after correction) — count them and expose the count in `n_boxes` as a separate `_empty_images` entry
rather than failing.

Implement `dataset_hash(root) -> str`: a stable sha256 over the sorted list of
`(relative_file_name, sha256(file_bytes))` pairs for every image plus the canonical (sorted-key,
separator-normalised) JSON of the annotations. Two byte-identical datasets in different directories
must hash identically; a single flipped box must change the hash.

tests/test_cv_dataset.py on a synthetic COCO package built in tmp_path (tiny generated JPEGs, no real
frames): a valid dataset returns the expected `DatasetStats`; each listed failure mode raises
`DatasetError` with the offender in the message (one test per mode); `dataset_hash` is stable across
directories and changes when one bbox coordinate changes; zero-annotation images are counted, not
rejected.
  </action>
  <verify>
    <automated>uv run pytest tests/test_cv_dataset.py -q</automated>
  </verify>

    - A synthetic dataset with a third category raises `DatasetError` naming that category

  </acceptance_criteria>

  <how-to-verify>
This is the labelling session itself — the one step no automation replaces.

1. Open the CVAT task and work through the frames. For each frame: fix boxes the zero-shot model got
   wrong, delete false positives, add missed players, and set the `referee` label on officials.
2. Label consistently: box the full visible body including limbs, exclude the shadow, and box
   partially occluded players at their visible extent. Consistency matters more than perfection —
   the detector learns your convention.
3. If the SAM2 assist is available (see `docs/cv-setup.md` §SAM2-Status), use it for propagation
   inside a clip's frames; if not, the fallback is manual correction, which is what the pre-labels
   exist to shorten.
4. Do NOT add frames beyond the ones in the task. The ~300-500 training-label budget is capped by
   D-06 and enforced by `validate_coco` — a gate miss is answered by going back to Phase 2.0 capture
   setup, not by labelling more.
5. When done, save the job and mark it completed in CVAT.

Rough expectation: a few hundred frames at 5v5 plus officials is a multi-session job, not an
afternoon. D-04 makes the time box soft — take the time the work needs.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CVAT export archive -> filesystem | operator-triggered download unpacked into the working tree |
| corrected dataset -> git | annotated player frames are PII |
| dataset -> trained model provenance | an unrecorded dataset makes a model untraceable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2.1-23 | Tampering | a corrected dataset that silently disagrees with the frame sample it claims to be | mitigate | Task 1 `validate_coco` cross-checks the image set against the manifest and reports missing/extra names; Task 3 gates the pull on it |
| T-2.1-24 | Repudiation | a registered detector that cannot be traced to its training labels | mitigate | Task 1 `dataset_hash` + Task 3 recording it in `docs/cv-setup.md`; plan 02.1-10 logs the same hash as an MLflow param |
| T-2.1-25 | Tampering | quiet escalation past the D-06 training-label ceiling | mitigate | Task 1 raises `DatasetError` naming D-06 above 600 images; the checkpoint text states the rule to the operator |
| T-2.1-01 | Information disclosure | corrected frames and annotations | mitigate | Written under `data/labels/`, gitignored by plan 02.1-01; acceptance criterion asserts `git check-ignore` |
| T-2.1-21 | Tampering | path traversal from the CVAT export archive | mitigate | Handled in plan 02.1-08's `export_cvat_task` (members resolving outside `out_dir` are rejected) |
