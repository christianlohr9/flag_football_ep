# Phase 02.1 Plan 04: Manual Homography Calibration Summary

**Pixel-to-field-yards `ViewTransformer` (cv2.findHomography-backed), an 18-landmark field-coordinate vocabulary computed from config, a fully validation-on-load calibration CSV loader, and a reference-frame-export + opt-in interactive point-picking tool -- the entire manual-homography half of the CV tracking pilot, independent of any video/tracking output.**

## Accomplishments

- `ViewTransformer` ports the `roboflow/sports` `sports/common/view.py` pattern verbatim (`cv2.findHomography`/`perspectiveTransform`/`warpPerspective`), raising `CalibrationError` instead of a bare `ValueError` when `cv2.findHomography` returns `None`; `transform_points` returns an empty array unchanged for empty input
- `field_landmarks(config)`/`FIELD_LANDMARKS` compute the fixed 18-name landmark vocabulary (playing-field corners, end-zone back-line corners, 10/20/30/40-yard sideline intersections, midfield points) in field yards from `config.cv.field_length_yards`/`field_width_yards`/`endzone_yards` (D-13 axis convention)
- `load_calibration(path)` validates on load exactly as specified: unknown landmark names, target-coordinate disagreement with `field_landmarks` beyond 0.01 yards, negative source pixels, fewer than 4 `use_for_fit` points, and collinear/degenerate fit-point sets -- every failure names the offending `hover_position_id`
- `transformer_for`/`reprojection_error_yards` build a per-hover-position transformer from the calibration frame and measure reprojection error in yards for the held-out-landmark independent check (D-10)
- `pick_points` always exports an annotated pixel-grid reference-frame JPEG (the documented hand-edit fallback) and, only when explicitly opted into, attempts bounded interactive point picking; `_append_calibration_rows` writes atomically and validates before committing, so a pick session can never leave a broken CSV on disk (T-2.1-11)
- `data/reference/homography_calibration.csv` seeded header-only with the exact `<interfaces>`-specified columns
- 19 tests in `tests/test_cv_homography.py`, all math/synthetic-clip-only (no real footage, no model weights), well above both tasks' minimum test-count acceptance criteria (10 and 14)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Interactive picking safety bound**
- **Found during:** Task 2 implementation
- **Issue:** The plan's literal wording ("wrap the interactive branch in a try/except for `cv2.error`... never leave the process hanging") assumes `cv2.imshow`/`cv2.waitKey` reliably raise `cv2.error` when no real display/window manager is available. Empirically verified in this environment that `cv2.imshow`/`cv2.waitKey` succeed without error even without a genuine interactive session to click in, meaning a naive try/except implementation would silently open a window and loop indefinitely waiting for clicks that will never arrive -- a real hang risk (T-2.1-12), and specifically dangerous for automated test/CI runs.
- **Fix:** Gated the interactive attempt behind an explicit `FFEP_CV_CALIBRATE_INTERACTIVE=1` opt-in (default off, so every automated invocation is safe by construction) and additionally hard-bounded the pick loop to a fixed iteration/time cap regardless of opt-in state, so even a human operator's interactive session cannot hang past ~5 seconds without input.
- **Files modified:** `src/flag_football_ep/cv/homography.py`
- **Verification:** `tests/test_cv_homography.py::test_pick_points_reference_frame_only_mode_writes_jpeg_and_leaves_csv_unchanged` runs `pick_points` with no env var set and completes without opening a blocking window; `_pick_points_interactive`'s `max_wait_iterations`/`wait_ms` parameters are directly inspectable in the source
- **Committed in:** `a45b539` (Task 2 commit)
