# Phase 02.1 Plan 16: Radar View and Showcase Reel Summary

**`render_radar_frame`/`render_showcase_reel` implemented in `cv/radar.py` (7 new tests, all green); a real 5-play, 46.1s side-by-side showcase reel (drone footage + synchronised radar) rendered from clips selected by a written, reproducible rule from the continuity review, with `docs/pilot-accuracy.md`'s new `## Showcase-Reel` section stating plainly that the reel is demonstration evidence, not a measurement.**

## Accomplishments

- `render_radar_frame(tracks_at_frame, config, size_wh)`: draws the pitch (both goal lines, sidelines, end-zone back lines, 5-yard markers with numbers) from `config.cv.field_length_yards`/`field_width_yards`/`endzone_yards` with a single undistorted yards-to-pixels scale (`_pitch_geometry`), then plots each row with `overlay.py`'s team colour scheme plus a distinct marker shape (circle/triangle/square) for players/referees/null-team tracks. Rows with null `x_yards`/`y_yards` are skipped without raising.
- `render_showcase_reel(config, clip_numbers, tracks, out_path)`: resolves each clip's raw video via `cv.frames.clip_paths`, composes `overlay.draw_frame`'s annotated footage next to `render_radar_frame`'s radar half per frame under a header strip (clip number, play index, one-line caption), writes one continuous mp4 with 5 black separator frames between plays, and raises `NoFieldCoordinatesForClip` naming a clip that has no field-coordinate rows. Counts and logs (via `logging.warning`) any null-coordinate rows skipped across the reel, since the contract's fixed signature cannot return that count.
- `tests/test_cv_radar.py` (7 tests): requested-size shape, origin-corner pixel position, identical yards-to-pixels scale on both axes, four distinct marker colours (two teams + referee + null-team), null-coordinate rows skipped without raising, `render_showcase_reel`'s frame-count/width contract against real synthetic clips + a seeded `video_inventory.csv`, and the named exception for a coordinate-less clip.
- Selected 5 clips (11, 2, 6, 13, 4) from `data/reference/continuity_review.csv` by a written rule (verdict=pass, id_switches=0, sorted by `longest_track_frac` desc / `n_fragments` asc / `clip_number` asc, both hover positions represented) and rendered the real reel via `ffep cv radar`.
- `docs/pilot-accuracy.md` `## Showcase-Reel`: the selection rule verbatim, the chosen clips' continuity stats, the output path, duration (46.1s), frame-by-frame end-to-end verification notes, and the "best plays, not a measurement" sentence pointing back at the measured C-09 numbers.

### Scope Notes -- Honest Findings, Not Auto-Fixed

**1. Selection-rule tie-break needed beyond the plan's literal text**
- **Found during:** Task 2, applying the selection rule to the real `continuity_review.csv`.
- **What happened:** All 6 clips satisfying `verdict=pass, id_switches=0` are tied at `longest_track_frac=1.0` (every clip in the dataset is), and none carry a `reviewer_note` -- the plan's stated ranking criteria do not discriminate among them.
- **Handling:** Added `n_fragments` ascending then `clip_number` ascending as reproducible tie-breakers, documented verbatim (with rationale) in `docs/pilot-accuracy.md`'s new section, so the rule stays fully reproducible rather than an unstated judgment call.
- **Verification:** manually re-derived the ranking from `continuity_review.csv` and `hover_positions.csv` before rendering; the resulting 5 clips (11, 2, 6, 13, 4) cover both hover positions without needing the plan's described "swap in the missing hover position" fallback.

**2. Pre-existing, unrelated test failure discovered during the full `cv`-tagged suite run**
- **Found during:** Task 2 close-out sanity check (`uv run --extra cv pytest tests/ -q -k cv`).
- **What happened:** `tests/test_cv_continuity.py::test_continuity_review_csv_uses_comma_dialect` fails against the real, committed `continuity_review.csv` because a human reviewer's German free-text note (clip 3) contains a semicolon as ordinary punctuation, which the test's Hudl-dialect guard does not distinguish from a leaked `;`-delimited CSV.
- **Handling:** Not fixed (out of this plan's `files_modified` scope: neither the CSV, `continuity.py`, nor its test belongs to this plan). Logged to `deferred-items.md`.
- **Verification:** `uv run --extra cv pytest tests/ -q -k cv --deselect tests/test_cv_homography.py::test_pick_points_ref_jpeg_is_gitignored --deselect tests/test_cv_continuity.py::test_continuity_review_csv_uses_comma_dialect` is fully green (both deselected failures are pre-existing and unrelated to this plan; the homography one was already documented by plan 02.1-15).
