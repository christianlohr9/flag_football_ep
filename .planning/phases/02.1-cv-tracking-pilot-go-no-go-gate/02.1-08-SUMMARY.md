## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Docker Desktop would not start: corrupted VM disk-size setting**
- **Found during:** Task 1, first `docker info` check
- **Issue:** `engine linux/virtualization-framework failed to start: ensuring disk: cannot resize ".../Docker.raw" to 1422465MiB: truncate ...: permission denied` (~1.4 PB target, an implausible leftover value from a prior session)
- **Fix:** Docker Desktop's own error-recovery dialog triggered an automatic "Reset to factory defaults" (deleted its Application Support state and VM disk); relaunching afterward started the daemon cleanly. No project file was touched; this is Docker Desktop's own self-healing mechanism, recorded here because it happened during this task.
- **Files modified:** none (external application state only)
- **Verification:** `docker info` subsequently reports a healthy server section
- **Committed in:** n/a (no repo file changed by this fix)

### Scope Boundary — Honestly Recorded, Not Auto-Fixed

**2. Live CVAT instance could not be verified running in this session**
- **Found during:** Task 1, after Docker Desktop recovered
- **Issue:** Network throughput from this execution environment to github.com/Docker Hub measured ~24-36 KB/s (multiple `curl -w '%{speed_download}'` samples; `docker pull alpine:latest`, a ~3.6 MB image, took 2m29s for its single layer). The full CVAT stack pulls roughly ten images (postgres, redis, kvrocks, `cvat/server` -- amd64-only per RESEARCH Pitfall 1, `cvat/ui`, traefik, opa, clickhouse, vector, grafana), well into the gigabyte range; at the measured rate this would take ten to thirty hours.
- **Handling:** Per the plan's own instruction ("time-box the attempt... do NOT keep fighting it: record the exact error, and adopt the documented fallback"), the compose setup (clone, sparse-checkout, loopback override) was completed and verified statically via `docker compose config` (confirms no syntax errors and that only `127.0.0.1` bindings remain), but `docker compose up -d`, superuser creation, the live `curl 127.0.0.1:8080` acceptance check, and the real `ffep cv cvat-push` run against a running instance were **not** completed in this session. This is recorded verbatim in `docs/cv-setup.md`'s `### Start`/`### Apple-Silicon-Realitaet` sections with exact reproduction commands, rather than silently claimed done. Prior plans in this phase (`uv sync --extra cv`, several GB of PyPI packages including `torch`) completed without this constraint in a different session, so this reads as this specific session's environment, not the user's general internet connection.
- **Files modified:** `docs/cv-setup.md` (honest record)
- **Verification:** N/A -- explicitly not verifiable this session; `docs/cv-setup.md` gives the exact commands for a session with normal bandwidth to complete in minutes
