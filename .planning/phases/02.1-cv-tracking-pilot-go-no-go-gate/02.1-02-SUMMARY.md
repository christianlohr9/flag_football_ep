## Decisions Made

- Strengthened the lazy-import guard with a second check beyond the plan's literal wording (see key-decisions above) so the acceptance criterion ("adding `import cv2` to detect.py makes the guard fail") is actually true given `cv/commands.py`'s function-body-local import discipline
- `cv/registry.py` imports `mlflow.pyfunc` at module level (mlflow is core, not cv-extras) so `RFDETRWrapper` can genuinely subclass `mlflow.pyfunc.PythonModel`; all other heavy types across the 18 modules stay behind `TYPE_CHECKING`
- MLflow-routing docstrings in `registry.py`/`detect.py`/`track.py` paraphrase around the literal string `set_tracking_uri` to keep the `grep -rn 'set_tracking_uri' src/flag_football_ep/cv/` acceptance check a genuine code-only guard
