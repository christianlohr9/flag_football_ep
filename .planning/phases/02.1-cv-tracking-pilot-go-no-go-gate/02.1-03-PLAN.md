  <action>
Implement `sight_session(config, session_id, out_csv=None)`:

1. Hover-position grouping. For each clip, extract one frame near the clip start (t = 0.5 s) and one
   near the end, convert to grayscale, downscale to 64x36, and build a framing fingerprint. Group
   clips by pairwise normalized cross-correlation of the fingerprints against a threshold (start at
   0.97 and record the value used in the result notices); clips whose fingerprints correlate above
   the threshold share a `hover_position_id`. IDs are assigned deterministically as `hp-01`, `hp-02`,
   ... ordered by the lowest clip number in each group, so re-running produces identical IDs.
   Static-camera framing is what makes this work — a drone repositioning between drives shows up as a
   new group, which is exactly the D-03 question.

2. Apparent-size measurement. Per clip, run `cv2.createBackgroundSubtractorMOG2` over ~30 sampled
   frames spread across the clip (the camera is static, so foreground blobs are moving players),
   take connected components above a small area floor, and record the p10 and p50 of blob pixel
   HEIGHT. Discard components touching the frame border and components taller than 1/4 of frame
   height (scoreboard/stand artifacts). These are estimates — the result notices must state the
   method and the sample count so the doc can carry the caveat honestly.

3. Tier assignment. Map each clip to the `docs/capture-protocol.md` tier vocabulary
   (`Ideal`/`Brauchbar`/`Unbrauchbar`) using the resolution from the inventory row and the measured
   apparent size as the altitude proxy. Use the tier words verbatim from that document — do not
   invent a new vocabulary.

4. Write `data/reference/hover_positions.csv` with the header
   `clip_number,clip_path,hover_position_id,apparent_player_px_p10,apparent_player_px_p50,tier,notes`,
   `clip_path` repo-relative (same rule as `video_inventory.csv`), one row per clip, sorted by
   clip number, comma dialect. Write it atomically (tmp sibling + `os.replace`).

Implement `recommend_inference_settings(rows, config)` returning `InferenceRecommendation`:
p50 apparent height >= 40 px -> `resolution=672, sahi=False`; 20 px <= p50 < 40 px ->
`resolution=896, sahi=False`; p50 < 20 px -> `resolution=896, sahi=True`. `resolution` values must
stay multiples of 224 (valid under either documented RF-DETR divisibility rule). `rationale` states
the measured p50/p10, the threshold band hit, and — when `sahi=True` — cites RESEARCH Pitfall 4
(SAHI is enabled from measurement, never by default, and costs inference time against the
< 1 h/game gate).

tests/test_cv_sighting.py, all on synthetic frames generated with numpy/cv2 (never real footage):
two distinct synthetic backgrounds produce two hover groups and one background produces one;
group IDs are stable across a re-run and across input ordering; a synthetic frame sequence with
moving rectangles of known height recovers that height within +/- 15% at p50; each recommendation
band returns the documented `(resolution, sahi)` pair and every returned resolution satisfies
`% 224 == 0`; the written CSV has the exact header and no absolute paths.
  </action>
