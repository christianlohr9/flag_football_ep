  <action>
Implement `load_detector(config, run_id=None)`: when `run_id` is `None`, resolve it through
`registry.resolve_champion(registry.detector_model_name(config), config)` — the champion alias is the
default, exactly as `model/score.py` documents for EP/WP. Load the model with
`mlflow.pyfunc.load_model(f"runs:/{run_id}/model")` after `mlflow_store.configure(config)`, wrapping
failures in `WeightsNotFound` naming the run id and the tracking store URI. Accept no filesystem path
argument at all — a weights path is not a supported input (T-2.1-15).

Implement `detect_video(config, clip, model, *, resolution, sahi)` as a generator yielding one
`DetectionBatch` per frame in frame order:
- decode with `cv2.VideoCapture`, raising `MissingClipError` naming the path when the clip cannot be
  opened, and stop cleanly at the end of stream (never spin on a failed read)
- full-frame path (`sahi=False`): run the model at `resolution` and convert its output to a
  `supervision.Detections` before building the `DetectionBatch`, so the whole pipeline speaks one
  detection type
- tiled path (`sahi=True`): slice with `sahi` using `config.cv.sahi_slice` and
  `config.cv.sahi_overlap`, then merge across tiles. RESEARCH Pitfall 4 documents an open tuning gap
  for RF-DETR at large slice sizes — start from the documented defaults, and record the slice size,
  overlap and resulting per-frame time in the result so the cost is visible rather than absorbed
- filter detections below a confidence floor read from the model's own default, and map class ids to
  `cv.dataset.CLASS_NAMES` names, raising a named exception if the model emits a class id outside
  that vocabulary
- yield frames with zero detections as empty batches rather than skipping them — the whole game is
  the denominator (D-09), and a skipped frame silently shortens it
- accumulate `StageTiming` entries (decode, detect, postprocess) and expose them through a
  `detect_video`-level timing accessor the caller can read after the generator is exhausted

tests/test_cv_detect_infer.py, offline with a fake model object (a callable returning fixed boxes) and

- an unopenable clip raises `MissingClipError` naming the path
- a class id outside `CLASS_NAMES` raises the named exception naming the id
- the SAHI path is exercised with a stubbed slicer and produces merged boxes whose count and

- the timing accessor reports non-zero decode and detect stages

Implement `extrapolate_game_runtime(stages, footage_seconds, game_seconds)`:
compute the per-stage real-time factor `stage.seconds / footage_seconds`, sum them into a total
factor, multiply by `game_seconds`, and return a `BenchmarkResult` carrying the per-stage timings, the
inputs, `extrapolated_game_minutes`, and a `formula` string that spells the arithmetic out with the
actual numbers substituted — the gate doc quotes this string verbatim, so it must be readable by a
human who was not in the room.

State the assumptions in the docstring and mirror them into `formula`:
1. runtime is linear in footage duration at fixed resolution and settings;
2. the pilot's 61 per-play clips exclude dead time between plays, so a continuous game recording of
   `game_seconds` is the honest denominator for C-09 — not the 10.5 minutes of clipped footage;
3. `game_seconds` defaults to 3000 (50 minutes of continuous recording) and is a CLI option, because
   the real number depends on the capture protocol's battery-swap regime;
4. the measurement machine is the primary Mac (D-11); Dell/Colab numbers are reference only, and the
   result records which machine produced the timings.

Raise a named exception when `footage_seconds` or `game_seconds` is non-positive, or when `stages` is
empty — an extrapolation from nothing is worse than no number.

tests/test_cv_benchmark.py, pure arithmetic:
- a known stage set and footage duration produce the exact expected `extrapolated_game_minutes`
- the `formula` string contains every input number and the result
- doubling `game_seconds` doubles the extrapolation
- non-positive inputs and an empty stage list raise the named exception
- the machine identifier appears in the result
  </action>
