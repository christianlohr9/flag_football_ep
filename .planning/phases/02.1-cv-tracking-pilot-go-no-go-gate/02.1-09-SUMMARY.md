# Phase 02.1 Plan 09: Corrected Training Dataset and Content Hash Summary

**A validated, hashable 304-frame CVAT-corrected COCO dataset for the pilot session (5962 player / 652 referee boxes, both hover positions represented), built by `validate_coco`/`dataset_hash` in `cv/dataset.py` and recorded in `docs/cv-setup.md` for plan 02.1-10's MLflow provenance.**

## Performance

- **Tasks:** 3 (Task 2 was the blocking human-labelling checkpoint)
- **Files modified:** 3 (1 created, 2 modified)
- **Automation runtime:** `ffep cv sample` (fast), `ffep cv prelabel` (~9 min, Grounding DINO transformers backend on CPU, HF weights downloaded fresh), `ffep cv cvat-push`/`cvat-pull` (network-bound, foreground), `ffep cv dataset` (fast)

## Accomplishments

- `validate_coco(coco_dir, manifest) -> DatasetStats` in `cv/dataset.py`: enforces the exact `player`/`referee` vocabulary in order (C-12), image-set equality against the manifest (missing/extra reported separately), annotation referential integrity, non-degenerate in-bounds boxes (1.0px epsilon for CVAT's polygon-derived sub-pixel rounding), the `[250, 600]` REQ-S2-02/D-06 image-count band, and per-split `player`-box coverage. Zero-annotation images are counted under `_empty_images`, not rejected.
- `dataset_hash(root) -> str`: sha256 over every image file's bytes plus canonicalized annotations JSON, stable across directories, sensitive to a single bbox coordinate change.
- Fixed `export_cvat_task` (plan 02.1-08) to extract directly into the caller's `out_dir` rather than a `task_{id}` subdirectory, so `cvat-pull --out X` followed by `ffep cv dataset --coco X` works without a nested-path guess.
- `tests/test_cv_dataset.py`: 14 tests (category vocabulary, image-set equality, annotation integrity, bbox bounds including the sub-pixel-tolerance case, split coverage, the real 250/600 floor/ceiling with D-06 in the message, hash stability/sensitivity) — all offline against synthetic fixtures.
- Full pilot round trip executed against the real 61-clip session: `ffep cv sample` (404 frames, manifest), `ffep cv prelabel` (404 frames, 8454 zero-shot boxes, 0 zero-detection frames), `ffep cv cvat-push` (CVAT task id 1), human labelling session in CVAT (304/404 frames corrected, operator called it done on quality-over-quantity grounds), `ffep cv cvat-pull` (404 frames retrieved), trim to the 304 corrected frames, `ffep cv dataset` (304 images, 5962 player / 652 referee boxes, 0 empty images, train 239 / val 65, `content_sha256=ab3a9673d61bc348d37ce298ba12d18b76395d1ade82a735c5b3d82d2e46aec0`).
- `docs/cv-setup.md`'s new `### Datensatz` subsection: CVAT task id/URL, the 304/404 corrected range, full dataset counts, hover-position distribution of the 304-frame subset (hp-01: 164 frames/24 clips, hp-02: 140 frames/22 clips — both well represented, 54%/46% close to the original 49%/51% clip split), the content hash, the labeling conventions the operator actually applied, and the single-annotator/no-IAA caveat.

## Decisions Made

- `export_cvat_task` extracts directly into `out_dir` (not a `task_{id}` subdirectory) — a Rule 1 fix to plan 02.1-08's code, made here because `dataset.py` is this plan's file and the mismatch directly blocked Task 2/3's stated CLI flow (`cvat-pull --out X` then `dataset --coco X` expects `X/instances.json`, not `X/task_{id}/instances.json`).
- `validate_coco`'s bbox-in-bounds check carries a 1.0px epsilon tolerance (Rule 1: an overly strict zero-tolerance comparison rejected real, correctly-boxed annotations). Measured on the real corrected dataset: 68/6614 annotations (~1%) sat up to 0.26px outside the frame, always at the top edge, always from frames CVAT exported as polygon-derived boxes (frames ≲103, per the operator's own labelling-convention note) — a rounding artifact of the polygon-to-bbox extrema derivation, not a labeling mistake. A box off by more than 1px is still rejected.
- Labelling-session trim to 304/404 frames (see Deviations below) is an explicit operator decision, not a data-quality failure — 304 remains inside the REQ-S2-02/D-06 `[250, 600]` band, and both hover positions stay well represented after the trim because `sample_training_frames` (plan 02.1-07) interleaves clips across hover positions rather than grouping them, so truncating the frame list does not collapse either camera regime.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `export_cvat_task` nested its output under a `task_{id}` subdirectory**
- **Found during:** Task 1, while reading plan 02.1-08's implementation against this plan's Task 2/3 acceptance criteria
- **Issue:** `export_cvat_task(config, task_id, out_dir)` extracted the CVAT export into `out_dir / f"task_{task_id}"`, so the normalized `instances.json` ended up at `out_dir/task_{id}/instances.json` — but this plan's acceptance criteria (and its own Task 3 `<action>`) expect `out_dir/instances.json` directly, matching `cv/prelabel.py`'s convention.
- **Fix:** Extract directly into `out_dir`; `_find_coco_annotations(out_dir, task_id)` now normalizes to `out_dir/instances.json`.
- **Files modified:** `src/flag_football_ep/cv/dataset.py`
- **Verification:** `tests/test_cv_cvat.py`'s existing round-trip tests still pass unchanged (they assert `result.name == "instances.json"` and `result.is_file()`, not a specific parent path); the real `cvat-pull --out data/labels/.../corrected` run produced `data/labels/.../corrected/instances.json` directly.
- **Committed in:** `b759f89` (Task 1)

**2. [Rule 1 - Bug] `validate_coco`'s bbox-in-bounds check had zero tolerance for sub-pixel float rounding**
- **Found during:** Task 3, running `ffep cv dataset` against the real 304-frame corrected export — raised `DatasetError` on a bbox at `y=-0.16` (and 67 similar cases up to `y=-0.26`)
- **Issue:** CVAT derives an exported bbox from a corrected polygon annotation by taking its coordinate extrema; for a player/referee boxed right at the frame edge, this can land the box a fraction of a pixel outside `[0, width] x [0, height]`. A strict zero-tolerance comparison treated every one of these as a fatal, whole-dataset-blocking validation failure.
- **Fix:** Added `_BBOX_BOUNDS_EPSILON_PX = 1.0` and relaxed the comparison to `x < -eps or ... `. Confirmed via a diagnostic script (not committed) that all 68 out-of-bounds annotations in the real dataset were within 0.26px, all negative-y, all consistent with polygon-derived boxes — not a systematic or large error.
- **Files modified:** `src/flag_football_ep/cv/dataset.py`, `tests/test_cv_dataset.py` (new `test_validate_coco_tolerates_subpixel_bbox_overflow`, and the existing out-of-bounds test still uses a 40px overflow well above the epsilon)
- **Verification:** `uv run pytest tests/test_cv_dataset.py -q` (14/14 pass); `ffep cv dataset` against the real corrected export then succeeded, exit 0
- **Committed in:** `47244e8` (Task 3)

### Scope Adjustment — Operator Decision, Not Auto-Fixed

**3. Labelling session completed 304/404 frames, not all 404**
- **Found during:** Task 2's resume signal
- **What happened:** The operator worked through frames in CVAT-frame order and stopped after frame 304, saving and marking the job completed in CVAT. Frames 305-404 were left as their original Grounding DINO zero-shot pre-labels — never reviewed or corrected.
- **Rationale (operator's own):** Quality over quantity — after 304 carefully corrected frames, continuing risked introducing correction errors rather than adding real training value. This is explicitly authorized by D-04 (soft time-box: the gate is decided when the pipeline has run end-to-end, not on a fixed clock) and does not touch D-06 (no *more* labels were added; fewer were kept, deliberately).
- **Handling:** The pulled 404-frame export and its 404-frame manifest were both trimmed to the first 304 entries (CVAT frame order, which is identical to the original push/manifest order — verified by file-name alignment at indices 0, 303, and 403) before validation. Annotations for the dropped 100 images were removed and the remaining annotation ids renumbered 1..N for coherence. The full, untrimmed 404-frame pull is preserved alongside the trimmed file as `data/labels/2026-05-16_FRIENDLY-GER-vs-PANAMA-ROJO-DRONE/corrected/instances.full-404.json` (gitignored), in case frames 305-404 are corrected in a later session.
- **Verification:** 304 is inside the `[250, 600]` REQ-S2-02/D-06 band; hover-position distribution checked post-trim (hp-01: 164 frames/24 clips, hp-02: 140 frames/22 clips — neither collapsed); `ffep cv dataset` exits 0 on the trimmed set.
- **Files modified:** `data/labels/2026-05-16_FRIENDLY-GER-vs-PANAMA-ROJO-DRONE/*` (gitignored, not committed); `docs/cv-setup.md` (`### Datensatz`, honestly records the 304/404 range)
- **Committed in:** `47244e8` (Task 3, docs only — the label data itself is gitignored)
